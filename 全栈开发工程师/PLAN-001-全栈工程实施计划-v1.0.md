| :--- | :--- |
| 计划编号 | `PLAN-001-FULLSTACK` |
| 版本 | `v1.0` |
| 状态 | 待执行 |
| 主责 Agent | 全栈开发工程师 |
| 产品代码目录 | `CRM智能聊天系统/` |
| 依据文档 | `ARCH-001-SYS...v1.1.md`、`ARCH-003-DATA...v1.0.md`、PRD、管理端接口文档 |

## 1. 角色目标

负责项目工程骨架、数据库、后端业务 API、前端管理端、平台接入、异步任务和部署配置，为 AI Agent 提供稳定的业务数据和工具执行层。

正式代码只能写入 `CRM智能聊天系统/`；本计划文档和交接记录保存在本目录或共享记忆文档中。

## 2. 不负责的内容

- 不设计 Agent 状态机、Prompt、RAG 策略、模型路由和 AI 置信度算法。
- 不绕过架构师修改技术选型、核心数据模型和跨模块接口。
- 不把业务规则藏在前端；所有权限、状态和业务校验必须在后端执行。
- 不使用模拟接口替代正式接口而不做标记。

## 3. 实施阶段

### Phase 0：实施准备

开始前必须阅读：

- 产品 PRD、管理端接口文档和任务拆解。
- `架构师/ARCH-001-SYS-系统总体架构设计-v1.1.md`。
- `架构师/ARCH-003-DATA-数据库与向量库初版设计-v1.0.md`。
- 测试工程师已有测试结论和共享记忆文档中的变更记录。

输出：

- 工程实施拆解和依赖清单。
- 需要架构师确认的冲突或缺失项。
- 前端路由、后端模块和数据库迁移的执行顺序。

### Phase 1：工程地基和认证

在 `CRM智能聊天系统/` 创建：

- FastAPI 后端骨架、配置管理、日志、统一异常和 `/health`。
- Next.js + TypeScript + Tailwind 前端骨架、路由和基础布局。
- Docker Compose：应用、PostgreSQL、pgvector、Redis、MinIO。
- SQLAlchemy 模型、Alembic 迁移和数据库连接管理。
- `users`、`roles`、`permissions`、`user_roles`、`role_permissions`。
- JWT 登录、刷新、当前用户和 RBAC 中间件。
- API 版本前缀 `/v1`、统一响应结构和错误码。

验收：

- Docker Compose 一键启动依赖。
- `/health` 返回 200。
- 登录、刷新、`/auth/me` 可用。
- admin/supervisor/agent 权限差异可测试。
- 完整迁移可升级、可回滚。

### Phase 2：平台接入、会话和客服工作台

后端：

- 实现 `stores`、`channel_accounts`、`customers`、`conversations`、`messages`、`webhook_events`。
- 实现 TikTok、Shopee、Amazon 的适配器接口和统一消息模型。
- Webhook 验签、事件幂等、原始载荷保存、消息落库和发送状态。
- 实现会话列表、消息详情、人工发送、未读数、分配和转人工。
- 实现订单、订单商品、物流信息和客服快捷查询接口。

前端：

- 登录页、侧边栏、顶部栏、主题切换和多语言基础能力。
- 客服工作台三栏布局：会话列表、聊天窗口、客户侧边栏。
- 消息历史、发送消息、未读状态、平台筛选和人工接管。
- AI 建议回复的展示、使用和刷新入口，但不在前端实现 AI 逻辑。

接口交付：

```text
GET/POST /workspace/sessions
GET/POST /workspace/sessions/{id}/messages
POST /workspace/sessions/{id}/transfer
GET /workspace/actions/order/{id}
POST /webhooks/{platform}
```

验收：

- 模拟三平台消息可进入统一会话。
- 相同外部消息重复投递不会重复入库。
- 客服可以查看消息、发送人工回复和转人工。
- 不同店铺数据不能互相读取。

### Phase 3：知识库、业务工具和主动营销

后端：

- 实现 `knowledge_categories`、`knowledge_documents`、`knowledge_chunks` 的 CRUD 支撑 API。
- 实现 FAQ 新增、编辑、删除、分类和批量导入。
- 为 AI Agent 提供工具执行层：查订单、查物流、更新地址、发券、转人工、发送平台消息。
- 每个工具实现输入校验、权限、超时、重试、幂等键、审计和结果结构。
- 实现 `marketing_campaigns`、`marketing_events` 和主动营销任务调度。
- 实现弃单扫描、中差评扫描、频控、暂停和失败重试。

前端：

- 知识库列表、分类管理、FAQ 编辑、批量导入反馈。
- 快捷操作：查订单、更新地址、发优惠券、转人工。
- 营销流程列表、创建/编辑、启停和效果数据。
- Agent 配置页面只负责配置展示和启停，不修改 Agent 内部执行逻辑。

工具契约必须先与 AI Agent 开发工程师确认，统一使用：

```text
tool_name
input_schema
output_schema
permission
timeout_ms
idempotency_key
error_codes
audit_action
```

验收：

- 工具成功、失败、超时和重复调用均可验证。
- 工具失败时不会伪造成功结果。
- FAQ 发布、导入和删除状态可查询。
- 营销事件不会重复发送。

### Phase 4：SSE、看板、部署和稳定性

- 实现 `/chat/query` 或工作台 AI 回复的 SSE 传输层。
- 实现 `metric_daily` 聚合和看板接口：指标、趋势、渠道、预警、热门意图。
- 实现 `/agents` 配置 CRUD、启停和运行日志查询接口。
- 完善 Dockerfile、环境变量模板、启动文档和数据库备份说明。
- 增加限流、超时、重试、trace_id、结构化日志和健康检查。
- 配合测试工程师完成 50 并发压力测试、端到端测试和回归。

验收：

- AI 回复可逐步渲染，断开后前端可正确结束状态。
- 看板数据与消息、会话、营销事件可追溯。
- P99 延迟和可用性达到项目验收目标。
- Docker 环境可从空数据库完成部署。

## 4. 与 AI Agent 开发工程师的接口

全栈工程师提供：

- 会话上下文读取接口。
- 知识库发布数据和检索调用接口。
- 订单、物流、客户、优惠券和转人工工具执行接口。
- Agent 运行、工具调用、消息发送和审计记录持久化能力。
- SSE 传输和前端消费协议。

AI Agent 工程师提供：

- Agent 状态输入输出类型。
- 工具调用契约和错误码使用方式。
- Prompt/模型配置字段要求。
- 置信度动作和转人工结果结构。
- Agent 评测数据所需的日志字段。

任何接口变更必须先更新共享记忆文档，再同步代码和测试。

## 5. 测试与交付物

必须提供：

- 单元测试：服务、Repository、权限、状态流转和工具执行。
- 集成测试：数据库迁移、Webhook、消息入库、SSE 和外部适配器。
- API 文档和请求/响应 DTO。
- Docker 启动说明和环境变量模板。
- 每个阶段的变更文件、验证命令、验证结果和已知风险。

测试未通过时，不得把任务标记为完成；缺陷由测试工程师按规范生成报告。

## 6. 最终完成标准

- 产品代码全部位于 `CRM智能聊天系统/`。
- 现有接口文档中的管理端接口均有路由、服务和数据映射。
- 数据库迁移、索引、店铺隔离和幂等约束可验证。
- 前端主要页面可用，主题、多语言和响应式正常。
- AI Agent 可以通过稳定工具接口访问业务能力。
- 提供实际测试结果、部署方法和交接说明。
