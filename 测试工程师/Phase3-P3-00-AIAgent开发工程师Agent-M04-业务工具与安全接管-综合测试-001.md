## 3. 被测快照与独立性说明

当前项目不是 Git 仓库，无法使用不可变提交 SHA 冻结被测版本。本轮对 16 个 Phase 3 核心源文件和测试文件计算组合 SHA-256：

```text
0f3e8928c704777a5b641b6b2bf797e2b297442eafdd11068a52164940bd2b2b
```

测试开始和结束时摘要一致，说明本轮执行期间被测文件未变化。但该摘要不能替代 Git 提交、签名制品或只读工作树。

此外，本次测试会话与实现会话处于同一会话链和同类模型环境，因此本报告提供重新执行的客观命令证据和代码审查结论，但不宣称达到组织意义上的人员/模型完全独立复核。生产发布前建议由另一测试执行者在不可变提交上复跑。

## 5. 代码审查结果

| 审查项 | 证据与结论 | 状态 |
| --- | --- | --- |
| 七工具白名单 | `query_order`、`query_logistics`、`query_customer_profile`、`update_shipping_address`、`send_coupon`、`transfer_to_human`、`send_platform_message` 均有固定定义和强类型契约 | 通过 |
| 输入/输出边界 | Pydantic 输入与输出均 `extra=forbid`；未知工具、缺失/额外字段和非法输出在副作用或 Agent 消费前失败 | 通过 |
| 可信资源 ID | 查询参数仅从 `AgentToolRuntimeContext` 读取；客户文本只参与确定性需求路由，不作为权威订单/客户 ID | 通过 |
| 写操作批准 | 地址、发券和平台发送要求同名 `ApprovedToolAction`，使用精确参数和幂等键；重复批准被拒绝 | 通过 |
| 平台发送边界 | 客户文本不能选择 `send_platform_message`；工作流返回固定 `send_performed=false` | 通过 |
| 权限与店铺隔离 | 执行器先校验固定权限，所有订单、客户、会话和渠道查询附加可信 `store_id` | 通过 |
| 超时语义 | 一般工具超时为 `timeout/TOOL_TIMEOUT`；平台发送不确定结果为 `unknown/TOOL_RESULT_UNKNOWN`，不自动重试 | 通过 |
| 幂等 | 同键同请求重放原调用；同键不同参数返回 `TOOL_IDEMPOTENCY_CONFLICT`，不重复业务动作 | 通过 |
| 审计 | 写操作、发券、平台发送和转人工追加审计；转人工重放不重复审计 | 通过 |
| 工作流安全 | 仅全部必需工具成功后生成解释；引用必须属于本次成功 `tool_call_id`；独立复核失败、模型拒绝或非法完成声明均隐藏草稿并转人工 | 通过 |
| Mock 降级 | Mock 成功结果最高进入 `HUMAN_REVIEW`，不能进入自动回复就绪 | 通过 |
| 接管闭环 | 工具失败时可执行可信 `transfer_to_human`；结果区分 `transfer_performed=true/false` | 通过 |
| 追踪最小化 | 运行摘要保存节点、Prompt 版本、调用 ID、名称、状态和稳定错误码，不保存地址、物流号、消息正文、模型原始输出或密钥 | 通过 |
| 架构边界 | Agent 经 `AgentToolService → SqlAlchemyToolExecutor → Repository/PlatformAdapter` 调用，不动态导入工具或直接绕过执行层 | 通过 |

对冻结范围执行四类常见密钥特征扫描，匹配数均为 0。扫描只统计命中数量，未读取或输出 `.env` 的真实值。

## 11. 最终结论与验收建议

**结论：通过当前契约级 Mock 范围的 Phase 3 M04 业务工具与安全接管验收。**

本轮未发现 P0/P1/P2 功能缺陷。七工具白名单、可信上下文、写操作批准、权限、店铺隔离、幂等、审计、失败关闭、工具引用、安全复核、Mock 降级和人工接管均达到当前工程验收条件。

本结论不等于生产发布许可：真实平台写操作、真实模型工具解释/安全质量，以及不可变提交上的异主体复核仍是生产放行前的必要门禁。任何后续移除 `ApprovedToolAction`、`unknown`、Mock 降级、`transfer_performed` 或 `send_performed=false` 约束的变更，都必须重新执行专项安全回归。
