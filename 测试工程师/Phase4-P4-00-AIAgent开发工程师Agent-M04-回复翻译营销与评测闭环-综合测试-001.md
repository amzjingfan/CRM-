## 9. 失败项与缺陷

### DEF-P4-AI-001：高风险业务声明绕过确定性安全门禁

| 项目 | 内容 |
| --- | --- |
| 优先级 | **P1** |
| 状态 | Open |
| 影响 | 无工具事实或批准动作时，模型可生成“已退款、将退款、已改地址、肯定送达、物流已离仓”等话术并被代码层判为安全；若后续启用自动发送，可能向客户发送虚假完成声明或越权承诺 |
| 代码位置 | `backend/app/agent/reply_safety.py` 第 27～43、54～76 行 |
| 前置条件 | 使用 `ReplyEvidenceKind.FAQ`，无成功工具证据 |
| 复现步骤 | 依次调用 `ReplySafetyPolicy.evaluate()`，输入上述 6 条中文/英文合成高风险话术 |
| 预期结果 | `is_safe=false`，返回稳定的越权承诺、虚构订单/物流或未授权完成原因码 |
| 实际结果 | 6 条均返回 `is_safe=true`、`reason_codes=[]` |
| 修复建议 | 将安全判断从有限关键词扩展为“动作 + 时态/承诺 + 证据类型”的规则矩阵；退款、地址、物流、发券、平台发送分别要求对应成功工具证据；新增中英文同义改写、否定句和条件句测试，避免误杀政策说明 |
| 回归要求 | 本报告 6 条样本全部阻断；加入版本化 JSONL 后评测集危险漏放为 0；FAQ、真实查询工具结果和 Mock 降级原测试继续通过 |

### DEF-P4-AI-002：翻译结果未进入公开建议与 SSE 契约

| 项目 | 内容 |
| --- | --- |
| 优先级 | **P1** |
| 状态 | Open |
| 影响 | 即使启用翻译并在工作流中生成 `customer_translation`，客服工作台和公开调用方也无法取得客户译文或回复译文，P2-10 实时翻译能力不可用 |
| 代码位置 | `backend/app/agent/schemas.py` 第 286 行；`backend/app/chat/schemas.py` 第 24～36 行；`backend/app/chat/service.py` 第 142～163 行 |
| 复现步骤 | 对照内部 `AgentWorkflowResult` 与公开 `SuggestionView`，检查 `suggestion_view()` 映射字段 |
| 预期结果 | 公开契约以低敏结构返回与 `trigger_message_id` 关联的翻译，或提供明确独立授权接口 |
| 实际结果 | 公开响应只包含建议、意图、置信度、动作和引用，翻译字段被丢弃 |
| 修复建议 | 由全栈与 AI Agent 工程师共同确定公开 Schema、权限、语言展示和 SSE 事件；不得返回原文摘要之外的敏感数据 |
| 回归要求 | 中文/英文/混合/未知、同语种零调用、翻译失败降级、权限、SSE 和前端展示测试全部通过 |

## 12. 最终结论与验收建议

**结论：不通过 Phase 4 M04 回复、翻译、营销与评测闭环的完整验收。**

本轮确认工程基线稳定：静态检查、覆盖率、数据库、前端、迁移、Compose、运行态和依赖安全均通过；语言识别、翻译脱敏关联、营销副作用顺序和开发侧确定性用例也可重复通过。

但 `DEF-P4-AI-001` 证明当前安全评测集存在明显盲区，6 条无业务证据的退款、地址、物流和送达声明全部被判为安全。该缺陷直接影响自动回复可信性，是生产启用阻断项。同时，公开翻译、店铺回复画像、线上 AI 指标和营销统一追踪尚未形成可交付闭环。

验收建议：

1. 立即保持 `AUTO_REPLY_ENABLED=false`、`AI_TRANSLATION_ENABLED=false`、`AI_MARKETING_ENABLED=false`，不得以本报告中的 Fake/Mock 结果替代生产验收。

3. 完成 `DEF-P4-AI-003～005` 的跨 Agent 交付，由架构师确认公开契约、追踪和指标口径。
4. 密钥轮换完成后执行真实模型翻译/营销/安全评测、真实 SSE 50 并发和五天稳定性门禁。
