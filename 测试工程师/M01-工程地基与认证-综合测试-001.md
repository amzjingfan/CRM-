## 2. 测试范围

本次围绕 Phase 1 交接内容验证以下能力：

1. FastAPI 应用健康检查和就绪检查。
2. JWT 登录、当前用户、刷新 Token、退出登录。
3. 错误密码、非法 Token、未认证访问和退出后的 Refresh Token 拒绝。
4. 密码哈希、Token 类型隔离、Cookie HttpOnly 和 CSRF Cookie 属性。
5. Alembic 迁移升级、回滚和再次升级。
6. PostgreSQL + pgvector、Redis、MinIO 容器健康状态。
7. Next.js 登录页构建、TypeScript、Lint、前端测试和开发服务器可达性。

本次不验收 AI Agent、Prompt、RAG、模型调用、真实平台联调、SSE、营销和知识库业务；这些不属于 Phase 1 验收范围，且当前 README 也明确标记为后续能力。

### 4.3 Alembic 迁移

为避免破坏持久化开发库，创建隔离数据库 `crm_phase1_test`，在后端容器内部执行：

```powershell
alembic upgrade head
alembic downgrade base
alembic upgrade head
```

结果：三步全部返回 0。008 版本迁移链可以完整升级、回滚并再次升级。

说明：直接从 Windows 主机使用 asyncpg 连接 Docker PostgreSQL 时出现 `WinError 64` 连接中断，因此改为通过后端容器访问隔离数据库完成验证；这不是迁移脚本失败。

## 5. 失败项与缺陷

### F-001：真实浏览器 DevTools 验证未执行

- 状态：环境阻塞，非产品缺陷。
- 优先级：P2。
- 影响：本次无法提供真实浏览器截图、控制台、网络面板和可访问性树证据。
- 原因：项目 `.mcp.json` 已配置 Chrome DevTools MCP，但当前会话的工具注册表尚未加载该服务；这是会话环境问题，不是项目配置缺失。
- 已完成替代验证：Next 开发服务器启动成功，`/login` HTTP 返回 200；前端 lint、类型检查、单元测试和生产构建通过。
- 后续：重新打开项目或新建会话使 `.mcp.json` 生效后，补做登录页、未认证跳转、错误提示、响应式布局、控制台、网络请求、截图和可访问性树回归。

### F-002：Windows 主机 asyncpg 连接 Docker PostgreSQL 不稳定

- 状态：已绕过并完成迁移验证。
- 优先级：P2，环境问题。
- 复现：在 Windows 主机执行本地 Alembic 并连接 `localhost:5432`，出现 `asyncpg.exceptions.ConnectionDoesNotExistError` 和 `WinError 64`。
- 处理：通过 `crm-backend-1` 容器连接隔离数据库 `crm_phase1_test`，升级、回滚、再次升级全部通过。
- 建议：团队统一使用容器内 Alembic 命令，或单独排查 Docker Desktop Windows 网络转发。

### W-001：第三方依赖存在弃用警告

- 状态：待后续依赖升级处理。
- 优先级：P3。
- 内容：Starlette/httpx TestClient 和 passlib/argon2 产生弃用警告。
- 当前影响：不影响本次测试通过，不构成 Phase 1 阻断缺陷。
