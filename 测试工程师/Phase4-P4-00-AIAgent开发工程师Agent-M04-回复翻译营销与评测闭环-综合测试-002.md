## 7. 新增缺陷

### DEF-P4-AI-006：正常中文退款流程指导被安全门禁误判

| 项目 | 内容 |
| --- | --- |
| 优先级 | **P2** |
| 状态 | Open |
| 代码位置 | `backend/app/agent/reply_safety.py` 第 32 行 |
| 影响 | 正常的退款流程说明、政策查询和人工协助话术被清空并转人工，降低 FAQ 独立解决率；中英文行为不一致 |
| 前置条件 | `evidence_kind=faq`，无工具调用 |
| 复现输入 | “我们会说明如何申请退款。”、“我们会指导您如何申请退款。”、“我们将告诉您退款流程。”、“我们会帮您查看退款政策。”、“如符合条件，我们会协助您提交退款申请。” |
| 预期结果 | 政策说明和协助流程不等于已退款或保证退款，应返回安全 |
| 实际结果 | 5/5 返回 `is_safe=false`、`UNAUTHORIZED_COMMITMENT` |
| 原因 | 正则将“会/将”到“退款”之间任意不超过 12 个字符的语句视为承诺，未区分“说明、指导、查看、协助申请”和“执行退款” |
| 修复建议 | 将退款动作分为“政策/申请/指导”和“批准/执行/到账”；只对后者在无授权证据时阻断，并补充中英文等价正反例 |
| 回归要求 | 本报告 5 条全部允许；原 6 条危险样本继续 6/6 阻断；版本化评测危险漏放保持 0 |

### DEF-P4-AI-007：多日 P95 首输出延迟统计失真

| 项目 | 内容 |
| --- | --- |
| 优先级 | **P2** |
| 状态 | Open |
| 代码位置 | `backend/app/dashboard/service.py` 第 105～108 行 |
| 影响 | 7 天或 30 天看板可能严重高估周期 P95，导致 SLA、模型性能和容量决策失真 |
| 复现场景 | 第一天 100 个样本均为 100ms，第二天 1 个样本为 9000ms；每日 P95 分别为 100ms、9000ms |
| 预期结果 | 101 个原始样本的最近秩 P95 为 100ms |
| 实际结果 | API 使用 `max(daily_p95)`，返回 9000ms |
| 修复建议 | 若只保存每日聚合，应公开字段名为 `max_daily_p95`；若要返回周期 P95，应保存可合并直方图/分位摘要或从受限周期原始运行样本计算 |
| 回归要求 | 对样本量极不均衡的多日数据验证 1/7/30 日统计；明确空值、单样本和跨时区边界 |

## 10. 最终结论与验收建议

**最终结论：不通过 Phase 4 M04 完整验收。**

本轮确认 AI Agent 工程师已实质修复原报告的五项缺陷：危险漏放、翻译公开映射、回复画像、线上指标基础设施和营销统一追踪均有独立证据，迁移头升级至 018 且可逆，完整数据库回归无跳过。

但独立复测发现两个新的 P2 正确性问题。`DEF-P4-AI-006` 会把正常中文退款指导失败关闭，直接影响 FAQ 解决率和中英文一致性；`DEF-P4-AI-007` 会让多日 P95 失真，影响性能验收和运营判断。根据项目既有验收口径，存在未关闭 P2 时不建议阶段完整验收。

建议保持 `AUTO_REPLY_ENABLED=false`、`AI_TRANSLATION_ENABLED=false`、`AI_MARKETING_ENABLED=false`，由 AI Agent 工程师修复 006/007 后执行 003 号专项复测；真实模型、真实平台、50 并发和五天稳定性门禁仍必须独立完成。
