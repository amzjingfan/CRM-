## 7. 失败项与缺陷

### DEF-P3-011：分类创建成功后前端读取失效表单引用，页面报错且不刷新

| 项目 | 内容 |
| --- | --- |
| 优先级 | **P1** |
| 状态 | 未关闭 |
| 影响范围 | 知识库分类创建成功反馈、分类树刷新、重复提交安全；相同代码模式还存在于 FAQ 草稿创建 |
| 责任 Agent | 全栈开发工程师Agent |

复现步骤：

1. 登录管理端并进入 `/knowledge`。
2. 输入分类名称和编码，在“Parent category”选择现有根分类。
3. 点击“Add category”。
4. 后端返回成功并已持久化；页面底部状态出现 `Cannot read properties of null (reading 'reset')`。
5. 表单未重置、分类树未刷新；手工刷新后新分类才出现，且父级关系正确。

代码定位：`frontend/app/knowledge/page.tsx:157` 在 `await createKnowledgeCategory(...)` 后调用 `event.currentTarget.reset()`。异步边界后 React 事件的 `currentTarget` 已不可用。`frontend/app/knowledge/page.tsx:205` 的 FAQ 创建存在同样模式，应一并修复和回归。

期望结果：提交前保存表单元素引用，或使用受控表单；接口成功后可靠重置、显示中文/英文成功提示并立即刷新树。接口已经成功时不得进入失败提示，也不得诱导用户重复提交。

### DEF-P3-012：未认证访问受保护页面时浏览器控制台记录业务错误

| 项目 | 内容 |
| --- | --- |
| 优先级 | **P2** |
| 状态 | 未关闭 |
| 影响范围 | 受保护布局、浏览器“零控制台错误”验收 |
| 责任 Agent | 全栈开发工程师Agent |

复现步骤：

1. 在无认证 Cookie 的新浏览器会话打开 `/knowledge`。
2. 页面正确跳转 `/login`。
3. 读取浏览器控制台，出现来自 `lib/api.ts` 的 `Error: 请求未认证`。

期望结果：预期的 401 应由受保护布局安静处理并跳转登录页，不应作为控制台错误输出；真实异常仍需保留可观测性。

## 9. 最终结论与验收建议

本轮 **不建议通过 Phase 3 M03 正式验收**。

虽然 002 号报告中的运行脚本、OpenAPI 和 375px 阻断项均已关闭，分类树和后端循环校验也已具备，但分类创建出现“服务端成功、前端报错且不刷新”的关键一致性问题，可能引发重复提交和错误运营判断。全栈开发工程师应先修复 `DEF-P3-011`，同时处理 `DEF-P3-012`，再申请针对分类/FAQ 异步表单、成功反馈、即时刷新、幂等重放和未认证跳转控制台的定向复测。

真实平台联调、真实 Embedding/RAG、AI 营销文案和 Agent 工具选择仍不属于本报告通过范围。
