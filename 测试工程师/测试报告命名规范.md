# CRM 智能聊天系统测试报告命名规范

## 1. 适用范围

本规范适用于测试工程师 Agent 生成的测试报告、回归报告、性能报告、AI 评测报告和正式测试结论文件。

所有测试产物统一存放在 `测试工程师/`。共享记忆文档只维护 `测试报告索引.md`，不得保存第二份正式测试结论。

## 2. 命名类型判定

生成报告前必须先判断属于“大范围测试”还是“阶段性测试”。

### 2.1 大范围测试

满足以下任一条件时，可使用大范围测试命名：

- 覆盖多个 Phase。
- 覆盖多个主责 Agent。
- 属于全系统、整模块、版本发布或最终验收。
- 属于跨模块回归、全链路测试、综合性能测试或安全审计。
- 无法合理归属到一个明确的 Phase 和主责 Agent。

### 2.2 阶段性测试

同时满足以下条件时，必须使用阶段性测试命名：

- 能明确归属到一个 Phase。
- 能明确关联一个任务编号或阶段汇总编号。
- 能明确识别被测实现的主责 Agent。
- 测试范围是一个任务、功能增量、阶段交付或其回归。

## 3. 大范围测试命名规范

保持原有格式不变：

```text
{模块编号}-{模块名称}-{测试类型}-{三位序号}.md
```

示例：

```text
M01-工程地基与认证-综合测试-001.md
M00-全系统-端到端测试-001.md
M00-全系统-发布回归-002.md
M00-全系统-性能测试-001.md
```

大范围报告虽然文件名不写 Agent 和 Phase，但正文的“测试基本信息”中必须填写：

- 覆盖的 Phase。
- 覆盖的任务编号。
- 被测主责 Agent。
- 被测协作 Agent。
- 测试执行 Agent。
- 关联实施记录路径。

## 4. 阶段性测试命名规范

阶段性测试必须使用：

```text
Phase{阶段号}-{任务编号}-{被测主责Agent}-{模块编号}-{模块名称}-{测试类型}-{三位序号}.md
```

示例：

```text
Phase1-P1-03-全栈开发工程师Agent-M01-FastAPI工程骨架-功能测试-001.md
Phase2-P2-07-AIAgent开发工程师Agent-M02-Agent对话编排-AI评测-001.md
Phase2-P2-09-全栈开发工程师Agent-M03-SSE流式输出-接口测试-001.md
PhaseX-PX-00-开发工具Agent-MT01-Skill升级-回归测试-001.md
```

## 5. 字段定义

| 字段 | 规则 | 示例 |
| --- | --- | --- |
| Phase阶段号 | 使用 `Phase1`～`Phase4`；跨阶段治理使用 `PhaseX` | `Phase2` |
| 任务编号 | 单任务使用 P1-01 等编号；阶段汇总使用 P1-00；无正式任务使用 PX-00 | `P2-07` |
| 被测主责Agent | 指实现被测功能的主责 Agent，不是测试报告作者 | `AIAgent开发工程师Agent` |
| 模块编号 | 使用项目模块编号；未建立时由架构师确认后再生成报告 | `M02` |
| 模块名称 | 使用 PRD、接口或实施记录中的正式名称 | `Agent对话编排` |
| 测试类型 | 功能测试、接口测试、AI评测、回归测试、性能测试等 | `AI评测` |
| 三位序号 | 同一组合从 001 递增，修订版不得覆盖原文件 | `001` |

## 6. 固定 Agent 名称

文件名中的被测主责 Agent 必须使用：

- `架构师Agent`
- `AIAgent开发工程师Agent`
- `全栈开发工程师Agent`
- `测试工程师Agent`
- `开发工具Agent`
- `共享记忆文档Agent`

如果功能由多个 Agent 协作完成，文件名只写实施记录中确认的主责 Agent；其他 Agent 在报告正文中列入“被测协作 Agent”。无法确定主责 Agent 时，暂停生成报告并交由架构师确认，不使用含糊的“多Agent”。

## 7. 测试类型固定用词

优先从以下类型中选择：

- `单元测试`
- `功能测试`
- `接口测试`
- `集成测试`
- `端到端测试`
- `页面交互测试`
- `兼容性测试`
- `安全测试`
- `性能测试`
- `压力测试`
- `AI评测`
- `回归测试`
- `综合测试`
- `发布验收`

不得为同一种测试随意创造多个近义名称。

## 8. 阶段性报告正文必填项

阶段性测试报告的基本信息必须包含：

```markdown
## 1. 测试基本信息

| 项目 | 内容 |
| --- | --- |
| Phase | Phase{阶段号} |
| 任务编号 | {任务编号} |
| 模块编号 | {模块编号} |
| 模块名称 | {模块名称} |
| 被测主责 Agent | {Agent} |
| 被测协作 Agent | {Agent/无} |
| 测试执行 Agent | 测试工程师 Agent |
| 关联实施记录 | `共享记忆文档/实施记录/{实施记录文件名}` |
| 测试类型 | {测试类型} |
| 执行日期 | {YYYY-MM-DD} |
| 测试结论 | 通过/有条件通过/不通过/阻塞 |
```

## 9. 索引同步

报告完成后，测试工程师 Agent 必须更新 `共享记忆文档/测试报告索引.md`，至少登记：

- 报告范围。
- Phase。
- 任务编号。
- 模块编号和名称。
- 被测主责 Agent。
- 测试执行 Agent。
- 报告路径。
- 最终结论和日期。
