## 3. 目标、范围与非目标

### 3.1 实施目标

- 对用户指定的 `tkw api` 获取可陈述的低敏店铺侧、应用侧授权事实，并明确仍缺的真实令牌与 CRM 证据。

### 3.2 实施范围

- 已登录 TikTok Shop Seller Center、Partner Center 的页面只读核验；同步低敏治理文件。

### 3.3 非目标

- 不修改应用状态、Scope、授权或店铺设置；不读取或输出密钥、Token、真实店铺 ID、买家和订单数据；不执行真实 API 调用；不进行来源使用权签署、向量化或生产放行。

## 5. 实施方案

### 5.1 方案说明

先在卖家侧核对目标应用是否对 US 店铺生效，再在开发者侧核对同名应用是否开启、是否指向本项目 staging 回调及相关应用级 Scope。将页面观察写成低敏事实，令牌实际授权与真实只读继续留待受控运行环境验证。

### 5.2 依赖关系

- 前置依赖：用户完成 Seller Center 与 Partner Center 登录并明确目标应用为 `tkw api`。
- 后续依赖：产品确认稳定 `shop_ref`；全栈在受控 CRM 运行环境核对令牌 `granted_scopes`、Get Authorized Shops 和渠道绑定；测试工程师执行独立真实环境验收；平台协议/法务核准 API Data 使用权。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 同一后台有多个自定义应用 | 错把无关应用授权当项目证据 | 以用户明确指定的 `tkw api` 为目标，并只将其 staging 回调与本项目接口契约作低敏交叉核对 |
| 应用侧 Scope 与店铺令牌实际授予范围不同 | 假阳性声明接口可用 | 仅登记“应用侧生效”，真实 `granted_scopes` 和只读调用独立待测 |
| 临时会话截图不是受控归档 | 证据不可长期追溯 | 只保留附件 SHA-256 和页面类型；正式原件由有权人员在受控位置归档后补引用 |
| 平台授权不等于知识使用权 | API 数据被越权共享或向量化 | `shop_private` 和来源许可门禁继续关闭 |
