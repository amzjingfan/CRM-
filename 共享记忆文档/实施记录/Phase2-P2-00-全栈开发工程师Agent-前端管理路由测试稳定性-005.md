## 5. 实施方案

### 5.1 方案说明

005 报告执行时，`phase3.test.mjs` 在模块加载阶段直接读取 `app/knowledge/page.tsx`，而该页面尚未出现在当时的测试快照中，因此 Node 在注册测试用例前抛出 `ENOENT`。之后 Phase 3 缺陷修复已交付完整知识库页面及配套 API，当前源码文件存在，原始 `npm run test` 已从失败恢复为通过。

本次不重复覆盖已经存在的知识库页面，而是把所有必需管理端路由集中声明为 URL，增加独立的路由存在性测试，并通过 `readRequiredSource` 在每个测试内部读取源码。这样既保留了页面缺失时必须失败的门禁，也让错误信息明确指出缺失路由，同时避免整个测试文件在模块初始化阶段中止。

### 5.2 依赖关系

- 前置依赖：`共享记忆文档/实施记录/Phase3-P3-00-全栈开发工程师Agent-测试缺陷修复-002.md` 已交付知识库和营销管理页面。
- 后续依赖：测试工程师针对 DEF-P2-003 生成 006 号正式复测报告。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 页面再次被删除或交付快照不完整 | 前端全量测试和生产构建失败 | 独立检查 workspace、knowledge、marketing、agents 四个管理路由源码 |
| 顶层同步读文件提前终止测试注册 | 测试结果只显示模块崩溃，其他断言无法执行 | 延迟到测试内部读取，并提供带路径的明确断言 |
| 仅验证文件存在、不验证可编译 | 页面可能存在但导入或类型错误 | 同时执行 lint、typecheck、全量测试和 Next.js build |
