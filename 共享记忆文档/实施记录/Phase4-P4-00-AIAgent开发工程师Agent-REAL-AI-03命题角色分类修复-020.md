### 3.1 实施目标

## 5. 实施方案

### 5.1 方案说明

确定性文本门禁继续作为 REAL-AI-02 结构化声明之外的纵深防御，但不再依赖单一“主体在前 + 动作在前”句式：

```text
客户金融目标 + 资金对象 + 结果状态 + 可选资金来源
→ 主动、被动、存在状态或来源后置均形成资金完成候选
→ 候选无可信结构化声明时失败关闭

退款主题 + 明确技术资产类型
或 后置证据否定 / 疑问 / 条件 / 测试夹具引用
→ 不视为当前客户完成事实
→ 仅保留人工复核草稿
```

普通前置否定与“可控制整个命题的后置评价/疑问/条件”使用不同模式集合，禁止前句安全语境跨越后续独立资金事实。

### 5.2 依赖关系

- 前置依赖：REAL-AI-02 结构化业务声明、AI-005 三态授权、019 号语法泛化修复、004 号独立开放集。
- 后续依赖：测试工程师第五批独立开放集；REAL-AI-04/05 真实回复、翻译、营销与真实模型评测。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 新结果状态或语序漏放 | 危险草稿进入人工建议区 | 按金融目标、资金对象和结果状态的角色组合识别，不依赖已知主体名称 |
| 技术资产类别扩展造成误放 | 技术文本掩盖真实客户事实 | 先全局发现资金候选，技术资产只豁免与资产范围重叠的候选 |
| 非断言作用域过宽 | 安全前句遮蔽后续危险事实 | 命题级后置评价与普通前置否定分离，并保留标点边界 |
| 开发回归被误认为正式关闭 | 生产能力提前放行 | 保持 P1/P2 Reopened，要求新的第五批独立开放集 |
