## 3. 目标、范围与非目标

### 3.1 实施目标

- 核对 `tkw api` 的受控配置、CRM OAuth 安全绑定设计与可获得的运行态证据。
- 以最小权利原则签署七个 TK-US 官方公开来源的内部使用边界。

### 3.2 实施范围

- 受保护 `.env` 和停止容器的低敏存在性/不可逆指纹核验；OAuth 实现、日志、服务和数据库可用性只读检查；公开页面的使用形式、应用/空间、复核周期与禁止用途审批；治理台账同步。

### 3.3 非目标

- 不读取、输出或提交真实 Token、密钥、数据库口令、店铺/订单/客户标识；不启动原始数据库卷；不发起新的 OAuth；不调用平台写接口；不采集或向量化官方正文；不完成内容版本与正式测试。

## 5. 实施方案

### 5.1 方案说明

将“平台页面授权”“本地应用配置”“令牌实际授权”“CRM 数据库绑定”“知识内容使用权”拆成独立证据层。配置只比较不可逆指纹并记录布尔结论；数据库无法安全只读时不启动原卷。公开页面采用受限使用审批：保存元数据、编写公司自编内容并在内部受控检索，禁止保存/向量化官方原文和店铺私有数据。

### 5.2 依赖关系

- 前置依赖：`AUTH-TK-US-001` 平台页面低敏证据、用户指定架构负责来源审批、现有 OAuth/ChannelAccount 实现与停止的 CRM 容器。
- 后续依赖：一次性数据库副本只读核验、真实 Get Authorized Shops、内容负责人逐版本审批和测试工程师独立评测。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 配置存在被误判为令牌已绑定 | 越权开启真实同步 | 将配置对应关系与运行态令牌/数据库行分开，后者保持未通过 |
| 启动原 PostgreSQL 卷改变证据 | WAL 或元数据被写入 | 不启动、不以可写方式挂载；后续仅在明确批准后使用一次性副本 |
| 可浏览页面被误认为可复制 | 侵犯平台权利或扩大分发 | 只批准元数据和公司自编内容，禁止正文、快照、原文向量化与片段展示 |
| 店铺/API Data 进入共享空间 | 隐私、合同和租户隔离风险 | 公开来源审批明确排除 API Data，`shop_private` 门禁保持关闭 |
