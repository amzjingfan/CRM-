## 5. 实施方案

### 5.1 方案说明

先执行后端与前端质量门禁，再使用独立临时数据库验证 Alembic 全量升级、回滚和再次升级；随后使用 Docker 中运行的后端、Worker、PostgreSQL、Redis 和 MinIO 验证健康检查、浏览器 Cookie/CSRF、Webhook 幂等和客服工作台 API。测试账号密码由命令运行时随机生成，不写入代码、日志或报告。

### 5.2 依赖关系

- 前置依赖：全栈 Agent Phase 2 实施记录、Docker 依赖服务、后端和前端依赖已安装。
- 后续依赖：前端容器可构建后补做浏览器页面和响应式回归；真实平台联调由后续平台测试任务负责。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| Docker Hub 网络不可用 | 前端容器无法启动 | 已完成本地 npm build；报告明确标记环境阻塞并要求补测 |
| 测试账号和密钥泄露 | 安全风险 | 随机生成密码，不记录 Token、密码和真实密钥 |
| 开发库被测试数据污染 | 影响后续开发 | 使用幂等演示数据；迁移验证使用临时数据库并完成清理 |
| 未完成真实平台联调 | 不能证明生产平台兼容 | 明确本阶段只验证契约级 Mock |
