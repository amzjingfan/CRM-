## 3. 目标、范围与非目标

### 3.1 实施目标

- 使用 root 仅完成服务器引导初始化，为后续日常部署建立位于独立大容量文件系统上的普通账户和隔离目录。
- 验证部署账户可使用指定 SSH 公钥登录，同时保持密码、sudo 和 Docker 守护进程权限失败关闭。
- 明确 Docker 数据目录仍占用根文件系统的阻断风险，避免把“代码位于大容量文件系统”误写为“容器数据已迁移”。

### 3.2 实施范围

- 只读核对操作系统、磁盘、inode、挂载、Docker/Compose、目标账户和 SSH 前置条件。
- 创建专用普通部署账户；账户名、服务器地址和密钥标识只保存在受控运维环境，不进入 Git。
- 建立 `{deployment-home}/src`、`{deployment-home}/config`、`{deployment-home}/assets/models`、`{deployment-home}/secrets/tls`、`{deployment-home}/evidence`、`{deployment-home}/backups` 和 `{deployment-home}/runner` 隔离目录。
- 使用用户指定私钥派生的单一公钥配置 SSH，不复制 root 的完整授权列表。

### 3.3 非目标

- 不迁移或清理 Docker 数据目录，不停止或重启现有容器。
- 不授予部署账户 sudo 或 Docker 守护进程访问权。
- 不克隆代码、不拉取 GHCR 镜像、不传输模型权重、不写入环境文件或 TLS 私钥。
- 不启动 Compose，不执行数据库迁移、真实店铺联调、回滚演练、健康探针或五日稳定性测试。
- 不把本次服务器初始化声明为 G0 通过、应用部署完成或 v0.1 生产放行。

## 5. 实施方案

### 5.1 方案说明

root 账户只用于检查挂载和创建最小权限普通账户。部署账户密码保持锁定，仅安装用户指定密钥对应的公钥；代码、配置、模型、TLS、证据和备份分别使用兄弟目录，避免环境文件、权重和证据进入完整 Git checkout。Docker 高权限和数据目录迁移必须在确认现有工作负载、停机窗口与回滚方案后单独批准。

### 5.2 依赖关系

- 前置依赖：目标服务器 root SSH 权限、独立且容量充足的数据文件系统、Docker Engine 和 Compose v2。
- 后续依赖：Docker 存储迁移决策、部署账户 Docker 权限方案、PowerShell 7、最新 main 不可变镜像、仓库外环境文件、模型六文件和 TLS 资产。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| Docker 数据目录仍位于根文件系统 | 拉取镜像和命名卷增长可能耗尽根盘 | 当前保持不变并标记为阻断项；迁移前先盘点现有工作负载、备份、停机和回滚 |
| 加入 `docker` 组等同获得近似 root 权限 | 部署账户可控制宿主机 | 本轮不授权；后续必须在明确知情批准后选择 docker 组或评估 rootless Docker |
| 复制 root 的全部授权密钥 | 无关人员获得部署账户访问权 | 只安装用户指定私钥派生的单一公钥，不读取或复制 root 授权列表正文 |
| 配置、模型或证据进入 Git checkout | 泄露凭据、丢失权重或污染基线 | 使用 checkout 外兄弟目录并在真实门禁中再次验证绝对路径、普通文件和只读挂载 |
| 服务器缺少 PowerShell 7 | 现有 staging/回滚脚本无法运行 | 真实 validate/deploy/rollback 前单独安装并验证 `pwsh` |

- 新建非 UID 0 的普通部署账户，home 位于独立大容量文件系统，登录 shell 为 Bash，密码状态为锁定。

- 创建代码、配置、模型、TLS、证据、备份和 runner 目录；敏感目录为 `0700`，代码父目录为 `0750`，公共模型资产目录为 `0755`。

### 6.3 关键实现说明

本次先验证 `{large-data-filesystem}` 独立于 `{constrained-root-filesystem}`，再创建部署账户。Docker Engine 当前数据目录仍位于受限根文件系统，且服务器存在活动工作负载，因此没有执行全局数据目录迁移、清理、重启或逐项目卷改造。模型目录只建立空结构；六个必需普通文件、固定 SHA-256 和只读挂载须在受控传输后由真实门禁验证。

## 8. 实施结果

- 完成项：独立大容量文件系统核对、普通部署账户、单一 SSH 公钥、隔离目录和普通用户登录验证。
- 未完成项：Docker 数据目录迁移或 rootless 方案、Docker 权限、PowerShell 7、代码 checkout、GHCR、环境/TLS/模型、Compose、回滚与健康证据。
- 与原方案差异：因 `docker` 组具有近似 root 权限，未在缺少单独知情授权时加入；因现有 Docker 数据和活动工作负载位于根文件系统，未静默迁移或清理。
- 当前状态：部分完成；账户与目录可用，但服务器尚不具备安全执行本项目 Docker 部署的完整前置条件。
