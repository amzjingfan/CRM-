## 3. 目标、范围与非目标

### 3.1 实施目标

- 以管理端 HTML 原型为直接视觉基线，重做知识库、智能营销及全局管理端信息架构。
- 在不破坏既有接口和业务逻辑的前提下，让数据看板、客服工作台、Agent 管理和系统配置保持同一套视觉语言。
- 完成真实浏览器、前端构建和后端接口回归后再交付本地预览。

### 3.2 实施范围

- 应用侧栏、页面标题、通用按钮/表单/状态/弹窗、响应式规则和统一图标族。
- 知识库分层树、FAQ 内容卡片、向量状态、筛选、导入、分类和知识 CRUD。
- 智能营销流程卡片、流程 CRUD/启停、真实触达报表和事件分页。
- 数据看板、客服工作台、Agent 管理、店铺/渠道/团队设置的视觉统一。
- 前端静态契约测试、生产构建、后端相关回归和同视口视觉验收。

### 3.3 非目标

- 不修改后端 API、数据库表、环境变量、AI Prompt、模型配置或生产平台门禁。
- 不为匹配参考图而写入虚假 FAQ、营销流程或统计数据。
- 不部署到外部环境；仅保持本地前后端预览可用。

## 5. 实施方案

### 5.1 方案说明

沿用现有 Next.js 路由和 `lib/api.ts`，只在视图层重组信息结构。全局壳层移除旧顶栏，采用原型中的 230px 左侧导航；页面使用浅灰底、白色细边框卡片、蓝色主操作和紧凑的数据密度。知识库用“分层树 + FAQ 内容”双栏结构，智能营销用“流程卡片 + 效果报表 + 执行记录”结构；所有筛选、分页、导入、CRUD、流程启停和指标继续调用真实接口。

标准界面图标统一使用 `@phosphor-icons/react`，避免文本符号和自制 SVG。移动端切换为底部导航，弹窗切换为底部面板，桌面、平板和横屏保持无横向溢出。视觉验收使用与参考图相同的视口和真实登录状态。

### 5.2 依赖关系

- 前置依赖：既有 Next.js 前端、FastAPI `/v1` API、PostgreSQL、Redis、MinIO、浏览器 Cookie/CSRF 和店铺/RBAC 数据。
- 后续依赖：正式发布流程使用本次已通过生产构建的源码；测试工程师可据此执行浏览器矩阵回归。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 大范围页面重排误改业务逻辑 | CRUD、筛选或权限边界退化 | 复用原 API 函数和提交逻辑，新增静态契约测试并执行 8 个核心路由实机回归 |
| 参考图使用示例数据，真实店铺为空 | 截图内容密度与参考图不同 | 坚持展示真实空状态，在视觉验收中单独记录数据状态差异 |
| 新图标依赖增加前端包体 | 构建或运行异常 | 仅增加单一成熟图标包，执行 lint、类型检查、测试和生产构建 |
| 小屏布局溢出或抽屉错位 | 移动端核心操作不可用 | 覆盖 375、667、768、1024、1440 五档视口并修正抽屉定位和 44px 触控目标 |

- 分类/知识/营销流程提交复用原异步 API 和幂等请求路径；删除继续要求确认，写操作权限由后端 RBAC 最终裁决。
- 智能营销报表使用真实 Dashboard 与事件数据计算，不写死参考图数字；当前店铺为空时提供可恢复的主操作。
- 保留 Cookie 认证、CSRF、`Idempotency-Key`、店铺隔离、SSE 中止和危险工具二次确认。
- 交互控件使用语义按钮、表单标签、`aria-label`、`aria-live` 和可见焦点；主要触控目标不小于 44px。
