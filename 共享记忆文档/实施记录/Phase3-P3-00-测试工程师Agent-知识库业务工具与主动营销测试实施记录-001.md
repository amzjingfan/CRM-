## 5. 实施方案

### 5.1 方案说明

先执行静态检查和完整自动化回归，再验证 013→009→013 迁移、数据库约束和运行时主链路；随后用临时店铺与数据执行跨店铺隔离、营销 unknown、冷却频控等专项，最后通过真实浏览器验证 Phase 3 页面、响应式、主题、语言和 URL 状态。测试结论只写入测试工程师权威报告，共享记忆仅登记索引和项目状态。

### 5.2 依赖关系

- 前置依赖：Phase 3 全栈实施记录、可用 Docker Compose、PostgreSQL、Redis、MinIO。
- 后续依赖：全栈开发工程师修复缺陷，测试工程师执行 Phase 3 独立复测。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 迁移回滚影响 Jobs | Worker 查询暂时不存在的表 | 回滚前停止 Jobs，恢复 head 后重启 |
| 临时测试数据污染 | 影响其他 Agent 判断 | 使用唯一前缀并在 `finally`/SQL 中清理，结束后复核计数 |
| 开发容器与构建并发 | `.next` 构建目录竞态 | 停止前端开发容器后重跑生产构建 |
| 旧 Jobs 镜像 | 新依赖未进入运行环境 | 按当前锁文件重建后重测，不把旧镜像误判为源代码缺陷 |
