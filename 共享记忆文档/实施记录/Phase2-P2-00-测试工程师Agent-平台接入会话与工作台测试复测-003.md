## 5. 实施方案

### 5.1 方案说明

先执行后端和前端质量门禁，再启动前端 Compose 服务，使用浏览器验证登录页、保护路由和四个视口；随后在临时数据库执行迁移升级/回滚/再次升级，并通过运行中的 backend、worker 和 PostgreSQL 验证认证、Webhook 幂等、非法签名、CSRF 和工作台数据链路。所有测试账号密码均运行时随机生成，不写入报告。

### 5.2 依赖关系

- 前置依赖：全栈工程师修复实施记录、现有 Phase 2 代码、Docker 服务和本地前端依赖。
- 后续依赖：架构师依据本报告进行 Phase 2 M02 技术验收；真实平台联调另行安排。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| Docker 镜像网络再次波动 | 容器无法启动 | 复测成功；保留 `NODE_IMAGE` 和 `NPM_REGISTRY` 可配置能力 |
| 测试数据污染开发库 | 影响后续测试 | 使用幂等演示数据；迁移使用临时库并完成清理 |
| 第三方平台仍为 Mock | 不能证明生产兼容 | 报告明确排除真实联调 |
| Phase 3 集成测试跳过 | 不能代表 RAG 全量通过 | 在报告中单独列明，不计入 Phase 2 M02 结论 |
