## 3. 目标、范围与非目标

### 3.1 实施目标

- 制定真实 TikTok 店铺和 DeepSeek API 的分阶段接入路径。
- 明确当前 Phase 4 生产阻断项和真实环境门禁。
- 规定真实店铺优先、测试店铺兜底的切换条件。

### 3.2 实施范围

- TikTok OAuth、只读 API、Webhook、人工写操作和自动化写操作。
- DeepSeek API、真实模型质量、公开 SSE 性能、五天稳定性和灰度。
- Agent 分工、凭证边界、回滚策略和正式报告。

### 3.3 非目标

- 不创建测试店铺。
- 不执行真实店铺写操作。
- 不修改产品代码、配置或密钥。
- 不把当前契约级 Mock 结论写成真实平台或生产 AI 通过。

## 5. 实施方案

### 5.1 方案说明

采用真实店铺优先的渐进式接入：先完成 OAuth 和只读能力，再接收 Webhook，之后仅开放人工确认的低风险消息，最后在真实模型质量、安全、性能和稳定性门禁全部通过后进入生产灰度。测试店铺只作为真实店铺无法安全联调时的替代环境。

### 5.2 依赖关系

- 前置依赖：Phase 3 Mock 工具层、Phase 4 SSE/Agent/营销工程能力、用户 TikTok 应用、公网 HTTPS 和 DeepSeek API Key。
- 后续依赖：真实平台适配实现、真实模型评测、公开 SSE 性能、稳定性报告和生产灰度。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 真实店铺写操作误触发 | 影响真实订单和客户 | 默认关闭写开关，先只读，再人工确认 |
| AI 高风险事实漏放 | 退款、地址和补偿错误承诺 | 关闭 `DEF-P4-AI-008/009` 前禁止自动回复和营销 |
| 模型性能未验证 | 公开 SSE 超时或拥塞 | 50 授权客户端、首分块/P99、五天稳定性和可用性报告 |
| 凭证泄露 | 店铺和模型账号被滥用 | Secret Manager、分环境 Key、轮换和日志脱敏 |
| 平台权限不足 | 真实接入无法完成 | 先读权限；只有明确权限或安全条件不足时切换测试店铺 |
