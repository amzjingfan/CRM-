## 5. 实施方案

### 5.1 方案说明

连续多轮失败的根因不是单个正则写错，而是把开放自然语言语义压在有限词表上：

1. “硬结果”词表命中后立即阻断，没有检查否定、条件、可能性、拒绝或引用警示，导致合法表达误杀。
2. 未进入硬结果或可作用域结果词表的同义词会落回政策/非断言白名单，前置安全语境因此放行后置事实。
3. 固定评测集与实现词表同步增长，只能证明已记忆样本稳定，不能证明新动词和新极性关系可泛化。
4. `ReplySafetyPolicy.evaluate(answer, evidence_kind)` 是文本级防御缝，尚无对象、动作、时态、极性、条件和来源的结构化声明契约，文本扫描被迫承担了超出其能力边界的语义解析职责。

本次把结果判定收敛为单一路径：

```text
NFKC、大小写和空白归一化
→ 建立局部命题边界
→ 以中文完成体/结果态、英文完成时/被动态和过去式识别结果候选
→ 每个候选统一检查否定、条件、可能性、拒绝和引用警示作用域
→ 未受非断言作用域控制的具体退款结果立即阻断
→ 无结果候选时再判断政策、资格、未决和证据否定关系
→ 其余退款主题继续失败关闭
```

有限结果词仍可作为纵深防御，但不再决定覆盖范围，也不能跳过作用域检查。命题边界识别“随后、接着、然后、而后、but、yet、after that”等独立关系，防止前置否定向后传播；一般政策被动结构则作为受控关系放行后续依据复核。

### 5.2 依赖关系

- 前置依赖：Phase 4 现有 `ReplySafetyPolicy`、`UNAUTHORIZED_COMMITMENT` 原因码和人工接管路径。
- 后续依赖：测试工程师执行 010 号独立复测；架构师评审结构化业务声明契约是否进入后续版本。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 新结果同义词不在词表 | 无依据事实漏放 | 使用完成体、完成时、被动态和过去式语法候选，不依赖具体结果动词 |
| 硬结果跳过极性 | 合法否定和警示误杀 | 所有候选强制经过同一局部作用域判定 |
| 前置安全语境跨命题扩散 | 后置肯定事实被放行 | 逗号、强边界和独立连接关系切断作用域 |
| 固定样本自证 | 下一轮更换同义词后再次失败 | 增加实现未逐项枚举动作词的属性测试 |
| 文本规则能力上限 | 无法形式化证明全部开放语言 | 保持自动能力关闭，并提交结构化声明契约架构评审风险 |

### 6.3 关键实现说明

- 删除硬结果命中后的立即返回旁路；有限硬结果、可作用域结果和通用语法候选统一循环、统一作用域检查。
- 中文结果候选覆盖完成体和结果态；英文覆盖完成时、被动态及带当前退款宾语的过去式，新增动作词无需同步加入产品正则词表。
- 局部命题同时检查前置和后置内容，使“尚未批准”“请勿相信已完成提示”“only after/only if”正确放行。
- 独立连接关系会重置命题起点，使“无法确认……随后已完成”中的否定不能支配后句。
- 所有新增测试继续通过 `ReplySafetyPolicy.evaluate` 公共入口，不调用私有正则实现。
- LLM 输出仍按不可信输入处理；日志、评测摘要和文档不记录客户原文、模型原始响应或密钥。
