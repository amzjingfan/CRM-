## 3. 目标、范围与非目标

### 3.1 实施目标

- 参考管理端原型统一管理端页面的导航、色彩、层级、卡片、表单、状态和响应式体验。
- 保持所有既有前端业务能力、后端接口路径、请求体、安全头和权限边界不变。
- 补齐认证异常、会话切换竞态、消息详情错误和已读状态反馈。

### 3.2 实施范围

- 应用壳层、登录页、根路由、数据看板、客服工作台和通用加载/空/错状态。
- 知识库、主动营销、Agent 管理和系统设置通过统一设计令牌与管理端组件样式获得一致视觉表现。
- 前端契约测试与多断点真实浏览器验证。

### 3.3 非目标

- 不修改后端 API、数据库、配置、AI Prompt、模型、RAG 或平台写操作。
- 不新增图表、图标或状态管理依赖。
- 不放宽 Mock、OAuth、自动回复、AI 营销或真实平台生产门禁。

## 5. 实施方案

### 5.1 方案说明

沿用现有页面组件和 `lib/api.ts`，以全局设计令牌和共享壳层为主完成渐进改造。登录页采用桌面双栏、平板及移动端单栏布局；管理端导航按看板、工作台、知识库、营销、Agent、设置排列；看板指标增加语义色和图表辅助网格；工作台继续使用三栏结构，并在窄屏切换为会话/聊天单视图和客户抽屉。

会话详情请求使用当前请求标记防止快速切换产生旧响应覆盖；详情加载失败显示明确错误状态；会话已读成功后同步清零列表未读数。认证服务异常显示可重试页面，401 仍按既有规则跳转登录。

### 5.2 依赖关系

- 前置依赖：既有 Next.js 前端、FastAPI `/v1` API、浏览器 Cookie/CSRF、店铺与 RBAC 数据。
- 后续依赖：正常前端镜像重建或发布流程使用本次源码与已通过的生产构建。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 大范围改样式造成业务交互退化 | 页面按钮、表单或列表不可用 | 不修改 API 层和业务提交逻辑；执行 lint、类型、契约测试、构建和真实浏览器回归 |
| 快速切换会话发生异步竞态 | 展示错误客户消息 | 详情 effect 增加当前请求标记，清理时废弃旧响应 |
| 小屏内容横向溢出 | 320px 设备无法操作 | 保留 44px 触控目标，并在 320/768/1024/1440 四档检查 `scrollWidth` |
| 旧运行实例未自动加载新源码 | 本地固定端口仍显示旧构建 | 使用独立端口验证当前源码；正式环境按既有流程重建前端镜像/进程 |
