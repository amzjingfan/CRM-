## 3. 目标、范围与非目标

## 5. 实施方案

### 5.1 方案说明

后端采用 FastAPI 模块化单体，统一管理配置、数据库会话、认证、权限、响应和异常；前端采用 Next.js App Router；PostgreSQL 保存业务数据并启用 pgvector，Redis 承担缓存和令牌状态，MinIO 作为对象存储；Docker Compose 提供本地一键运行环境。

### 5.2 依赖关系

- 前置依赖：Docker Desktop、Python 3.11、Node.js、PostgreSQL、Redis、MinIO。
- 后续依赖：平台接入、会话消息、客服工作台、知识库、AI Agent 和营销模块复用认证、权限、数据库和统一错误结构。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| Windows 主机连接 Docker PostgreSQL 不稳定 | 本地迁移命令可能失败 | 统一在 Compose 网络内执行 Alembic |
| Docker Hub 网络连接重置 | 后端镜像构建失败 | 后续切换可稳定获取的官方基础镜像 |
| Phase1 初期缺少店铺隔离 | 资源可能无法按店铺授权 | 后续创建 stores 后补齐 store_id 和权限隔离 |
