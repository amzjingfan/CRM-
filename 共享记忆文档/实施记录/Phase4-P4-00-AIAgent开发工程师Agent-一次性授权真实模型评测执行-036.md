## 5. 实施方案

### 5.1 方案说明

先执行完全本地的候选摘要、冻结数据集、清单、DLP、运行配置和聚焦回归门禁。门禁通过后，在单一隔离进程中临时设置 `APP_ENV=integration` 与 `LLM_LIVE_EVAL=true`，使用已存在的服务端 Secret 配置执行一次评测；DeepSeek SDK 重试固定为 0，评测进程不进入业务 Service、Repository、工具层或平台适配器。

36 条样本全部进入同一评测运行。其中 34 条发送到真实 DeepSeek，2 条 `model_timeout` 样本按冻结评测设计执行本地确定性故障注入，以验证失败关闭契约且不浪费外部请求。运行结束后立即对结果执行 Pydantic Schema、禁用字段、源正文回显和密钥回显检查。

### 5.2 依赖关系

- 前置依赖：REAL-AI-01～04、REAL-AI-05 001～004 号正式报告、人类数据责任人的精确一次性数据出境授权。
- 后续依赖：测试工程师独立复核本次结果并决定 `DEF-REAL-AI05-002` 状态；架构师、全栈和测试工程师继续完成 SSE 50 客户端、五日稳定性和生产放行。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 重复外部评测 | 超出一次性授权 | 固定唯一运行 ID 和排他结果路径；本次只启动一个外部评测进程，不执行重跑 |
| 模型正文或源数据落盘 | 扩大数据留存 | 结果 Schema 只允许哈希、枚举、原因码、时延、Token 与成本；落盘后检查正文出现次数为 0 |
| Provider 内部重试扩大调用 | 超出执行边界 | DeepSeek SDK `max_retries=0`，运行时 `LLM_MAX_ATTEMPTS=1` |
| 评测误触发业务副作用 | 写库或平台发送 | 评测入口只构建 Provider 与低敏聚合器，不加载工具、Repository 或平台发送流程 |
| 开发侧结果被误当作正式验收 | 越权放行生产 | 明确 `DEF-REAL-AI05-002` 仍待测试工程师独立复测，生产开关保持关闭 |
