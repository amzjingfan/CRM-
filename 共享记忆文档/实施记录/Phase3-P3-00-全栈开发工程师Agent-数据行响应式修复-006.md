## 3. 目标、范围与非目标

### 3.1 实施目标

- 修复知识库和营销数据行在 375px 移动端及 1024px 平板宽度下的横向溢出。
- 保持操作按钮可见、可换行、键盘可达，并沿用项目既有 44px 最小触控区域。
- 增加响应式样式回归测试，防止数据行恢复为不可收缩的横向布局。

### 3.2 实施范围

- 知识库和营销页面共用的 `.data-row`、`.row-actions` 响应式样式。
- Phase 3 前端静态契约测试。
- 全项目后端、前端、Compose 和依赖安全回归核验。

### 3.3 非目标

- 不修改测试工程师的正式测试报告和最终测试结论。
- 不修改 AI 工程师拥有的模型、Prompt、RAG、`app/agent` 或模型推理依赖。
- 不执行真实平台联调，也不新增或修改 API、数据库和环境配置。

## 5. 实施方案

### 5.1 方案说明

数据行内容区和操作区都允许收缩；文本使用安全断行，操作区使用 `flex-wrap` 和 8px 间距。在 1199px 及以下将营销活动数据行改为纵向排列，在 767px 及以下让所有数据行操作区占满容器宽度。该方案保留全部操作入口，不使用裁剪或隐藏横向溢出来掩盖问题。

### 5.2 依赖关系

- 前置依赖：Phase 3 知识库和营销页面现有数据行结构、第四次综合测试报告的数据态宽度证据。
- 后续依赖：测试工程师在 375/768/1024/1440px 四档视口使用真实数据独立复测。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 操作按钮过多再次撑宽容器 | 小屏出现横向滚动 | 操作区允许收缩和换行，小屏占满可用宽度 |
| 长标题或标识不可断行 | 内容区挤压操作区 | 数据行子项设置 `min-width: 0`，标题和辅助文本允许安全断行 |
| 响应式规则后续被覆盖 | 缺陷回归 | 新增 CSS 契约测试并纳入 `npm run test` |
| 未执行带认证数据态浏览器复测 | 无法由开发侧代替正式关闭缺陷 | 明确交由测试工程师按原报告步骤独立复测 |

### 6.3 关键实现说明

- `.data-row` 及其非操作子项设置 `min-width: 0`，避免 Flex 子项固有宽度撑开页面。
- `.row-actions` 从不可收缩单行布局调整为可收缩、可换行布局，最大宽度不超过父容器。
- 1199px 及以下的营销数据行采用纵向排列，解决报告中 1024px 数据态操作区溢出。
- 767px 及以下的操作区占据整行，按钮保留现有 44px 触控尺寸和键盘操作语义。
- 采用 UI/UX 规范中的移动优先、8px 间距、44px 触控目标和禁止页面整体横向滚动原则。
