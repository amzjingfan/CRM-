## 3. 目标、范围与非目标

### 3.1 实施目标

- 完成 TK-US 物流/履约、退换退款、商品刊登合规三类确定字节内容的内容负责人、来源权利和内部合规签署。
- 完成 KB-G0-01～07 的产品、架构、全栈、AI、测试与来源权利/安全角色评审，固化 K2/K3 可实施契约。
- 保持内容审批、索引资格、测试验收和生产放行相互独立。

### 3.2 实施范围

- 三份 `company_shared`、`en-US` 公司自编 JSON 内容与精确 SHA-256。
- 内容版本审批记录、来源登记、覆盖矩阵、测试计划和 G0 架构评审文档。
- 内部证据 API、服务身份/店铺委托、独立数据部署、迁移/回滚和质量/容量门禁。

### 3.3 非目标

- 不采集、复制、快照、嵌入或展示 TK 官方正文。
- 不构建或激活 K3 正式索引，不执行独立 QA，不把内容标为可服务。
- 不接入真实 Token/API Data、具体 SKU、订单、客户或 `shop_private` 数据。
- 不调用外部模型，不自动回复用户或执行平台动作；项目内部文档永不进入 RAG 语料。

## 5. 实施方案

### 5.1 方案说明

先将三类公司自编业务陈述冻结为确定字节 JSON，按版本复算 SHA-256，再由内容、来源权利和内部合规角色分别签署。架构评审并行检查产品范围、接口四态、身份授权、数据隔离、索引代际、FAQ 迁移、质量/容量和回滚；各角色提出的条件同步进权威文档后，由架构师形成 `验收-001-KB` 总结论。

已批准内容只获得进入隔离候选索引、冻结样本和独立 QA 的资格。索引激活与 `service_eligibility=true` 必须等待测试报告及发布记录，索引状态不得反向提升内容权威或使用权。

### 5.2 依赖关系

- 前置依赖：TK-US 市场与三场景确认、公开来源受限使用审批、已授权店铺低敏证据、现有本地 BGE 资产。
- 后续依赖：K2 独立知识服务实现；K3 候选索引、冻结评测、独立 QA 与发布记录；K4 私有来源/API Data 证据闭环。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 审批被误当正式发布 | 未测试内容进入正式服务 | 明确 `approved/approved/not_indexed` 与 `service_eligibility=false`，发布另设门禁 |
| 官方公开页面被误当可复制正文 | 权利越界 | 只保留来源元数据、官方链接和公司自编内容，禁止快照/原文向量/片段 |
| 静态规则冒充实时事实 | 错误订单、物流、退款或 SKU 结论 | 条件不足返回 `no_evidence` 或人工处理，K4 真实数据保持关闭 |
| 跨系统或外部模型泄露 | 权限和用途越界 | 每应用独立身份、item-level ACL、`external_model_allowed=false`、低敏审计 |
