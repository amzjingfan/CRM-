### 3.1 实施目标

- 修复 D19 中支付准备金因撤销扣款回升却未形成高风险资金候选的问题。

### 3.2 实施范围

- 调整 `RefundFactPolicy` 的金融目标、撤销来源、恢复状态、技术资产和命题级证据控制关系。

- 不由开发 Agent 自行关闭正式缺陷或放行公开回复、生产翻译、AI 营销、自动回复和真实平台写操作。

## 5. 实施方案

### 5.1 方案说明

第六轮失败由两个共享分类缺口组成，而不是工作流状态错误：

```text
客户金融目标 + 撤销/返还来源 + 恢复/增长状态
→ 形成当前资金结果候选
→ 无可信结构化声明时失败关闭

退款主题 + 技术对象类型
或 命题载体 + 审计/核验/证据控制谓词
→ 识别为资产或未成立命题
→ 保留人工复核草稿，仍不取得自动发送权限
```

技术资产识别扩展到事件说明书、GraphQL、消息路由、监控指标、SDK、物化视图及同类协议对象；非断言不只匹配单个否定词，而是要求叙述、主张、假说、核验人或证据材料与审计、确认、判断、验证状态形成关系。逗号后的“只是待验证假说”只控制紧邻候选，强标点后的新资金命题仍独立检查。

### 5.2 依赖关系

- 前置依赖：REAL-AI-02 结构化业务声明、AI-005 三态授权、021 号实施记录和 006 号权威测试报告。
- 后续依赖：测试工程师第七批独立开放集；REAL-AI-04/05 真实回复、翻译、营销与模型评测。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 开放金融词形继续变化 | 新资金事实可能漏放 | 按目标、来源和状态角色组合测试，保留结构化声明主边界 |
| 技术资产识别范围过宽 | 技术前句遮蔽客户事实 | 候选和资产按命题范围关联，新增强边界防遮蔽测试 |
| 后置非断言跨句生效 | 后续危险事实被错误放行 | 仅允许紧邻后置评价，强标点继续切分独立命题 |
| 开发回归被误认为缺陷关闭 | 生产能力提前放行 | P1/P2 保持 Reopened，要求第七批独立开放集和架构师门禁 |
