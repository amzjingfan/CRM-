## 2. 需求与依据

- 用户要求：大范围测试报告命名保持不变；阶段性测试报告必须明确哪个 Agent、Phase 几。

## 3. 目标、范围与非目标

### 3.1 实施目标

- 保留大范围测试的既有命名格式。
- 为阶段性测试新增 Phase、任务编号和被测主责 Agent 字段。
- 区分被测主责 Agent 与测试执行 Agent。

### 3.2 实施范围

- 测试工程师 Agent 规则。
- 测试报告命名规范。
- 团队职责、MVP 验收、代码手册、实施记录规范和测试报告索引。

### 3.3 非目标

- 不重命名现有大范围测试报告。
- 不修改正式产品代码。
- 不重新执行产品测试。

## 5. 实施方案

### 5.1 方案说明

采用双格式并行：大范围测试继续使用原格式；能明确归属 Phase、任务和主责 Agent 的阶段性测试使用扩展格式。扩展格式中的 Agent 表示被测功能的实施主责 Agent，测试报告作者仍为测试工程师 Agent。

### 5.2 依赖关系

- 前置依赖：实施记录中已明确的 Phase、任务编号和主责 Agent。
- 后续依赖：测试工程师据此生成报告，测试报告索引登记完整责任信息。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| Agent 字段被误解为报告作者 | 无法追踪被测实现责任 | 规范明确其含义为“被测主责 Agent” |
| 多 Agent 协作时文件名过于含糊 | 无法判断最终责任 | 文件名只写实施记录确认的主责 Agent，协作 Agent 写入正文 |
| 现有报告被强制改名 | 历史索引和引用失效 | 大范围报告保持原名不变 |
