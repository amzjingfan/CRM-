### 5.1 方案说明

先审查修复源码并建立缺陷矩阵；再执行后端、前端和依赖质量门禁；随后使用隔离数据库完成迁移与 pgvector 测试，运行 Phase 3 验收脚本；最后用真实浏览器验证父级维护、环路选项过滤、响应式尺寸和控制台，并清理全部夹具。

### 5.2 依赖关系

- 前置依赖：修复记录 004、运行中的 Docker Compose 服务、迁移 head `013_marketing`。
- 后续依赖：全栈开发工程师修复新缺陷，测试工程师执行下一轮定向复测。

### 5.3 风险控制

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 宿主 asyncpg 连接 Docker PostgreSQL 被重置 | 隔离库集成测试无法从宿主完成 | 将同一测试文件临时复制到后端容器，通过容器网络执行；结束后删除 |
| 迁移回滚影响正式数据 | 数据不可恢复 | 只在命名明确且预先确认不存在的隔离数据库执行，结束后删除 |
| 浏览器测试污染正式数据 | 后续测试不可信 | 临时账号和分类由保持运行的清理流程托管，测试结束后查询确认计数为 0 |
| 配置展开暴露敏感环境变量 | 密钥泄露 | 报告和索引不记录任何值，最终配置验证使用 `config --quiet` |
