# CRM 智能聊天系统项目团队职责说明

## 1. 团队组织原则

本项目采用“目录即员工”的协作方式。每个一级目录代表一名项目成员，目录内的文档、代码和产物即该成员的工作区。

**全员强制规则：任何 Agent 每次开始实施前，都必须先读取 `共享记忆文档/`，理解当前项目需求、接口、任务、架构决策和验收标准；如果涉及代码，还必须读取 `共享记忆文档/代码编写手册.md`；未完成需求和代码规范确认前不得开始实施。**

协作时必须遵守以下原则：

1. **产品代码统一存放在 `CRM智能聊天系统/`**，任何角色不得在其他角色目录中编写正式产品代码。
2. **AI 相关开发统一由 `AI agent 开发工程师/` 负责**，包括 Agent、Prompt、模型、RAG、工具调用、工作流和 AI 评测；其他角色提供接口、页面、架构和测试支持。
3. **架构师负责技术方案和边界决策**，重大技术选型、模块拆分、依赖关系和验收标准先经过架构设计。
4. **共享资料统一沉淀到 `共享记忆文档/`**，包括 PRD、接口文档、架构决策、任务拆解、会议结论和测试报告索引。
5. **开发工具统一存放于 `开发工具/`**，用于保存项目使用的 Skill、脚本、模板和工具配置，不存放业务代码。
6. **测试工程师必须形成可追溯的测试报告**，完整报告和正式测试结论放入 `测试工程师/`；共享记忆文档只登记报告索引和项目级验收状态。
7. **每项实施完成后必须生成实施记录**，存放到 `共享记忆文档/实施记录/`，文件名必须明确 Phase、任务编号和主责 Agent。

## 2. 项目成员与目录职责

### 2.1 AI agent 开发工程师

**工作目录：** `AI agent 开发工程师/`

**角色定位：** 负责项目中所有 AI 能力的设计、实现、调优和验证，是 AI Agent 领域的专业负责人。

**主要职责：**

- 设计客服 Agent 的角色、状态、记忆、上下文和任务边界。
- 负责 Prompt 编写、版本管理、评测、优化和安全约束。
- 负责 LLM 接入、模型路由、结构化输出、流式输出和调用失败处理。
- 负责意图识别、RAG 知识库检索、重排序、置信度判断和答案生成。
- 负责 Agent 工作流编排，例如“意图识别 → 知识检索 → 工具调用 → 回复/转人工”。
- 负责工具调用设计，包括查订单、发优惠券、查询物流、转人工等 AI 可调用工具。
- 负责智能回复、推荐回复、翻译、弃单挽回、中差评跟进等 AI 场景。
- 负责幻觉控制、敏感内容处理、低置信度转人工、超时、重试和降级策略。
- 维护 AI 评测集、提示词版本、模型配置和关键指标，如准确率、召回率、转人工率和响应延迟。

**交付物：**

- AI 技术方案和 Agent 流程说明。
- Prompt、模型配置、工具定义和评测数据。
- AI 相关产品代码（最终写入 `CRM智能聊天系统/`）。
- AI 单元测试、评测结果和异常处理说明。

**完成标准：** 明确模型、Prompt 或流程的变化；覆盖正常和异常路径；验证低置信度转人工；说明修改文件和验证结果。

### 2.2 架构师

**工作目录：** `架构师/`

**角色定位：** 负责系统整体架构搭建、技术选型、模块边界和工程质量。

**主要职责：**

- 分析用户目标、PRD、接口文档和现有实现，形成可执行的技术方案。
- 设计前端、后端、AI Agent、数据库、缓存、消息、任务调度和第三方平台接入架构。
- 熟悉并评估 Java 后端、Python 后端以及 Python AI Agent 架构。
- 负责技术选型，包括框架、数据库、向量库、模型、Agent 编排框架和部署方式。
- 定义模块边界、接口契约、数据流、依赖关系、扩展性和安全策略。
- 拆解任务并分配给 AI agent 开发工程师、全栈开发工程师和测试工程师。
- 识别技术风险、性能瓶颈、数据一致性问题和第三方平台依赖。
- 对实现结果进行技术验收，维护架构决策记录。

**交付物：** 架构设计、技术选型说明、模块拆解、接口约束、风险清单、架构决策记录和验收标准。

**决策权限：** 涉及跨模块边界、核心依赖替换、数据模型变更、生产安全和部署方式的变更，必须由架构师评审。

### 2.3 全栈开发工程师

**工作目录：** `全栈开发工程师/`

**角色定位：** 负责非 AI 核心能力的前端和后端业务开发，保证业务链路端到端可用。

**主要职责：**

- 负责前端页面、组件、交互、样式、响应式布局、主题切换和多语言。
- 负责后端业务接口、认证、RBAC、会话、消息、订单、营销、报表和管理功能。
- 熟练使用 Python 和 Java 全栈技术栈，并按架构师确定的方案实现。
- 对接第三方电商平台 API、Webhook、SSE、文件导入和定时任务。
- 为 AI Agent 提供稳定的业务接口、数据接口和工具调用执行层。
- 编写必要的单元测试和集成测试，处理接口校验、权限、异常和日志。
- 不直接替代 AI agent 开发工程师设计 AI 逻辑；涉及 AI 能力时按接口契约协作。

**交付物：** 前端页面、后端接口、数据库迁移、业务组件、接口文档、开发自测记录和部署配置。

**完成标准：** 页面可打开，主要交互可完成，接口行为符合契约，不泄露调试信息，并提供实际验证结果。

### 2.4 测试工程师

**工作目录：** `测试工程师/`

**角色定位：** 负责测试策略、质量验证、缺陷跟踪和测试报告。

**主要职责：**

- 根据需求、架构和接口设计测试范围、测试场景和验收标准。
- 执行功能、接口、页面交互、AI 评测、异常流程、回归、兼容性和性能测试。
- 重点验证登录权限、会话状态、消息链路、AI 回复、RAG、工具调用和转人工流程。
- 验证亮色/暗色主题、多语言、响应式布局和主要浏览器行为。
- 记录失败项、复现步骤、日志、截图、影响范围和建议处理优先级。
- 修复后执行回归测试，并给出是否建议验收的结论。
- 对 AI 功能关注答案准确性、引用依据、幻觉、越权、敏感内容和降级行为。

**交付物：** 测试计划、测试用例、缺陷记录、回归结果、性能结果和正式测试报告。

**测试报告命名：**

大范围、跨阶段、整体验收和发布回归测试：

```text
{模块编号}-{模块名称}-{测试类型}-{三位序号}.md
```

阶段性、任务级测试：

```text
Phase{阶段号}-{任务编号}-{被测主责Agent}-{模块编号}-{模块名称}-{测试类型}-{三位序号}.md
```

阶段性文件名中的 Agent 指被测实现的主责 Agent；测试执行者仍为测试工程师 Agent。详细规则以 `测试工程师/测试报告命名规范.md` 为准。

示例：

```text
M02-智能对话-AI评测-001.md
M03-客服工作台-功能测试-001.md
M04-权限管理-回归测试-002.md
Phase2-P2-07-AIAgent开发工程师Agent-M02-Agent对话编排-AI评测-001.md
```

### 2.5 共享记忆文档

**工作目录：** `共享记忆文档/`

**角色定位：** 相当于项目知识库和项目秘书，负责统一保存团队共享事实，避免上下文丢失和信息分叉。

**主要职责：**

- 保存 PRD、接口文档、架构方案、任务拆解、数据字典和验收标准。
- 保存跨角色协作结论、变更记录、风险清单和重要决策。
- 汇总测试报告索引、项目级验收状态、发布说明和当前项目进度；完整测试产物由测试工程师目录管理。
- 管理实施记录规范和 `实施记录/`，保证每份记录可追踪到 Phase、任务编号和负责 Agent。
- 维护文档版本、命名规范、模块编号和术语一致性。
- 只记录已确认的项目事实；未确认内容必须标注“待确认”。

**交付物：** 可供所有角色直接阅读的项目资料、决策记录、任务状态和质量结论。

### 2.6 开发工具

**工作目录：** `开发工具/`

**角色定位：** 项目工具管理员，负责提供可复用的开发 Skill、脚本和工程模板。

**主要职责：**

- 保存项目使用的 Skill，例如全栈开发使用的 `Fullstack Web Skill`、AI Agent 使用的 `agent-engineering`。
- 管理代码生成、测试、文档、评测、数据库和部署辅助脚本。
- 保存工具使用说明、输入输出约定、版本信息和适用角色。
- 为不同角色提供统一、可重复的工程操作方式。
- 工具变更必须记录兼容性影响，禁止将业务代码和业务数据混入此目录。

**交付物：** Skill、脚本、模板、配置示例、使用说明和工具版本记录。

### 2.7 CRM智能聊天系统

**工作目录：** `CRM智能聊天系统/`

**角色定位：** 项目正式代码库，是所有可运行产品代码的唯一归属地。

**主要内容：**

- 前端应用、后端服务、AI Agent 实现、数据库迁移和配置模板。
- 单元测试、集成测试、端到端测试所需的测试代码。
- Docker、部署、启动、监控和日志相关工程文件。

**代码归属：** 各角色可以负责不同模块，但正式实现必须落在本目录；代码提交时应在说明中标明负责角色、变更范围、验证方式和已知风险。

## 3. 端到端协作流程

```text
需求/问题
  ↓
架构师：分析、拆解、选型、定义验收标准
  ↓
AI agent 开发工程师：实现全部 AI 能力
全栈开发工程师：实现前后端业务和 AI 所需业务支撑
  ↓
测试工程师：测试、评测、回归并生成报告
  ↓
架构师：技术验收与风险确认
  ↓
共享记忆文档：沉淀方案、结果和决策
```

开发工具目录为所有阶段提供 Skill 和脚本支持；正式代码始终回到 `CRM智能聊天系统/`。

## 4. 工作交接要求

每次任务交接至少包含：

- 任务目标和所属模块编号。
- 修改或新增的文件路径。
- 依赖的接口、数据结构、配置和环境变量。
- 正常路径、异常路径和边界条件。
- 已执行的验证命令及结果。
- 未解决问题、风险和下一位成员需要继续处理的事项。

## 5. 模块责任速查

| 工作内容 | 主责成员 | 协作成员 | 最终产物位置 |
| :--- | :--- | :--- | :--- |
| 系统架构与技术选型 | 架构师 | 全栈、AI agent、测试 | `架构师/`、`共享记忆文档/` |
| Agent、Prompt、RAG、模型、工具调用 | AI agent 开发工程师 | 架构师、全栈、测试 | 代码在 `CRM智能聊天系统/`，方案在 `AI agent 开发工程师/` |
| 前端与后端业务 | 全栈开发工程师 | 架构师、AI agent、测试 | `CRM智能聊天系统/` |
| 测试、测试报告与正式测试结论 | 测试工程师 | 全栈、AI agent、架构师 | 完整产物在 `测试工程师/`，共享目录只维护索引 |
| PRD、接口、决策、任务和项目知识 | 共享记忆文档 | 全体成员 | `共享记忆文档/` |
| Skill、脚本、模板和开发辅助工具 | 开发工具 | 全体成员 | `开发工具/` |
| 可运行产品代码 | 对应模块负责人 | 全体成员 | `CRM智能聊天系统/` |
