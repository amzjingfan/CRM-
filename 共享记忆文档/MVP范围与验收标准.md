# CRM 智能聊天系统 MVP 范围与验收标准

## 1. 文档目的

本文档用于统一后续开发对 MVP 范围、核心闭环、实现深度和验收标准的理解。

所有 Agent 开始开发前必须阅读本文档，并结合最新 PRD、接口文档和架构决策执行。

### 1.1 当前版本范围关系

本文定义的仍是“三平台完整 MVP”验收标准，不因 v0.1 首版缩小而被改写。2026-09-08 确认的 v0.1 是完整 MVP 之前的 TikTok 人工辅助限定生产发布/试点子集，只验收 TikTok OAuth、读取、Webhook、人工发送、AI 建议、RAG、工作台、知识库和看板。

v0.1 的范围和门禁适用性以 `架构师/ADR-006-CROSS-TikTok人工辅助首版发布范围-v1.0.md` 为准。即使该限定版本通过，也只能声明“TikTok 人工辅助 v0.1 已放行”，不能声明本文件所定义的三平台、自动回复和主动触达完整 MVP 已全部完成。

## 2. MVP 核心目标

MVP 必须实现“客户消息进入系统后，可以被 AI 处理并自动回复或转人工”的核心业务闭环，并具备基础的主动触达和数据统计能力。

核心链路：

```text
TikTok / Shopee / Amazon 消息
        ↓
统一消息接入
        ↓
创建或更新客户、会话和消息
        ↓
AI 意图识别
        ↓
FAQ 知识库检索
        ↓
LLM 生成回复
        ↓
置信度判断
        ↓
自动回复或转人工
        ↓
记录日志并更新数据看板
```

主动触达链路：

```text
弃单 / 中差评
        ↓
定时任务检测
        ↓
AI 生成话术
        ↓
发优惠券或道歉消息
        ↓
记录执行结果
```

## 3. MVP 必须实现的模块

### 3.1 平台接入

至少支持以下平台：

- TikTok Shop
- Shopee
- Amazon

每个平台至少实现：

- 接收平台消息或订单数据。
- 将平台数据转换为统一内部格式。
- 创建或更新客户、会话和消息。
- 向平台发送回复或营销消息。
- 保存发送结果和失败原因。

如果真实平台审核或权限暂时无法完成，允许先使用 Mock 适配器、Webhook 测试接口或沙箱数据，但必须保留与真实平台一致的接口边界，并提供可重复执行的集成测试。

### 3.2 AI 智能问答

MVP 只实现以下 5 类意图：

| 意图 | 说明 | 示例 |
| :--- | :--- | :--- |
| `logistics_query` | 物流查询 | 我的订单到哪里了？ |
| `return_policy` | 退换货咨询 | 怎么申请退货？ |
| `size_guide` | 尺码咨询 | M 码具体多大？ |
| `price_inquiry` | 价格咨询 | 这个商品多少钱？ |
| `general` | 其他通用问题 | 客服电话是多少？ |

AI 流程必须包括：

- 意图识别。
- FAQ 检索。
- LLM 生成答案。
- 置信度评分。
- 自动回复。
- 低置信度转人工。
- 回复、检索和决策日志记录。

置信度规则：

| 置信度 | 系统行为 |
| :--- | :--- |
| `≥80%` | AI 自动回复 |
| `60%–80%` | AI 回复并标记人工复核 |
| `<60%` | 建议或自动转人工 |

MVP 采用单 Agent 工作流，不实现多 Agent 协同和 A2A 分布式协议。

### 3.3 FAQ 知识库

MVP 先实现 FAQ 问答层，不要求一次完成复杂知识中台。

必须支持：

- FAQ 新增、编辑、删除和查询。
- FAQ 分类管理。
- Excel 批量导入。
- FAQ 向量化和检索。
- 返回 Top-5 检索结果及相似度。

MVP 暂不强制支持 PDF、网页自动抓取和复杂文档解析。

### 3.4 客服工作台

必须提供客服统一处理入口，包含：

- 会话列表。
- 按平台、店铺、状态和未读筛选。
- 聊天历史和文本发送。
- AI 建议回复。
- 一键采用 AI 回复。
- 转人工。
- 客户基本信息。
- 订单查询。
- 发优惠券。
- 会话状态管理。

界面不要求达到完整商业化视觉标准，但必须支持客服完成一次完整处理。

### 3.5 主动触达

#### 弃单挽回

- 定时扫描未付款订单。
- 判断触达条件。
- AI 生成挽回话术。
- 自动发放优惠券。
- 发送消息。
- 记录执行结果。

#### 中差评跟进

- 定时获取中差评。
- 生成道歉或补偿话术。
- 自动发送。
- 记录发送结果和处理状态。

物流关怀在 MVP 阶段允许先做事件记录或基础通知，不要求复杂营销编排。

### 3.6 数据看板

必须展示以下 4 个核心指标：

- 会话量。
- AI 转人工率。
- 平均响应时间。
- 挽回 GMV。

同时支持：

- 近 7 天会话趋势。
- 平台渠道分布。
- 基础时间或平台筛选。
- 数据更新时间。

MVP 不实现自定义报表和复杂 BI 分析。

### 3.7 系统基础能力

必须具备：

- 登录。
- JWT 认证。
- RBAC 角色：`admin`、`supervisor`、`agent`。
- 店铺接入管理。
- 员工管理。
- PostgreSQL。
- Redis。
- 数据库迁移。
- Docker Compose 启动。
- 日志和基础异常处理。
- `/health` 健康检查接口。

## 4. MVP 技术边界

| 层级 | MVP 方案 |
| :--- | :--- |
| 后端 | Python FastAPI 单体应用 |
| 前端 | Next.js + Tailwind CSS |
| 数据库 | PostgreSQL + pgvector |
| 缓存 | Redis |
| LLM | Claude API 或 OpenAI API，先接入一个主模型 |
| 部署 | Docker Compose |
| Agent | 单 Agent 工作流 |
| 消息接入 | 官方 API + Webhook + 统一消息适配层 |

MVP 阶段不做 Kubernetes 微服务化，不做多 Agent 拆分，不做 A2A 分布式协议。

## 5. MVP 量化验收指标

| 指标 | 验收标准 |
| :--- | :--- |
| 平台接入 | 3 个平台具备统一接入能力 |
| 意图分类 | 5 类意图准确率 ≥85% |
| AI 独立解决率 | 常见咨询 ≥70% |
| AI 首字延迟 | <3 秒 |
| RAG 检索 | 返回 Top-5 结果并提供相似度 |
| 转人工 | 低置信度能够正确转人工 |
| 核心链路 | 消息→AI→回复/人工完整跑通 |
| 工具调用 | 查订单、发券、转人工可用 |
| 主动触达 | 至少成功跑通一个弃单挽回测试案例 |
| 测试覆盖 | 核心 AI、RAG、工具调用覆盖率 ≥70% |
| 压力测试 | 50 并发下 P99 延迟 <5 秒 |
| 稳定性 | 连续运行 5 天无阻断性故障 |
| 部署 | Docker Compose 一键启动 |

## 6. MVP 端到端验收场景

### 场景一：高置信度自动回复

1. 客户从任一已接入平台发送物流咨询。
2. 系统接收消息并创建或更新会话。
3. AI 识别为 `logistics_query`。
4. 系统检索 FAQ 或订单物流信息。
5. AI 生成答案，置信度达到 80% 以上。
6. 系统自动回复客户。
7. 会话、答案、置信度和发送结果被记录。

### 场景二：低置信度转人工

1. 客户发送超出知识库范围的问题。
2. AI 置信度低于 60%。
3. 系统不直接编造答案。
4. 会话标记为待人工处理或转人工。
5. 客服工作台显示待处理状态。
6. 测试工程师可以查看完整日志和转人工原因。

### 场景三：客服辅助处理

1. 客服打开会话列表。
2. 查看客户资料和历史消息。
3. 点击 AI 建议回复。
4. 一键将建议填入输入框并发送。
5. 客服可以查订单、发优惠券或转人工。

### 场景四：弃单挽回

1. 系统检测到满足条件的未付款订单。
2. 定时任务生成一条待触达记录。
3. AI 生成挽回话术。
4. 系统发放优惠券并发送消息。
5. 系统记录发送、优惠券和后续转化结果。

### 场景五：数据看板

1. 系统产生会话、AI 回复、人工接管和营销数据。
2. 聚合接口按时间范围统计数据。
3. 看板展示 4 个核心指标、趋势和渠道分布。
4. 数据与明细记录可以相互追溯。

## 7. 明确不纳入 MVP

以下功能推迟到 V1.1 或以后：

- WhatsApp 等新增渠道。
- 亚马逊创作者计划。
- 多渠道获客。
- 多 Agent 协同。
- A2A 分布式协议。
- Kubernetes 微服务化。
- 完整可视化营销流程编排器。
- 高级 BI 和自定义报表。
- 复杂模型训练和自动微调平台。
- 全自动无人客服运营。

## 9. 任务完成交接要求

每个开发任务完成后必须说明：

- 所属模块编号和任务目标。
- 修改或新增的文件路径。
- 使用的接口、数据结构、配置和环境变量。
- 正常路径、异常路径和边界条件。
- 执行过的验证命令及结果。
- 未解决问题、已知风险和后续建议。

测试报告必须放入 `测试工程师/`。大范围、跨阶段、整体验收测试使用：

```text
{模块编号}-{模块名称}-{测试类型}-{三位序号}.md
```

阶段性、任务级测试使用：

```text
Phase{阶段号}-{任务编号}-{被测主责Agent}-{模块编号}-{模块名称}-{测试类型}-{三位序号}.md
```

详细规则以 `测试工程师/测试报告命名规范.md` 为准。

## 10. MVP 完成定义

当客户从 TikTok、Shopee 或 Amazon 发来咨询后，系统能够完成：

> 接收消息 → 识别意图 → 检索 FAQ → 生成答案 → 自动回复或转人工 → 记录会话 → 在看板统计；

并且至少成功完成一次：

> 弃单检测 → AI 生成话术 → 发券触达 → 记录挽回结果；

即可认为 MVP 达到基本完成标准。
