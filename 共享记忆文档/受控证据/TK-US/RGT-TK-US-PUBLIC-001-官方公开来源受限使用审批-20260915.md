# RGT-TK-US-PUBLIC-001 官方公开来源受限使用审批

## 1. 审批信息

| 项目 | 内容 |
| --- | --- |
| 审批编号 | `RGT-TK-US-PUBLIC-001` |
| 审批对象 | `SRC-TK-US-001`～`SRC-TK-US-007` 七个 TikTok Shop US Seller University 官方公开页面 |
| 适用空间 | `company_shared` |
| 适用应用 | `company-knowledge-service` 及通过该服务登记、鉴权的公司内部消费系统 |
| 审批责任 | 架构师Agent（依据项目负责人在当前会话中指定“架构”负责审批） |
| 审批日期 | 2026-09-15 |
| 复核到期 | 2026-10-15；页面、条款、用途或访问边界变化时立即复核 |
| 审批结论 | **允许受限使用**；只批准来源元数据、公司自编摘要和结构化业务规则，不批准官方正文复制、快照、原文向量化或片段展示 |

这是公司内部知识治理审批，不是 TikTok Shop 的额外许可、平台协议变更或法律意见。平台条款与适用法律优先；若平台撤销授权、条款不再支持既定用途或专业复核否决，应立即停止采集与发布并撤回受影响版本。

## 2. 复核依据与判断

- [TikTok Shop US Seller Terms](https://seller-us.tiktok.com/university/essay?default_language=en&identity=1&knowledge_id=1331308753078058) 将 TikTok Shop Data 的使用限制在获准的卖家运营目的，并对共享、跨司法辖区传输、安全保护和 API Data 使用设置限制。
- [TikTok Shop Developer Terms](https://partner.tiktokshop.com/docv2/page/6506bc942f024f02be400315) 提供的开发许可具有有限、可撤销、不可转让等边界，不能被解释为取得公开页面全文的再许可或跨系统任意分发权。
- [Data Security and Privacy Review](https://partner.tiktokshop.com/docv2/page/data-security-and-privacy-review) 将授权、卖家、买家、订单、商品、运营、支持和日志等数据纳入受保护数据治理，要求数据最小化、留存/删除和撤销授权后的处置。
- 七个登记对象为公开的 Seller University 页面，但“可浏览”本身不证明可以复制全文、保存页面快照、对官方正文做向量化或向多个系统展示原文片段。

因此采用最小化方案：只登记官方 URL、标题、发布者、市场、语言、页面日期与复核日期；知识内容由公司人员重新表述为摘要或结构化规则，保留出处链接，不复制受保护的表达形式。该方案仍须经过逐版本内容审批和测试，不能凭本审批直接发布。

## 3. 允许用途

以下用途在本审批范围内：

1. 保存七个来源的 canonical URL、标题、发布者、`knowledge_id`、适用市场/语言、页面日期、复核日期及内容版本引用。
2. 由公司内部内容负责人基于官方页面编写非逐字的摘要、FAQ 与结构化业务规则，并保留官方来源链接和适用条件。
3. 仅对上述公司自编内容进行分块、嵌入、检索与内部引用；向已登记内部系统返回公司自编答案、来源链接和适用范围。
4. 为物流/履约规则、退换退款政策、商品刊登规则等卖家运营用途提供人工辅助；高风险结论必须经过人工复核。
5. 保存低敏的版本哈希、审批记录、命中日志和撤回记录，以支持审计、更新与删除。

## 4. 禁止用途

以下用途不在本审批范围内：

- 不保存官方页面全文、页面快照、截图、图片、表格、附件或大段原文；`snapshot_allowed=false`、`excerpt_allowed=false`。
- 不对官方原文、页面 DOM、截图 OCR 文本或附件直接建立向量；仅可向量化已审批的公司自编内容。
- 不批量抓取、不绕过登录/访问控制、不使用未获准的爬虫或自动化下载。
- 不向外部客户、供应商、模型服务商或未登记系统再分发内容；不把 `company_shared` 当作公开发布空间。
- 不把商品刊登政策当成具体店铺 SKU 规格，不把政策知识当成实时订单、库存、退款或履约状态。
- 不提供个案税务或法律结论，不据此自动发送客服消息、自动执行退款或其他平台写操作。
- 不将 Access Token、Refresh Token、授权码、真实店铺 ID、买家/订单/客服记录或其他店铺私有数据写入公司共享知识库。

## 5. 私有/API 数据边界

本审批只覆盖七个公开页面的低敏元数据和公司自编内容，不覆盖 TikTok Shop API Data。店铺商品、履约配置等数据若后续确需进入知识服务，只能在以下条件全部满足后进入租户隔离的 `shop_private` 空间：

1. 令牌实际 `granted_scopes`、Get Authorized Shops、CRM `channel_accounts` 绑定和只读调用均经受控核验；
2. 用途属于当前卖家内部运营，完成产品、隐私/平台协议与安全审批；
3. 实施最小字段、租户隔离、加密、留存/删除和撤销授权后的删除/停用机制；
4. 不包含买家、订单、客服对话、支付、风控或其他个人/敏感数据的 RAG 摄取。

API Data 不得因“店铺已授权”自动升级为 `company_shared`，也不得由多个公司系统直接共享同一令牌。

## 6. 发布门禁与撤回

每个正式内容版本仍须具备：来源 ID、公司自编正文、适用条件、版本哈希、内容审批人、审批时间、复核到期、评测集与撤回路径。物流、退款、商品政策等高风险规则须由业务内容负责人逐版本复核；税务内容须另经税务专业人员复核。

发生页面更新、条款变化、来源失效、内容冲突、审批过期或授权撤销时，立即将版本降为不可检索，停止后续采集，记录影响范围并按留存规则删除。未经这些门禁，覆盖矩阵状态保持 `待审批`，当前有效覆盖仍为 0。

## 7. 签署结论

架构治理签署：**允许受限使用 / 内容发布仍待审批**。

批准范围仅为“官方来源元数据 + 公司自编摘要/规则 + 官方链接 + 公司内部受控检索”。官方正文复制、页面快照、官方原文向量化、原文片段展示、公开分发以及任何店铺私有/API 数据摄取均未批准。
