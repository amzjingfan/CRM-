## 4. 受阻过程与安全处置

- 当前 TTS Open Toolkit 未登录，不能形成开发者会话侧的授权查询证据；本轮未自动发起新的持久 OAuth 登录。
- Partner Center API Testing Tool 页面未呈现可用操作界面，未能发起 Get Authorized Shops。
- 当前 CRM 容器已停止，staging 未形成可验证的在线服务，真实读取开关关闭。
- CRM 原 PostgreSQL 数据卷存在，但直接启动 PostgreSQL 会写入 WAL/元数据；为避免改变原始证据，本轮未把原卷以可写方式挂载或启动。
- 本机已有其他 PostgreSQL 服务占用默认端口，且没有获准的 CRM 数据库只读凭据；未尝试暴力猜测口令。

后续最小风险方案是：在用户明确批准后，将停止的 CRM PostgreSQL 数据卷只读复制到一次性临时卷，仅在副本上启动隔离 PostgreSQL，不暴露主机端口、不连接外部网络，只查询脱敏聚合字段（行数、状态、Scope 名称、到期/最近同步时间与不可逆关联摘要），随后删除临时副本。原卷不得以可写方式挂载。

## 5. 门禁结论

架构技术签署：**配置对应关系通过；令牌/CRM 运行态绑定未通过**。

在令牌实际 Scope、Get Authorized Shops、`channel_accounts` 脱敏行和最近成功只读时间齐备并经测试工程师独立复核前：

- 不得宣称真实 TikTok OAuth 或 CRM 店铺绑定验收完成；
- 不得启用 `shop_private` 数据摄取；
- 不得将商品、订单、客服或其他 API Data 转为 `company_shared`；
- 不得开放自动回复、退款、发布或任何平台写操作。
