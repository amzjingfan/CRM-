## 2. 覆盖计数与私有空间模板

本次矩阵列出八个一级领域、八个 TK-US 候选覆盖单元：`已生效 0`、`待审批 7`、`资料待获取 1`、`已过期 0`、`不适用 0`。这不是八领域内容完备率，也不代表七份正文可保存或检索。架构师Agent已被用户指定为治理统筹；所有高风险单元的专业内容复核、平台权利批准及复核日期仍未完成，不得发布。

`shop_private` 只保留非计数模板：`domain_code / TK / US / en-US / 内部授权读者 / shop_private / shop_ref`。只有平台负责人证明实际店铺授权、产品指定业务用途、权利负责人确认 API/上传资料的内部处理范围且产生稳定代号后，才创建真实单元。当前不在 Git 记录店铺 ID、Token、订单号或客户资料；从 TK API 获取的商品等静态店铺数据也不自动变为 `company_shared`。

## 3. 首批试点场景与更新规则

用户于 2026-09-14 确认首批三个 TK-US 试点场景：物流/履约规则咨询、退换退款政策咨询、商品信息/规格咨询。前两类分别落在 `COV-TK-US-LOG-01`、`COV-TK-US-AFT-01` 的候选目录；第三类属于商品领域，但 `COV-TK-US-PROD-01` 当前的 `SRC-TK-US-002` 只是商品刊登政策，不能证明具体商品规格，规格试点仍是 `资料待获取`。在产品/平台负责人提供获准的实际商品资料、真实店铺授权及稳定低敏店铺代号前，不实例化 `shop_private` 规格单元。物流最佳实践亦不能单独代替适用的履约政策。架构师Agent统筹治理，产品/专业内容及权利负责人仍须确认具体问题、目标读者、来源许可和验收样本。价格/活动、订单实例、税务合规等维持目录与缺口管理，不以空内容强行演示回答。

每次更新本矩阵时，先核对 `共享记忆文档/公司级知识来源登记与许可清单.md` 的来源权利和版本，再核对内容审批、实际店铺/应用授权、时效和测试工程师冻结评测结果；缺任何一项不得升为 `已生效`。来源撤销、冲突或到期应立即降级并记录原因。正式测试报告只放 `测试工程师/`，本矩阵仅保存低敏评测集引用和项目级状态。
