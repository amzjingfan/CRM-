# 动态 Agent 模块

当前正式人工建议和管理页调试都从本目录进入。模型读取当前店铺所有已启用 Agent 的描述、服务范围和冻结会话上下文，通过原生 function calling 选择参与者；每个 Agent 根据自身发布版本发现全部配置工具，调用后生成草稿，协调器汇总成一段，经独立依据复核和最终知识撤权检查后供坐席复核。

| 目录 | 职责 |
| --- | --- |
| management | 店铺配置、不可变发布版本、模型/七段式系统提示词/工具/文件绑定和调试 HTTP 入口 |
| orchestration | 全候选语义路由、子 Agent 并发协调、结果汇总与冲突检测 |
| runtime | 正式建议、单 Agent 执行、冻结快照、状态机、上下文预算和运行持久化 |
| tools | `@tool` 目录、原生调用循环、授权对象绑定和实时订单/物流只读适配 |
| rag | 显式绑定文件检索、Embedding、重排、分块与共享向量化支撑 |
| memory | 同店铺/会话/客户范围的摘要及已核验事实、乐观锁和关闭/重开生命周期 |
| prompts | 七段结构、平台策略、编译、正文摘要与发布校验 |
| providers | DeepSeek、OpenAI、Anthropic 原生 function-calling 协议 |
| safety | 不可信来源标记、输入脱敏和只读工具结果投影 |
| core | 翻译、营销、历史离线评测及仍共用的模型/安全/运行契约；不含旧 FAQ 执行器 |

运行入口是 `runtime.formal.run_formal_suggestion` 和 `management.debug.run_agent_debug_v2`。旧 `app.agent`、`app.agent_management`、FAQ 工作流、正则工具路由、FAQ 专用 Provider 端点及固定答案渲染已退役。知识库自身的 FAQ 管理、数据和向量化保持原有职责。

Agent 数量和配置工具数量不设固定截断；候选目录按上下文容量分批。工具循环受一次运行的总截止时间、模型上下文和重复无效调用收敛约束。模型不能提供店铺、订单或客户权威 ID；服务端从授权会话绑定这些对象。写工具只形成待人工确认提案，本模块不发送平台消息。

RAG 必须显式传入文件范围，并验证店铺、当前有效版本、内部审批与展示前撤权。未绑定文件时只使用已配置工具，证据不足时澄清或转人工，不检索整店 FAQ。

七段提示词由身份职责、服务范围、工具规则、升级条件、语言格式、合规红线、澄清兜底构成。发布版本、文件版本、消息水位和记忆 revision 在运行开始冻结。金额、状态等可信事实带来源保存，预算不足不会截断或改写事实。会话关闭冻结写入，重开恢复；记忆不跨用户或会话。

`AGENT_V2_DEBUG_ENABLED` 与 `AGENT_V2_FORMAL_ENABLED` 默认关闭。关闭时明确返回不可用，不恢复已删除的 FAQ 路径。故障版本通过保留的上一发布产物恢复；新配置和记忆数据不依赖破坏性降级。
