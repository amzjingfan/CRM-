## 2. 责任边界

- AI Agent 负责语言识别、回复语言/语气解析、结构化生成、翻译、安全门禁、置信度和评测契约。
- 全栈服务负责公开 API、认证、店铺权限、可信业务上下文、SSE 传输、工具执行、业务表和平台写。
- 测试工程师负责真实模型质量、50 并发 SSE、首输出、真实平台和 5 天稳定性的正式结论。
- Agent 结果始终 `send_performed=false`；`auto_reply` 只是达到条件的决策，不是已发送事实。

## 3. 店铺级回复策略

`AgentReplyProfile` 是可信内部契约：

| 字段 | 可选值 | 默认值 | 安全规则 |
| --- | --- | --- | --- |
| `tone` | `friendly/professional/concise/empathetic` | `friendly` | 只转换为固定系统指令 |
| `reply_language` | `auto/zh-CN/en` | `auto` | `auto` 只依据确定性语言识别 |
| `operator_language` | `zh-CN/en` | `zh-CN` | 只用于客服翻译目标 |
| `brand_name` | 1～80 字符 | 空 | 拒绝控制符与换行 |

内部从 `agent_configs.knowledge_scope.reply_profile` 解析该配置。公开 Agent 配置 API 仅允许写该强类型子对象；任意运营文本、模型、Prompt 和阈值仍拒绝写入。

## 4. 语言与翻译

- 客户语言先使用字符集信号分成 `zh-CN/en/mixed/unknown`，不调用模型。
- `mixed/unknown` 在自动模式下保守回退到客服工作语言，不静默猜测。
- FAQ/工具结构化输出必须显式返回 `answer_language`，与解析语言不一致即失败关闭。
- 翻译结果通过 `trigger_message_id + source_text_sha256` 与原消息关联，不改写或复制 `messages`。
- 翻译前复用敏感信息脱敏，不允许模型还原屏蔽标识。只有通过主回复安全门禁的草稿才可翻译。
- `AI_TRANSLATION_ENABLED=false` 默认关闭，避免额外模型调用无意拉长 SSE 关键路径。开启时必须同时 `LLM_ENABLED=true`。

## 5. 确定性安全门禁

门禁在模型依据复核前执行，且不信任模型的“安全”声明：

| 原因码 | 含义 | 处置 |
| --- | --- | --- |
| `SENSITIVE_DATA_EXPOSURE` | 输出包含邮箱、手机或长标识符 | 清空草稿，转人工 |
| `UNAUTHORIZED_COMMITMENT` | 无授权退款、退费、退钱、返款、赔付/补偿执行承诺，或审批、审核中、处理、打款、汇回、到账等无依据状态；政策、申请条件、平台审核流程、查询入口和一般时效说明不命中此规则 | 清空草稿，转人工 |
| `FABRICATED_ORDER_STATUS` | 无查单/物流工具依据的实时状态 | 清空草稿，转人工 |
| `MOCK_COMPLETION_CLAIM` | 将 Mock 结果描述为真实已完成 | 清空草稿，人工复核/转人工 |
| `OUTPUT_LANGUAGE_MISMATCH` | 输出语言违反店铺策略 | 清空草稿，转人工 |

FAQ 引用、工具调用引用、Prompt 注入防护、模型拒绝和置信度决策继续遵守 AI-002 与 AI-004。

## 6. AI 营销文案

```text
waiting_ai 事件
→ 店铺解析与可信触发摘要
→ MarketingCopyService
→ 结构化文案
→ ReplySafetyPolicy
→ 安全：交给现有幂等工具链路
  不安全：AI_MARKETING_REVIEW_REQUIRED
```

- 弃单只接受 `pending/unpaid` 支付状态、币种和字符化金额；不传平台订单号或客户标识。
- 中差评只接受 1～3 星和经脱敏评价。可以道歉和邀请人工协助，不得自行承诺退款/补偿。
- 生成节点固定 `send_performed=false`。安全通过后才交给 Worker，且必须先生成安全文案再执行发券等副作用。
- LLM 瞬时错误按现有上限重试；安全拒绝不自动重试。平台写仍由 `tools`/适配器处理。

`agent_runs.output_summary` 只增加节点路径、Prompt 版本、语言、翻译错误码和安全原因码，不保存客户正文、翻译正文、知识正文、完整模型输出或密钥。营销消息触达必须先找到同店铺客户会话，再创建统一 `agent_runs`；后续 `tool_calls` 关联同一运行 ID。没有会话时在模型调用前失败，不伪造外键。

## 8. 评测和回归规则

- 退款主题先执行 NFKC/大小写归一化，再验证完成态谓词是否绑定退款申请、审批、资金、账户或可信业务主体。有限结果动词不能成为安全边界，孤立的“已/has”也不能在页面、按钮、文档、FAQ 或表单等非业务对象上触发退款事实。
- 每个业务结果候选只接受直接支配它的否定、条件、可能性、拒绝和引用警示。前置政策、否定或未决表述不能跨越另一主语或任意话语关系掩盖后置资金事实；无可信退款工具事实时，未受直接控制的具体结果失败关闭。
- `evals/agent-phase4-v1.0.0.jsonl` 当前包含 234 条客服回复、翻译、弃单和中差评安全样本。报告 010 的 16 条业务结果与 16 条非业务完成对象作为独立回归测试保留，不并入同版固定评测集作为泛化证明。
- 确定性文本门禁是纵深防御，不能形式化证明覆盖全部自然语言。自动回复、真实模型和真实平台写保持关闭；生成节点的结构化业务声明契约需要由架构师单独评审后再改变工作流接口。
- 确定性门禁必须输出安全判断准确率、原因码准确率和危险漏放数，不输出样本正文。
- 统一指标契约覆盖意图准确率、RAG 命中率、工具成功率、转人工率、动作准确率、P95 首输出、平均耗时、Token 和显式价格下的估算成本。每日 P95 可写入 `metric_daily`，但 1/7/30 天周期 P95 必须按店铺时区从原始 `agent_runs.first_output_latency_ms` 样本重新计算，禁止取每日 P95 的最大值或平均值。
- 任何 Prompt、模型、检索、工具 Schema 或安全规则修改，必须执行对应版本集与全量回归。没有真实密钥/模型时不得声称正式模型评测通过。

## 9. 交接与生产门禁

- `/suggest`/SSE 已增量映射低敏翻译结果，Agent 配置 API 已提供经授权的强类型回复画像；全栈工程师后续负责前端展示与编辑交互。
- 真实平台适配器、优惠批准政策、营销合规和消息订阅/退订规则在生产自动触达前必须由架构师确认。
- 测试工程师必须独立验证真实模型中英质量、行为安全、SSE 首输出小于 3 秒、50 并发 P99、成本预算与 5 天稳定性。
