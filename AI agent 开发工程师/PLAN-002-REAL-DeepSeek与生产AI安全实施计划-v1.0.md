## 1. 目标和边界

实现 DeepSeek Provider，关闭 `DEF-P4-AI-008/009`，完成真实模型回复、翻译、营销草稿、安全门禁和版本化评测。AI Agent 不直接访问 TikTok、平台凭证或业务数据库写接口，任何业务动作继续使用全栈白名单工具。

评测通过前只允许离线或内部草稿模式；不得开启公开回复、自动回复、AI 营销发送和真实高风险平台写操作。

## 2. 实施门禁

编码前必须读取共享记忆、代码编写手册、AI 目录适用 Skill、`AI-005-REPLY`、M04 010 正式测试报告及全部 004～009 历史缺陷样本。先冻结独立评测集，禁止边修改规则边把失败样本加入训练集后自证通过。

真实 DeepSeek Key 只能由用户通过服务端环境提供；测试、日志、Prompt 和评测证据不得保存 Key 或完整客户隐私。

## 3. 纵向实施任务

### REAL-AI-01：DeepSeek Provider 生产加固

> 当前状态（2026-08-27）：009 号第九次独立复测已关闭 `DEF-REAL-AI01-007`，并确认
> `DEF-REAL-AI01-001～006` 保持关闭；REAL-AI-01 Provider 当前工程范围有条件通过。该结论不放行
> 真实客户业务 Prompt、REAL-AI-02～05、公开回复、生产翻译、AI 营销、自动回复、原生 Token SSE、
> 50 客户端并发或五日稳定性门禁。

- 复用当前 `DeepSeekProvider`、Provider Factory 和 OpenAI 兼容 Chat Completions 实现，不创建第二套 Provider 或 Agent 工作流。
- 加固结构化输出、超时、有限重试、取消、限流和稳定错误分类；保持 SDK 重试关闭，由现有 Agent 服务统一限次。
- Provider 输入使用最小化脱敏上下文；输出必须经过 Schema 校验后才能进入工作流。
- 记录 Provider、模型、Prompt 版本、请求 ID、Token、首输出和总耗时，不记录原始敏感内容。
- 当前 SSE 是安全草稿校验后的传输层分块，不直接输出 DeepSeek 原生 Token；若以后需要原生流式输出，必须另行评审增量安全门禁。

验收：最小请求、流式、非法输出、截断、空响应、429、超时、取消和供应商错误。

### REAL-AI-02：结构化业务声明

> 当前状态（2026-08-31）：测试工程师正式报告已确认 `DEF-REAL-AI02-001～004` 全部关闭。只读低敏重放
> 契约已在执行器、权威声明和可信证据边界统一复验；重放仍按当前权限检查，权限已撤销时不返回历史摘要，
> 也不覆盖原成功审计。未修改公开 HTTP/SSE、数据库、依赖、模型或 Prompt；公开回复、生产翻译、AI 营销
> 和自动回复继续关闭。

定义内部受控声明，至少包含：

```text
subject_type
subject_id
action
tense
polarity
condition
evidence_type
evidence_id
confidence
```

- 订单、物流、退款、优惠、地址和承诺时间等高风险事实必须形成声明并绑定可信工具证据。
- FAQ 只能证明政策和知识，不能证明某个订单已退款、已发货或资金已到账。
- 无证据、证据跨店铺、时态不一致、否定/条件作用域不明确时失败关闭并转人工。
- 文本规则保留为纵深防御，不继续承担唯一事实证明职责。

若声明需要修改跨模块公共 DTO 或数据库，先提交架构师评审；优先作为 Agent 内部类型实现，避免不必要迁移。

## 4. 与全栈的固定契约

- AI 输入只接收可信 `store_id`、会话上下文、最多限定条数的历史、FAQ 引用和工具证据。
- AI 输出保持 `send_performed=false`，仅返回草稿、动作建议、声明、引用、安全原因和工具需求。
- 全栈工具层决定权限、幂等、平台执行和最终发送状态。
- Provider 配置和 Key 注入由全栈运行面提供；AI 代码不得读取浏览器配置。
- 任意跨模块字段变更先登记共享记忆并由架构师确认。
