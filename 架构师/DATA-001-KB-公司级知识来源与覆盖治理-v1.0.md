## 1. 目的与非语料边界

本文件定义 K1 治理元数据和 K2/K3 可测试的准入规则，不是知识库语料、数据库迁移或已经批准的接口 DTO。`共享记忆文档/` 中的覆盖矩阵与来源登记仅用于项目治理，不允许被采集器读取或向量化。项目 PRD、代码、接口、实施记录、测试、运维材料、内部聊天和凭证均在语料排除清单内。客户当前订单、物流、退款和地址等实例事实只能由可信业务接口获取。

一级领域固定为：`platform_operations` 平台开店与运营、`product` 商品与选品、`pricing_marketing` 定价促销与营销、`order_payment` 支付风控与订单、`fulfillment` 仓储物流与清关、`aftersales` 售后退换与争议、`customer_service` 客服沟通与服务流程、`tax_compliance` 市场税务与合规。领域目录可全量建立，但每个领域的有效内容覆盖必须单独举证。A/B/C/D 分别是获准原始资料、经确认业务规则、FAQ、脱敏且获准案例的内容形态，不授予权限。

## 2. 覆盖单元

覆盖单元以 `domain_code × platform_code × market_code × language_tag × audience_code × space_code × shop_ref` 唯一标识，生成稳定 `coverage_cell_id`。其中 `shop_ref` 是稳定、低敏内部店铺代号：`company_shared` 时必须为空，`shop_private` 时必须非空且经权威授权映射。不能用店铺名称、平台 Token 或浏览器自报 ID 作权限依据；不同店铺不能合并为一个私有单元。泛跨境电商资料可用平台 `cross_platform`，但只有确认跨平台适用的来源才可如此标记。语言使用 BCP 47 标签，首批 TK-US 来源的原文候选为 `en-US`。

| 字段 | 必填/可空 | K1 临时权威及未来服务权威 | 规则 |
| --- | --- | --- | --- |
| `coverage_cell_id` | 必填 | 覆盖矩阵；K2 服务生成 | 根据上述完整维度稳定生成，不靠表格行号 |
| `domain_code` / `platform_code` / `market_code` | 必填 | 覆盖矩阵；K2 受控枚举 | 首批市场 US 是用户指定，真实店铺关联另行核验；未知市场不可兜底为 US |
| `language_tag` / `audience_code` | 必填 | 覆盖矩阵；K2 服务 | 语言与读者不匹配不得扩大适用范围 |
| `space_code` / `shop_ref` | 必填/条件必填 | 覆盖矩阵；K2 授权权威 | 仅 `company_shared`、`shop_private`；后者必须绑定店铺代号 |
| `knowledge_shape` | 必填 | 覆盖矩阵；K2 内容版本 | A/B/C/D 是形态而非安全等级，可针对同一来源有不同版本形态 |
| `coverage_status` | 必填 | 覆盖矩阵；K2 由权威事实推导 | `资料待获取 / 待审批 / 已生效 / 已过期 / 不适用`；不得由运营直接绕过准入设为已生效 |
| `content_owner_ref` / `review_due_at` | 必填/未有来源时可空 | 覆盖矩阵；K2 治理记录 | 无负责人不得发布；复核周期由来源更新频率和风险决定，不预设全域固定天数 |
| `source_refs` / `evaluation_set_ref` | 可空/生效时必填 | 来源登记、测试计划；K2/K3 权威 | 无已授权来源或未通过评测时有效覆盖数为 0 |
| `gap_reason` | 未生效时必填 | 覆盖矩阵 | 区分缺来源、缺权利、缺审批、缺评测、缺授权、过期和不适用 |

K1 矩阵只可陈述来源登记与审核进度；正式“已生效”必须由服务端读取当前内容版本、许可、权限、时间与索引状态后推导。一个覆盖单元存在候选 URL 并不代表该单元已有可检索知识。

## 3. 来源、使用权与内容版本

来源指外部发布者或经商家授权的资料；内容版本指本服务实际处理的精确字节/结构化字段。二者必须分开。公开可访问的官方页面只是候选来源，不自动证明允许复制全文、保存快照、制作向量、在多个系统共享或对买家引用。

| 字段 | 必填/可空 | 权威与限制 |
| --- | --- | --- |
| `source_id`、`publisher`、`source_type` | 必填 | 来源登记；类型区分官方页面、商家授权上传、人工维护、实际授权 API 数据，不能把第三方转载标为官方 |
| `canonical_url_or_object_ref` | 必填 | 官方 URL 或受控对象键；不记录签名 URL、Token 或原始私有文件路径 |
| `source_market`、`source_language`、`source_updated_at`、`captured_at` | 必填/页面无公开更新时间时可空 | 来源适用范围与核验时间分离；未知时保持待审，不伪造发布日期 |
| `rights_basis_ref`、`rights_review_status`、`rights_reviewer_ref`、`rights_reviewed_at` | 发布前必填 | 仅保存授权依据的低敏引用；状态区分 `未审 / 允许受限使用 / 拒绝 / 已撤销`，不得用网页可见性代替许可 |
| `allowed_app_refs`、`allowed_space_codes`、`snapshot_allowed`、`excerpt_allowed` | 发布前必填 | 使用权必须细化到内部应用、空间和保存/展示形式；未明确即按不允许处理 |
| `source_owner_ref`、`review_due_at`、`effective_from`、`effective_until` | 发布前必填/结束时间可空 | 到期、撤权或复核逾期均从正式检索排除，人工延长须留审计 |
| `content_version_id`、`content_sha256`、`source_id` | 内容版本必填 | 正文/结构化字段、适用范围、语义类型或许可变更均产生不可变新版本；哈希只用于完整性，不证明正确性 |
| `statement_type`、`customer_scope`、`risk_level` | 内容版本必填 | 沿用 ADR-005 分类；政策、税务、合规、支付承诺等标高风险，不以模型自动分类取代人工确认 |
| `approval_ref`、`approved_by_ref`、`approved_at`、`index_state` | 正式检索前必填 | 审批绑定精确版本；索引就绪是必要但非充分条件；不能引用 CRM `users` 外键 |
| `conflict_group_ref`、`supersedes_version_ref` | 有冲突/替代时必填 | 关联受影响平台、市场和生效时间；不以相似度分数裁决相反规则 |

日志和测试制品只保留低敏 ID、状态、错误码、耗时、来源标识和不可逆/脱敏摘要；不记录完整客户查询、正文、向量、密钥、平台原始响应或许可凭据正文。历史会话形成 D 层前必须先取得合法使用依据、去标识化并逐条审批；默认不收录。

## 4. 准入与状态迁移

来源状态与内容版本状态分开。来源可处于候选、权利审查、受限许可、拒绝或撤销；这些状态不得由索引 Worker 改写。内容版本正向路径为 `draft → reviewed → published/pending → ready`：`reviewed` 仅表示元数据/内容待发布审核，不可检索；`published/pending` 表示精确版本获准内部复核但索引未完成，不可检索；`ready` 仍需每次查询重新核对权威许可、空间、店铺、市场、时效和冲突。撤销、过期、授权失效是权威不可检索条件，异步删除切片不是生效条件。

| 事件 | 有权操作人/系统 | 权威变化 | 正式检索 | 审计与恢复 |
| --- | --- | --- | --- | --- |
| 新来源或自动采集 | 受控采集器/内容人员 | 来源候选；内容 `draft` | 禁止 | 记录来源、批次、低敏校验；待权利审核 |
| 元数据与许可复核 | 内容负责人、使用权核准人 | 来源获受限许可；内容 `reviewed` | 禁止 | 记录许可范围、审核主体与时间；缺一项退回草稿 |
| 精确版本审批 | 有管理权限的审批人 | `approved_for_internal_review`，`published/pending` | 禁止 | 记录内容哈希、版本、审批人、时间；不得自动提升到公开回复 |
| 幂等索引成功 | 索引 Worker | 当前版本索引 `ready` | 仅在全部权威条件同时满足时允许 | 哈希和版本原子比较；失败保持不可检索 |
| 正文、分类、适用范围或许可改变 | 内容负责人/来源变更事件 | 新版本 `draft`；旧版本失去当前资格 | 旧新版本均禁止，直到新版本重新审批/索引 | 保留历史和差异，不复用旧审批 |
| 撤销、复核逾期、许可失效或店铺撤权 | 有权人员/权威事件 | 当前资格立即失效 | 立即禁止 | 留低敏审计；恢复需重新核验并按版本审批 |
| 来源冲突登记 | 内容负责人 | 标记受影响版本/范围 `conflict` | 不给出胜者；返回冲突/人工确认 | 记录双方来源、适用范围和裁定主体 |
| 模型、索引或授权权威故障 | 系统 | 不改变内容批准事实 | 返回 `unavailable` 或认证拒绝 | 恢复后重试，不降级为自由生成或普通无答案 |

只有当前版本已批准、许可允许该应用/空间/展示形式、主体及店铺授权有效、平台/市场/语言/读者匹配、未过期或冲突、索引完整就绪并通过独立质量评测时，覆盖状态才允许为 `已生效`。`unknown` 语义类型、损坏/缺失安全元数据、版本漂移或未登记权利一律不可检索。CRM 使用这些证据也只能内部人工复核，`automatic_delivery_allowed=false`。

## 5. 高风险、冲突和复核

政策、税务、法律、支付风控、平台限制及对客户作承诺的资料为高风险。内容负责人按来源更新频率提出复核到期时间，产品/有权审核人批准；到期未复核时先失效，再补审，不用全域统一天数掩盖差异。税务/法律资料只能提供来源与适用条件，不由知识服务形成具体操作结论。内容负责人可人工登记自然语言冲突并立即停止相关版本的正常证据返回；系统不承诺自动发现全部冲突。

店铺私有资料必须核验授权数据类型和实际 Scope。TK-US [卖家条款](https://seller-us.tiktok.com/university/essay?default_language=en&identity=1&knowledge_id=1331308753078058) 的 API 数据使用范围由有权人员审查；外部页面与店铺 API 数据是两种不同权利来源，不能用其中一种许可覆盖另一种。K1 仅登记候选 URL，不抓取正文、不存快照、不构建向量。

## 6. K1/K2/K3 交接与验收

- K1 交付八领域目录、覆盖矩阵、来源及权利登记、首批 TK-US 市场和候选场景。矩阵的 `已生效` 数由可验证证据决定，不能凭类别数量推断。
- K2 将本模型转成独立数据库约束、授权策略、审计和内部 API；具体字段类型/索引/错误码须经 KB-G0 ADR 与接口设计评审，不以本文代替迁移脚本。
- K3 对已获使用权且获逐版本审批的内容进行解析、索引和按领域评测；新阈值、引用合法率与 GPU 资源需测试工程师独立报告。
- 安全负样本至少覆盖跨应用、跨店铺、未授权来源、草稿、撤销、过期、冲突、版本漂移和损坏元数据；零越权证据。真实来源和评测不足时，K1 只能记 `部分完成`，不得宣称“全领域知识已建成”。
