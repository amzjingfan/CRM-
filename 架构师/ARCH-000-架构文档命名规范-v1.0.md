# 架构文档命名规范

## 1. 适用范围

本规范适用于 `架构师/` 目录下的架构设计、技术选型、架构决策、接口约束、数据设计、风险评估和技术验收文档。

## 2. 标准命名格式

```text
{文档类型编号}-{模块编号}-{文档名称}-v{主版本}.{次版本}.md
```

示例：

```text
ARCH-001-SYS-系统总体架构设计-v1.0.md
ARCH-002-AI-AI-Agent架构设计-v1.0.md
ARCH-003-DATA-数据库与向量库设计-v1.1.md
ADR-001-SYS-采用模块化单体架构-v1.0.md
TECH-001-API-统一消息模型技术选型-v1.0.md
```

## 3. 字段规则

### 3.1 文档类型编号

| 编号 | 类型 | 用途 |
| :--- | :--- | :--- |
| `ARCH` | 架构设计 | 描述系统、模块或专题架构 |
| `ADR` | 架构决策 | 记录一个已确认的架构决策及其原因 |
| `TECH` | 技术选型 | 记录框架、中间件、数据库、模型等技术选型 |
| `API` | 接口架构 | 描述跨模块接口、协议和数据契约 |
| `DATA` | 数据架构 | 描述数据模型、数据流、存储和一致性 |
| `SEC` | 安全架构 | 描述认证、授权、审计和安全边界 |
| `PERF` | 性能架构 | 描述容量、延迟、并发和优化方案 |
| `DEP` | 部署架构 | 描述环境、容器、发布和基础设施 |
| `RISK` | 风险记录 | 描述架构风险、影响和应对措施 |
| `验收` | 技术验收 | 记录架构和实现结果的验收结论 |

### 3.2 模块编号

| 编号 | 模块 |
| :--- | :--- |
| `SYS` | 系统总体 |
| `AUTH` | 认证与权限 |
| `CHANNEL` | 平台接入 |
| `MSG` | 消息与会话 |
| `AI` | AI Agent |
| `KB` | 知识库与 RAG |
| `TOOL` | AI 业务工具 |
| `CRM` | 客服工作台 |
| `MKT` | 主动营销 |
| `DATA` | 数据看板 |
| `OPS` | 运维与部署 |
| `CROSS` | 跨模块 |

新增模块时由架构师分配编号，并同步到共享记忆文档。

### 3.3 序号

同一文档类型和模块下，从 `001` 开始递增，不重复使用已归档编号。

### 3.4 版本号

采用 `v主版本.次版本`：

- 主版本：架构方向、模块边界、核心技术选型或数据契约发生重大变化。
- 次版本：补充说明、修正错误、增加局部细节或更新验证结果。

## 4. 文档状态

文档正文必须包含状态字段：

```text
状态：草案 | 评审中 | 已确认 | 已废弃
```

已废弃文档不得删除，必须保留并在正文中指向替代文档。
