## 产品问题与目标用户

跨境电商客服需要在多店铺、多会话和复杂政策中快速回复，同时避免越权、幻觉、重复发送和敏感数据泄露。当前 MVP 面向两类用户：

- 管理员：管理店铺、TikTok 授权、团队、Agent、知识和安全策略。
- 客服坐席：在统一工作台查看会话和业务事实，获取 AI 建议，并在人工复核后发送普通文本。

MVP 的核心价值是缩短人工坐席的信息搜索与回复时间，同时保留店铺隔离、人工决策、审计和失败关闭。

## MVP 成功标准

- 坐席可以从登录、会话查看、AI 建议到人工确认发送完成一次受控闭环。
- 所有业务访问绑定服务端计算的店铺和权限范围，跨店铺访问失败关闭。
- AI 只使用脱敏允许字段、已审批知识和受控工具结果；业务事实不由模型猜测。
- 人工消息发送具备 CSRF、权限、幂等和审计边界；结果不确定时进入 `unknown` 并通过对账收敛。
- 完成 G0～G6 的真实环境证据后才可进入 G8 最终 Go/No-Go；代码存在、Mock 或确定性测试不代表生产放行。

## 核心用户流程

1. 管理员配置受控环境，为专用测试店铺完成 TikTok OAuth，并确认 Scope 与 Token 状态。
2. TikTok Webhook 或只读同步把外部会话映射到内部店铺、渠道、客户和会话。
3. 坐席在工作台选择会话，查看已授权的消息和业务事实。
4. 系统对允许字段执行 DLP，检索已审批知识，必要时调用只读工具，生成可追溯建议。
5. 坐席复核并明确确认普通文本；服务端再次执行权限、CSRF、幂等和审计检查后调用平台。
6. 已确定结果记录为成功或失败；超时等不确定结果记录为 `unknown`，由对账接口收敛，不自动重复发送。

## AI 与知识验收

- BGE-M3 向量维度固定为 1024，Dense Top-20，bge-reranker-large Top-5，Dense 接受门槛为 `0.52`。
- 知识正文、`statement_type` 或 `customer_scope` 变更时生成新版本并撤销原审批。
- 当前发布只生成 `approved_for_internal_review`，不授予公开自动回复权限。
- 完整 MVP 目标口径为意图识别准确率不低于 85%、AI 独立解决率不低于 70%、首 Token 小于 3 秒、50 并发下 P99 小于 5 秒。总 PRD 中的 95% 意图识别、500 ms 首 Token 和 500 并发属于长期容量目标，不替代当前门禁。
- 2026-10-12 最新 staging 冻结综合集真实 DeepSeek 评测使用 Prompt `v1.2.3`，得到 33/36（91.67%），超过预设 85% 数值门槛；售后与引用旧失败已过，但否定说明、英文条件政策、西语英译有 3 条逐项失败，G4 保持部分通过。评测专用 Prompt `v1.2.4` 仅为代码候选，尚未发布或真实复测，不能宣称 AI 质量已取得生产放行。

## 安全与非功能要求

- 默认保持 `AUTO_REPLY_ENABLED=false` 和 `REAL_TIKTOK_HIGH_RISK_WRITE_ENABLED=false`。
- 真实密钥、Token、客户正文、完整 Prompt 和跨店铺标识不进入日志或公开响应。
- 模型、工具、平台或协议不确定时失败关闭并转人工，不降级为无审计自动化。
- 50 客户端 DeepSeek SSE、连续 5 日 99.5% 可用性、备份恢复和上一版本回滚是发布门禁，不是文档性承诺。

## 明确不纳入当前 MVP 放行

下列能力可作为总 PRD 的后续产品路线，但不属于 TikTok 人工辅助 v0.1：

- Shopee、Amazon、WhatsApp、独立站与飞书的真实生产接入。
- 无人工确认的公开自动回复、主动营销、催付、挽回、邀评与其他高风险平台写入。
- 130+ 语种生产翻译、自动客户数据写入/合并、海关数据和企业地图获客。
- 自动下单、优惠券应用、支付和退换货决策。
- 基于 A2A 协议的分布式微服务 Agent 集群、Redis Cluster、服务发现和独立扩缩容。当前代码继续使用单仓库模块化单体与最少运行服务。

## 发布门禁与完成定义

MVP 代码基线不等于生产发布。产品完成需满足：

1. G0：真实配置、密钥轮换、DNS/TLS、备份恢复和实际回滚。
2. G1～G3：真实 TikTok 首次 OAuth、非物流只读、Webhook、人工消息和 `unknown` 对账闭环。增强物流 `202604` 独立验收，不阻止进入 G2，但在最终 G8 前仍须通过。
3. G4：真实 DeepSeek 建议质量、DLP、引用、结构化声明和转人工复测。
4. G5：50 客户端 SSE 的延迟、错误、断连、队列和资源证据。
5. G6：连续 5 日稳定运行，可用性至少 99.5%，且告警和故障恢复可验证。
6. G8：安全、业务与运维基于完整证据做出最终 Go/No-Go 决定。

当前 G0～G6 尚未全部关闭，因此 G8 保持阻塞。
