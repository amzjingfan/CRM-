# G5 手动合成内容与凭证续期入口

从 main `8a0d48a` 增加 `ContentCheck`、`ContentPrepare`、`RenewCredentials` 三个手动 staging 模式，复用 R05 的隔离 50 会话内容工具。入口核对 GitHub 受审源码、运行后端不可变摘要与 OCI revision、Rootless UID、部署数据库指纹、签名配置及仓库外私有文件；容器固定 `--workdir /opt/crm-g5-source`。内容写入和令牌续期各有不同的精确确认值，写入结果不确定时停止，不盲重试。证据只含固定状态与计数。

独立审查发现续期后第三份文件阻断只读对账，以及逗号文件名可绕过最初的文件集合比较。最终实现对真实目录名使用 JSON 数组逐项核对；续期后只读检查还验签第三份文件的 50 个用户与会话映射，重复续期仍拒绝。新内容模式允许 GitHub 可验证的历史受审提交，但必须与运行镜像 revision 完全一致，以免证据合并使 main 前进后阻断现场对账；新部署仍要求当时当前 main。

本轮只交付源码、测试和操作说明，没有调度 GitHub Actions、发布镜像、修改 staging 数据或凭证、调用 DeepSeek、发 TikTok 消息或部署 production。现场内容准备、凭证续期、单会话安全输出及 50 并发仍未验收。
