# R82 G5 负载分段诊断候选

R80 的 50 个隔离账号均取得安全 SSE `delta`，但首输出与总耗时 P99 分别为 7287.4/7293.9 ms，未满足严格的 `<3000/<5000 ms`。R81 空载只读探针表明 BGE 和 FAQ 查询在空载较快；它不能解释 50 并发长尾。

在现有店铺隔离检索服务中分别测量查询向量等待与混合检索端口的墙钟耗时。后者包含两路 SQL 与结果融合，不能称为 PostgreSQL 纯执行时间。仅成功 Agent 运行把两项非负整数加入原有 `output_summary.node_timings_ms` 白名单；没有检索的路径不写该项，失败终态不伪装成功。原店铺 ID、查询脱敏、知识审批、排序、安全复核、DLP、发送开关和门槛均未改变。

既有手动资源采样器增加本地 BGE 服务及 PostgreSQL 两个固定容器的 CPU、内存与进程峰值。它仍只接受固定容器名、固定输出路径和实际运行的后端不可变摘要；缺容器或解析异常失败关闭，不输出原始 Docker 响应、正文、凭证或连接地址。运维与 AI 当前文档已同步。

本轮只交付候选源码和本地验证。手动镜像发布、可恢复 staging 负载窗口、严格 P99、断连及 G3 恢复仍需现场证据；不据候选代码关闭 G5 或放行 production。
