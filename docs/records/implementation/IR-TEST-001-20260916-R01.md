# 实施目标与范围

把后端、前端与 PostgreSQL 集成测试、普通 AI eval 数据集和版本化结果集中到唯一 `src/tests/` 根，并同步 pytest、Node、ESLint、CI、脚本和当前事实文档。迁移保持产品行为、测试断言、数据内容、模型阈值、正式 TR、冻结发布证据与生产门禁结论不变。

# 实际变更及原因

- 将 40 个后端测试按 `agent`、`auth_security`、`domain`、`platform`、`runtime_infrastructure` 分类到 `src/tests/backend/`，建立 linked-worktree 安全的共享路径根。
- 将 6 个 PostgreSQL/pgvector 集成模块及其 README 归入 `src/tests/integration/postgres/`，由同一后端 pytest 入口发现。
- 将 5 个 eval 数据/manifest 与 18 个版本化结果迁入 `src/tests/ai/`，修复评测脚本和测试的 CWD 无关路径，保留逐文件 Git blob 身份。
- 将 5 个前端契约文件与 40 个 Node 测试迁入 `src/tests/frontend/contract/`，增加共享 URL 路径 helper，并使 ESLint 同时覆盖产品源码和兄弟测试树。
- 将 `TEST_LAYOUT` 固定为 `centralized`，更新 CI、治理、开发、测试策略、入口文档、忽略规则和布局回归契约；`src/tests/.artifacts/` 是唯一项目内临时测试输出根。
- 候选提交 `4cd66643540d7e70acaeae2229a0f10620f7b6ae` 把 `TEST-001` 置于验证阶段并固定完整交付 subject；后续证据尾只包含治理允许的记录、索引、任务、状态和计划 bookkeeping。

# 关键决定与偏差

- 后端依赖与应用导入仍以 `src/backend/` 为根，前端依赖仍以 `src/frontend/` 为根；只集中测试资产，不创建共享平台或新运行服务。
- 后端和前端生产镜像继续使用模块级 build context，因此 `src/tests/` 与 eval 数据不会进入运行镜像。
- 历史 `docs/superpowers/`、`docs/history/`、冻结 `release/baselines/` 和既有正式 TR 保留形成时的旧路径事实；活动入口和机器配置使用新路径。
- 独立审查仅给出一个非阻塞 Minor：未来可在 `src/tests/README.md` 补充 sibling-path 聚焦 pytest 需要 `-c pyproject.toml`。为保持已完整验证的候选不变，本任务不实施该建议。
