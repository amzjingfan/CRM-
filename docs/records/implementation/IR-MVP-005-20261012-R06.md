# 实施目标与范围

用户批准仅在现有 G4 评测器增加低敏失败定位：结构化声明不匹配字段名、冻结禁用词序号、引号与附近禁止用语提示。使用合成输出测试，不调用 DeepSeek，不发布镜像。

# 实际变更及原因

在 `real_model_evaluation.py` 中把原声明匹配判断抽成等价的字段差异计算，保留原 `BUSINESS_CLAIMS_MISMATCH` 与 `FORBIDDEN_CONTENT_PRESENT` 判分；失败样本报告新增 `diagnostics`，只允许固定枚举字段、0～19 的禁用词序号和两个布尔提示。一个禁用词出现多次时，两个提示均要求每处都满足；报告不保存模型正文、禁用词原文或客户正文。工作流白名单同时约束嵌套字段，避免把诊断扩展成任意文本出口。新增冻结样本和假 Provider 的合成测试。

# 关键决定与偏差

引号和附近禁止用语仅是排查提示，不作为安全豁免；原禁用词规则仍判失败。旧 `live` 报告只有哈希与失败码，无法从旧证据回填三条模型草稿的字段或语境。不得据此签署 G4。

# 数据、配置、接口、迁移或 Prompt 影响

只扩展离线评测报告和该工作流的低敏验证契约；冻结集、85% 门槛、Prompt、Provider、运行服务、数据库、TikTok 开关和 production 均未改变。后续真实运行需要先发布新 backend 镜像并另行取得调用授权。

# 验证交接

R06 TR 记录候选 subject 的完整后端回归、类型与静态检查、YAML/PowerShell 解析及合成输出边界测试。R06 RR 审查信息流、判分等价性和发布边界。

# 限制、风险与回滚

附近禁止用语提示按有限词表和窗口计算，不能证明模型是否推荐了禁用表述；引号也不能自动证明安全。部署前的真实效果未知。若代码/工作流检查失败，回滚本 subject，不改变已有 `live` 报告或 staging 服务。
