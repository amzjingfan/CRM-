# G5 断线后的 AgentRun 审计终态修复

R101 的隔离 SSE 断连已释放 Redis 租约且留下服务端提前关闭事件，但同一运行记录仍为 `running`。工作流的首次 `start` 提交位于取消异常处理之前；传输断开可能落在该提交的边界，依赖请求会话写失败终态并不充分。

修复在 SSE 清理中先等待工作流取消，再使用独立数据库会话按当前用户授权店铺、会话、trace、请求时间窗和 `running` 状态选至多两条记录。仅唯一候选可用带状态比较条件的原子更新写 `failed/AGENT_CANCELLED`，已成功/失败记录不改写；多条匹配拒写。审计写入失败仍释放租约并记录固定错误类型，不输出身份、请求正文或凭证。正常安全草稿、DLP、5 秒门槛和 TikTok 发送模式不变。

对应代码、测试和当前契约文档见 subject `3b643125909b5aa6cbff0f41672cac680a707925`。本记录只描述源码修复；隔离 staging 的数据库终态尚待新镜像现场复核。
