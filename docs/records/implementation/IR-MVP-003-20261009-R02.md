# 本轮实施

以 PR #101 合入的 G2 加固代码为基线，增加 staging Runner 上的只读订阅诊断。工作流仅允许从 main 运行，核对调用者确认词、已运行后端的精确不可变摘要和 GitHub 返回脚本的 Git blob SHA，再把脚本通过 stdin 送入已运行的 backend 容器。脚本要求恰好一个已连接 TikTok 渠道，只调用现有 `GET /event/202309/webhooks` 适配器，输出主题集合、订阅数量和预期回调地址匹配数量，不输出 URL、店铺标识、Token 或平台异常。工作流没有订阅写入。

# 现场部署与边界

用户精确授权的单个后端私有镜像已发布；六角色不可变镜像预取、staging G2 模式 validate/deploy 均成功。部署门禁核对迁移头、三个公网健康接口、固定出口与模式；独立公网 ready/渠道页 200、无签名 Webhook GET 405。详见[低敏部署证据](../../../release/evidence/staging/crm-staging-g2-backend-rollout-20261009.json)。该证据不证明 Partner Center 当前订阅或真实事件。PR #102 尚未合入和运行，G2 保持 `DOING`。

# 限制与恢复

仅在 staging 的 backend/worker 开启真实只读及 Webhook；消息写入、高风险写入和自动回复仍关闭，production 未变。默认 staging deploy 可移除 G2 叠加层；本轮尚未实际切回验证。外部订阅写入仍须单独核准精确主题和地址。
