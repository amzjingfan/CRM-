# 目标与范围

仅关闭 G0 的 staging 隔离恢复子项：从活动 PostgreSQL/MinIO 制作受限备份，在独立数据库与不发布主机端口的 MinIO 容器/卷中验证恢复。用户批准隔离方案及仅收紧旧服务器 SSH 私钥 ACL。活动数据库和对象桶从未作为恢复目标；production 不变。

# 实际实施

原始 SSH 私钥仅调整 ACL，移除继承的 `Authenticated Users` 和 `Users` 访问，保留当前管理员、Administrators 和 SYSTEM；密钥内容未复制或输出。业务机 `/home/crmdeploy/backups/mvp008-20260929T011100Z/` 为 `crmdeploy:crmdeploy:0700`，PostgreSQL 自定义格式备份为 `0600`。备份可由 `pg_restore --list` 读取；MinIO `/data` 被复制到同一受限目录。

从该备份恢复到独立数据库，迁移头、全部 29 张表的逐表行数摘要和总行数与源一致。当前真实 MinIO 桶无对象，因此先验证其空桶在隔离实例中可读取，再仅在隔离实例写入固定测试对象，经第二次隔离备份、独立卷恢复及 API 读取证明对象字节和 SHA-256 一致。临时数据库、两个容器、两个卷和专用网络经精确名称/挂载核验后移除；受限备份保留作恢复点。

# 决定、偏差与边界

仓库原有 `restore-postgres.ps1` 带 `--clean`，`restore-minio.ps1` 会覆盖同名对象；两者未被用于活动 staging 目标。实际使用 PostgreSQL 原生命令与 Rootless Docker 在隔离目标完成恢复。活动后端/前端镜像源为 `c99df142...`，检索服务仍为旧摘要；没有更换镜像、迁移、环境文件、应用配置或真实平台开关。

本任务不等于 `MVP-008` 或 G0 完成：上一版三镜像的受审兼容集合缺失，当前主机只缓存一份检索镜像，现有回滚脚本要求候选和上一版三类摘要逐一不同。没有执行实际镜像回滚，也没有将历史 `f7c0f9f9` 生产域名镜像当作兼容目标。
