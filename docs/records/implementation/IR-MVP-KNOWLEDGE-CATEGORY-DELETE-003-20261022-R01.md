# 实施目标与范围

按用户补充要求，让当前店铺知识库侧栏的自定义分类可删除。v4 HTML 原型只有新增交互，因此删除是本次增补；Agent 管理页面保持原样。

# 实际变更及原因

- 自定义分类行增加独立的删除按钮和包含分类名的可访问名称；预置分类没有删除入口，管理弹窗也只对自定义分类提供删除。
- 删除前显示分类名称与空分类约束，取消不发请求；确认后调用现有删除接口并禁用重复删除与切店操作。
- 服务端确认成功后移除本页分类、清除已删分类的当前选择，并基于最新页面状态重新加载，避免删除期间切换分类导致旧请求覆盖列表或保留失效 URL。
- 后端仍决定空分类和店铺权限；409 等失败保留分类并显示错误。本页演示文件若归属该分类，则提示先刷新清空，避免删除后静默改归属。
- 窄侧栏为分类名称、计数和 44px 删除按钮保留空间；浏览器回归覆盖取消、409、成功、延迟响应切换分类、刷新和预置分类保护。

# 关键决定与偏差

仅当前店铺真实自定义分类允许删除；原型五个业务分类作为预置导航保护。沿用既有 API 和服务端空分类校验，不增加“强制删除”或级联删除。刷新清除页面演示文件，不会触及服务端知识。

# 数据、配置、接口、迁移或 Prompt 影响

无新公共接口、数据结构、迁移、权限、模型或 Prompt。调用现有带 CSRF 与幂等键的分类删除请求；服务端店铺隔离、非空检查及审计保持原有实现。

# 验证交接

见同任务 TR R01。两项独立只读审计核对 v4 原型与现有接口，一项只读 UI 审查指出异步切换竞态与演示文件、可访问名称问题，均已修复并复审通过。

# 限制、风险与回滚

合成浏览器未代替真实登录态或 staging 验收；未运行后端测试，因为后端未改。删除期间若用户切到其他分类的后续页，成功后会回到第 1 页。回滚撤销本 subject 的前端与产品说明变更；已成功删除的真实空分类需由用户重新创建。
