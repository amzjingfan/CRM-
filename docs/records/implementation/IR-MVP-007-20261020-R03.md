# Staging 现场缓解

从 PR #456 已合并源码安装反向 SSH unit 和进程参数校验器，仅重建 TikTok 出口 helper；两条 SSH 的保活参数由 `30/3` 调为 `10/2`。保留原账号、主机密钥校验、固定网关、回环入口和出口密钥只读挂载。网关仅将 `/healthz` 从关闭访问日志改为现有低敏 JSON 日志，并通过配置测试后 reload。原 G6 采集服务已停止，原件保持冻结；没有启动新观察窗口、发布镜像或操作 production。

网关现场 vhost 比受审仓库文件多一个 `/activate/` location。本次先备份现场原文件，精确替换 `/healthz` 日志行，保留该现场块；未来如整体部署仓库 vhost，必须先审查并调和这项漂移。私有备份与部署副本路径、SHA、运行身份及容器范围见[低敏机器证据](../../../release/evidence/staging/crm-staging-g6-ssh-mitigation-live-20261020.json)。

# 限制与恢复

旧 unit 和 vhost 的私有备份已保留；出口 Compose 使用旧受审基础文件叠加合并后新 overlay，旧基础文件未覆盖。若较短保活导致异常重连，恢复旧 unit/overlay 与现场 vhost，再核对固定出口和三公网健康。公网 TLS 间歇超时仍未解决；本实施不构成 G6 可用性通过或后续通过保证。
