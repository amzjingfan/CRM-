# 实施目标与范围

把 R03 已合入的人工普通文本发送能力部署至 staging，仅对一个店铺内受控 TikTok 买家会话启用真实写入，并完成一次买家与工作台的双向现场验证。production 和自动发送不在范围内。

# 实际变更及原因

- R03 源码由 PR #301 squash 合入 main `70d8968a0d5245f5578f703ca734990d547ab564`。从该提交手动构建并推送不可变后端、前端私有镜像，预取后运行 staging validate/deploy 门禁；迁移、三健康和运行模式通过。
- 只向受控数字平台会话 ID 注入写入范围；只读核对目标 `send_mode=real`，其余 179 个同店铺会话均为 `disabled`。Webhook 读取与工作台翻译继续启用，G5 SSE 关闭。
- 用户精确授权后，从项目工作台仅发送一次指定普通文本。工具持久化为 `sent/real`，官方只读会话历史返回同一平台消息 ID。受控买家从手机回复后，工作台自动显示回复，Webhook 验签、渠道绑定和处理成功。
- 本轮仅增加低敏现场证据、IR/TR/RR 和当前任务/门禁事实；不修改源码、接口、数据库、Prompt 或生产配置。

# 关键决定与偏差

浏览器初次打开的是旧前端页面，刷新后才显示真实发送能力。一次发送按钮调用在浏览器自动化层超时，但页面随后显示唯一已发送消息；只读数据库、工具审计和 TikTok 官方只读接口均确认仅一次真实发送，因此没有重发。Seller Center 的本次出站画面未独立观察，平台读取、买家手机回复和 CRM 回流构成现场双向闭环。

# 数据、配置、接口、迁移或 Prompt 影响

本轮没有新的结构或安全边界变化。staging 单会话开关保持启用，其他会话仍关闭；部署门禁只接受受审镜像摘要和精确范围。GitHub Actions 没有参与本次手动发布。

# 验证交接、限制与恢复

见 [R04 TR](../../reports/tests/TR-MVP-004-20261017-R04.md) 和[低敏证据](../../../release/evidence/staging/crm-staging-g3-bidirectional-20261017.json)。受控会话可在工作台与买家互发普通文本；其他会话不在真实写入范围。若后续出现 `processing/unknown`，停止新发送并依据平台事实人工对账，不自动重试。恢复路径为同一受审镜像切回 Webhook 只读加翻译模式，运行写开关置 false 后复核健康。G2 的 Webhook 重试、乱序和持续恢复仍单独验收；production 未发布。
