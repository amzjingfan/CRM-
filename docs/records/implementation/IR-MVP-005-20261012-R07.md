# 实施目标与范围

用户批准在严格禁用词判分和冻结数据不变的条件下，修复 G4 售后结构化声明遗漏与引用禁用短语复述。镜像、staging 部署和再次付费模型调用分别保留独立授权边界。

# 实际变更及原因

先在冻结独立集的售后与引用样本上为实际评测请求添加契约测试，并观察其因缺少新规则而失败。随后把评测专用系统指令升至 `real-model-eval-v1.2.3`：有证据的售后政策人工复核草稿仍输出一条 `refund_policy` 声明；证据不足则失败关闭转人工；引用禁止承诺时概述其风险，不在正文复述禁用原句。测试转绿，代码提交为本记录 `final_sha`。

此前获批的诊断后端从 main `84aa53a9498ae20b4bf10939fde467c46ec81e63` 单独发布并部署 staging；第二次获批的真实 G4 评测为 34/36，留有售后声明数量不符和引用禁用词两条失败。本次把这些机器证据的低敏副本及来源摘要长期保存在 `release/evidence/`。G2 同日只读观察仍为零事件。

# 关键决定与偏差

引用样本的引号与禁止措辞只是诊断提示，不作为评分豁免；不降低 85% 门槛、不改禁用词规则、不改冻结集。没有把 Prompt 的本机契约测试解释为真实模型效果。当前 staging 仍运行 `v1.2.2`；本次代码提交与现场评测的运行提交必须分开看。

# 数据、配置、接口、迁移或 Prompt 影响

仅改变 G4 合成评测专用 Prompt 文本及版本；公共 API、数据库结构、模型、数据集、真实平台写入、公开自动回复和 production 配置不变。旧评测报告保留原版本，不回填或覆盖。

# 验证交接

R07 TR 记录红绿测试、完整后端回归、Ruff、mypy，以及已部署诊断后端的发布、预取、预检、部署、G4 prepare/live 现场证据。R07 RR 审查严格判分、失败关闭和授权边界。后续真实复测须先从合入后的 main 精确发布新后端并部署 staging，再单独授权模型请求。

# 限制、风险与回滚

Prompt 是对模型的指令，确定性测试不能保证其遵循，G4 仍为部分通过。若新 Prompt 导致安全、引用或结构化声明回归，应停止真实复测，使用共享历史的 `git revert` 回滚候选代码；staging 继续使用已验证的旧镜像直到另行受控切换。
