# R64 手动 GHCR 登录与 G5 单会话窗口

用户所问的 GHCR 401 发生在**本机 Docker Desktop**，不是 staging Rootless Docker。用现有 GitHub 凭据向本机 Docker 登录 GHCR 后，按不可变摘要远端 inspect 和拉回均成功；没有把 Token 写入命令参数、仓库或证据。staging 主机通过现有 SSH 入口访问，应用操作均由 UID 1004 的 `crmdeploy` 和 Rootless socket 执行，没有启动本机虚拟机或 GitHub Actions。

从 main `665e05f6b5508d4e615feb73d8483532c822f49c` 手动发布私有 linux/amd64 后端 `ghcr.io/cp11-gh/crm-backend@sha256:0c64af0e2e0dd590995561e3483ca43c5e847c35b2dc5617fcc960cfce40b5dc`。远端 OCI index、amd64 子 manifest、revision、按摘要拉回和 12 层压缩大小均核对，见[镜像证据](../../../release/evidence/staging/crm-staging-g5-r64-manual-backend-image-20261018.json)。

从 staging 的同一干净受审提交执行 `CheckOnly`、六摘要预取、G5 validate/deploy；候选仅临时替换 backend，前端和检索镜像不变。原隔离夹具只读核对为 FAQ v3、`knowledge_ready=true`、50/50 会话。第十代 50 枚短期 CRM 测试令牌独占新建，原九代文件保留；再核对 50 个不同身份及各自会话，未新增账号或修改业务数据库。唯一合成 SSE 已产生安全 `delta`，但首个 `delta` 7829.7 ms、总耗时 7837.6 ms，超过 3000/5000 ms 严格门槛；因此没有启动 50 并发。只读 Agent 摘要为 `human_review`、`safety_reasons=none`、`decision_reason=none`，不能把本次延迟归因于 Schema 或安全拒绝。

随后从已审核的历史恢复 checkout 与窗口前私有快照执行 `RestoreManualSend`，恢复原后端 `sha256:04c4f64d…bd1dcc`、G3 限定会话人工发送、Webhook 只读和工作台翻译；LLM/SSE 关闭、限流 10，迁移头、三个健康端点与固定出口均经门禁核对。真实凭证、私有恢复快照、会话 ID、模型正文和请求 ID 保留在仓库外。测试及剩余风险见 [R64 TR](../../reports/tests/TR-MVP-006-20261018-R64.md) 与 [RR](../../reports/reviews/RR-MVP-006-20261018-R64.md)；G5 仍 `DOING`，production No-Go。
