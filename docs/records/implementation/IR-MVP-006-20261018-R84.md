# R84 FAQ 检索事务在模型等待前结束

R83 两轮现场的 50/50 安全输出通过，但首安全 `delta` P99 为 6579.5/4878.8 ms，严格 3000 ms 门槛失败。低敏同窗采样显示 PostgreSQL 最多 45 条 `idle in transaction`；检索墙钟包含连接等待、SQL 和融合，尚不能把所有长尾归于单一操作。代码检查确认运行记录的 `start` 已提交，而 FAQ 检索沿用请求会话，检索后可能继续等待模型重排与独立安全复核。

运行 Agent 工厂现在向现有检索器注入同一数据库引擎的会话工厂。每次 FAQ 混合检索仍在可信 `store_id`、发布/审批、ready 和当前版本条件下查询，但使用独立短时会话；检索返回、异常或取消时，该会话立即关闭，之后才进行重排与模型复核。请求会话继续负责权限、工具和 Agent 运行记录；未改 API、迁移、Prompt、模型、评分、DLP、SSE 事件、发送开关或阈值。非运行的显式测试/评测构造仍可传入已有会话。

本轮只交付本地候选源码。不能由连接关闭的确定性测试宣称 G5 性能通过；需手动发布匹配 main 的私有后端镜像，在可恢复 staging 窗口重复 50 个不同隔离账号的单会话、50 并发、数据库状态/资源、断连和原 G3 恢复验收。未使用 GitHub Actions。
