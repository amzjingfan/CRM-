# 实施目标与范围

消除管理端旧 HTML 被跨版本缓存，导致 staging 已部署 UI 修复却仍执行旧营销页 JS 的缺陷。范围仅为前端页面缓存策略、回归测试和部署说明；不改变营销逻辑、真实 OAuth、模型、数据库、凭据或 production。

# 实际变更及原因

根布局声明 `dynamic = "force-dynamic"`，让所有管理端页面按请求输出当前构建的 HTML。新增针对本机生产模式服务的回归测试：`/login`、`/marketing`、`/settings/stores` 的 HTML 必须 `no-store`，而 `/_next/static/chunks/` 的带指纹 JS 仍为 `immutable`。部署说明补充双重检查。修复前同一测试在 `/login` 观测到 `s-maxage=31536000`，修复后通过。

# 关键决定与偏差

Next.js 16.3.4 的既有构建曾将所有页面静态生成；新构建显示全部页面按需动态渲染。选择根布局统一约束，避免只修营销页而其他页面继续跨版本缓存。保持静态资源缓存不变。此变更增加 HTML 请求的服务端渲染负载，需要在 staging 观察资源和响应延迟。

# 数据、配置、接口、迁移或 Prompt 影响

无数据迁移、公共 API、权限、密钥、模型或生产配置变更。回滚为切回已验证的上一前端镜像；浏览器中可能仍有旧 HTML，回滚后也需校验实际缓存头和页面构建资源。

# 验证交接与限制

本机生产构建、缓存头、静态资源缓存、隔离浏览器交互和前端检查见 TR。代码审查见 RR。合并不等于 staging 部署；现场镜像、恢复点、健康与版本一致性须另行验证。此前旧检索镜像例外仅限 2026-09-23 那次部署，不能自动沿用。
