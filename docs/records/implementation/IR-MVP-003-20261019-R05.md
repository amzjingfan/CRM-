# 实施目标与范围

为 G2 官方重投与乱序现场验收准备受控 staging 探针。用户已确认短时单会话、一次 503、低敏审计和恢复设计；受控买家手机账号稍后可用，本轮不启动现场故障窗口。

# 实际变更及原因

- 真实签名通过且绑定至精确内部店铺后，只有指定数字会话中的可见 `NEW_MESSAGE` 买家通知会进入探针。Redis `NX` 原子标记保证同一运行窗口只触发一次 503；支持落库前和落库后两个模式，重投继续走原有通知 ID 与正文摘要幂等校验。
- 增加 `forced_503`、`redelivered` 固定审计结果，仅保存正文 SHA-256 和模式。没有消息正文、平台 ID、令牌或原始异常。
- staging 设置要求完整目标、真实 Webhook 模式、带时区且不超过 30 分钟的绝对失效时间；production 拒绝。手动门禁仅向 backend 叠加配置，核对合并配置、运行配置、原六摘要恢复快照与证据脱敏。
- 接口和手动部署文档同步短窗口及恢复要求。没有迁移、生产配置或公开消息发送变化。

# 关键决定与偏差

该探针只制造一次可观测失败，不能单靠 503/200 数量判定官方重投。现场必须核对同一签名正文、平台来源、接收先后、事件/消息幂等、审计和原 G3 模式恢复。探针过期停止故障注入，仍须手动恢复运行配置。

# 验证交接与限制

确定性回归、静态检查及风险审查见 R06 TR/R05 RR。未发布镜像、未部署 staging、未发送买家测试消息；G2 保持 `DOING`。后续受控买家就绪后使用精确快照启动短窗口，并在结束后核对原摘要、健康和固定出口。
