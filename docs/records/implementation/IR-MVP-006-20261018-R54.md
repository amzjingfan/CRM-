# R54 FAQ 草稿结构与低敏诊断

[R53 单会话](../../reports/tests/TR-MVP-006-20261017-R53.md)在 `faq_draft/invalid_schema` 处记录 `business_claims:model_type` 和 `unknown:missing`。运行模型正文没有保存，不能断言它实际返回的值或缺失字段。代码核对发现 FAQ JSON 模式的系统 Prompt 没列出 `FaqAnswerModelOutput` 的必需顶层字段，也没说明 `business_claims` 是含 `complete` 和 `claims` 的对象。

按已确认的有界设计，在原 FAQ 系统 Prompt 明列六个顶层字段、语言/置信度/引用的形状和声明清单对象；无业务命题时 `claims=[]`，有业务命题时不得省略声明。Prompt 从 `faq-answer-v1.6.0` 升为 `v1.6.1`，注册表摘要同步更新。只在固定 `LLMOutputSchemaPath` 中增加 FAQ 的五个必需顶层字段，以便后续 `invalid_schema` 低敏诊断区分缺失字段；不记录字段值或模型正文。

保持原严格 Pydantic Schema、DLP、引用校验、评分、模型调用上限和 TikTok 发送开关。没有修改数据库、公共接口、冻结评测集或 staging 配置。本轮仅提交源码、确定性测试和当前文档；镜像发布、部署及新的付费单会话各自独立处理。验证与残余风险见 [R54 TR](../../reports/tests/TR-MVP-006-20261018-R54.md)。
