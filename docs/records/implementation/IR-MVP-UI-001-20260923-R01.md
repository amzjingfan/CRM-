# 实施目标与范围

修复管理端截图暴露的空店铺、无反馈和筛选状态问题，并按用户授权在本机隔离浏览器中复验。该候选只修改前端交互、前端测试和对应文档；不触碰真实 TikTok OAuth、密钥、后端接口、staging 运行服务或 production。

# 实际变更及原因

- 知识库、智能营销在用户无授权店铺或 URL 携带过期/未授权 `store_id` 时终止加载，展示创建店铺入口并禁用依赖店铺的创建控件。
- 店铺与 Agent 编码表单的浏览器正则改为兼容 Chrome `v` 标志及既有服务端允许的连字符；店铺、渠道、Agent 的失败提示移至可见页面区域。知识归档失败不再产生未处理 Promise。
- 渠道、Agent、团队在无店铺时给出前置说明；配置加载失败不误报为无店铺。团队仍允许系统级 admin 无店铺创建，坐席/主管不可越过店铺前置条件。
- 会话筛选后选中项必须仍在当前列表中；旧列表响应不能覆盖最新筛选。切换 Agent 后，旧日志请求的成功或失败都不能覆盖当前 Agent 日志；请求失败显示错误而不是空数据。
- 增加 `playwright-core` 的本机 Chrome 隔离测试入口与 20 个合成数据浏览器回归用例，测试目标限定 localhost。

# 关键决定与偏差

保留既有 TikTok 服务端 OAuth、安全和写入开关，不尝试在浏览器测试中连接真实店铺。浏览器回归不是“所有按钮在真实 staging/平台均可用”的证明。独立审查发现的三个竞态/授权 URL 边界已补失败用例后修复；两个提示/断言质量建议也已处理。

# 数据、配置、接口、迁移或 Prompt 影响

无数据库迁移、公共 API、权限模型、生产配置、Prompt 或凭据变化。`playwright-core@1.62.1` 只作为开发依赖；不下载或提交浏览器二进制。回滚可撤销候选源码提交，数据库和运行数据不需要恢复；本轮未执行部署。
