# 实施目标与范围

把应用、测试、运维脚本、部署资产、Dockerfile、Compose 与本地环境示例迁入单一 `src/` 工程根，同时保留仓库根的 GitHub/Codex 元数据、当前文档与冻结发布证据。任务不改变产品范围、公共 API、数据结构、迁移顺序、权限、安全开关、Prompt、模型协议或生产门禁结论。

# 实际变更及原因

- 将 `backend/`、`frontend/`、`tests/`、`scripts/`、`deploy/`、四个 Dockerfile、八个 Compose 文件和 `.env.example` 迁入设计规定的 `src/` 子目录。
- 按用户明确决定保留 `deploy/cloudflared/config.example.yml` 的删除，不在目标目录恢复。
- 建立 `SOURCE_ROOT` 与 `REPOSITORY_ROOT` 路径契约，修复普通 checkout 与 linked worktree 中五个固定 `parents[n]` 缺陷。
- 新增 `src/scripts/start-local.ps1`，同步 Compose、Docker、CI、CODEOWNERS、活动文档和运维脚本路径。
- 显式固定 Compose 项目名 `crm`；开发镜像使用 `BACKEND_DEV_IMAGE`，避免生产摘要变量污染本地构建标签。
- 为全新 MinIO 卷增加幂等桶初始化，为 PostgreSQL 首次初始化增加 90 秒健康检查宽限期，使 `/v1/health/ready` 在全新卷启动后可达。
- 备份/恢复脚本默认绑定 `src/compose/docker-compose.yml`，并保留 `-ComposeFile`、`-ProjectName`、`COMPOSE_FILE` 与 `COMPOSE_PROJECT_NAME` 覆盖能力。
- 修正模型权重忽略规则和活动证据路径，防止大文件误提交及已删除角色目录继续成为事实入口。

# 关键决定与偏差

- 沿用单仓库模块化单体，没有增加微服务、共享平台或新运行依赖。
- 实际启动暴露的 MinIO 空桶和 PostgreSQL 首次初始化时序属于“全新环境可启动”验收缺陷，因此在 Compose 层修复；没有改变业务健康检查逻辑。
- 独立评审发现裸 Compose 调用可能向上误读旧根文件，已在最终候选前修复并复核关闭。
- 历史规格与冻结 `release/` 事实保持原样；只更新当前活动文档和机器清单。

# 数据、配置、接口、迁移或 Prompt 影响

- 数据库 schema、迁移、公共 API、Prompt、模型和安全开关均无变化。
- 本地环境文件规范路径变为 `src/config/.env`；生产仍要求仓库外环境文件与密钥注入。
- Compose 服务名、`crm` 项目名、网络和 `crm_*` 命名卷契约保持不变。
- 新增一次性 `minio-init` 服务；生产覆盖继续使用受控 MinIO 镜像与必填凭据。
