# 实施目标与范围

将 `staging.overselfx.com` 改为入口与业务分离的 staging：`38.55.145.52` 只运行宝塔 Nginx、公信 TLS 和回环反向监听，`192.168.110.210` 只用 UID 1004 的 Rootless Docker 运行完整 CRM。通路固定为 `443 → 127.0.0.1:18080 → SSH 反向隧道 → 127.0.0.1:18081 → proxy:80`，不修改 GitLab 已占用的 `10080/10443`。

本草稿只记录已冻结候选与本地证据。GitHub 合并、不可变镜像、两台服务器变更、宝塔证书和公网验收标记为 `PENDING_LIVE_EXECUTION`。

# 实际变更及原因

- 新增 Rootless staging overlay，proxy 只发布 `127.0.0.1:18081:80`，并只读挂载无 TLS 私钥的 `nginx-tunnel.conf`。
- 两个 staging 门禁同时强制单一回环端口、单一内层 Nginx 挂载、不可变镜像和全部高风险能力关闭。
- 实际 Compose 验证发现 production 文件会在 rootless override 前展开 `TLS_CERT_DIR`；门禁现在只在子进程内注入不会被最终配置挂载的哨兵值，且在 `finally` 恢复原环境。
- 新增公网隧道账号、旧服务器用户级隧道、HTTP `503` 持有 vhost、正式 HTTPS vhost 和双端动态验证脚本。
- 独立审查发现已活动旧隧道不会被 `enable --now` 替换；安装器改为显式 restart，并从运行中 `/proc/<pid>/cmdline` 核对 `18080 → 18081`。
- 内层 Nginx 新增 Webhook 专用路由并关闭原生错误日志，避免公网层脱敏后又在业务层记录 query/验签材料。
- `deploy` 现在先等待 PostgreSQL/Redis/MinIO，用已审阅 backend RepoDigest 执行 `alembic upgrade head` 和 `alembic current --check-heads`，通过后才启动应用与入口。
- 从活动树移除历史同机 `80/443 → 10080/10443` 脚本与 unit，避免形成第二条可执行 staging 入口；历史仍可由 Git 恢复。
- 同步架构、部署、发布门禁、项目状态和唯一活动运行手册，任务保持 `VERIFYING`。

# 关键决定与偏差

- 公网层只允许隧道账号在 `127.0.0.1:18080` 创建反向监听；账号锁定、无 shell，SSH 只允许 Ed25519 公钥和指定 remote-forward。
- 公网与内层 Nginx 都使用 `$uri` 而不是完整 query 记录 access log；OAuth callback 和 Webhook 不记录原生代理错误。
- 入口、隧道、证书或应用未就绪时只返回明确 `502/503`，不允许回退到 GitLab 或其他 vhost。
- production 只保留 `www.overselfx.com`、HTTPS、不可变镜像和安全开关等公共契约，不自动继承 staging 的双服务器拓扑。

# 数据、配置、接口、迁移或 Prompt 影响

- 变更 staging 编排、Nginx、SSH 授权和运行证据契约；无公共 API、数据模型、迁移、Prompt 或模型文件变化。
- staging 环境文件不再需要 `TLS_CERT_DIR`；TLS 私钥只保存在新服务器宝塔管理目录。
- backend、frontend 和 retrieval-model-service 必须来自合并后 main SHA 发布的 `repository@sha256:`；服务器禁止本地 build 和浮动 tag。
