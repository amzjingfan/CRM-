# 实施目标与范围

按用户 2026-09-17 的明确决定，将 staging 公网域名固定为 `staging.overselfx.com`，将 production 公网域名固定为 `www.overselfx.com`。同步 OAuth 回调、Webhook 示例、CORS、公开 API、TLS 目录、GitHub Staging 精确目标守卫、测试夹具和部署文档；不修改真实能力开关，不执行外部 DNS、TLS、Partner Center、部署或远端 Git 操作。

# 实际变更及原因

- `Settings` 的 TikTok staging/production OAuth 固定回调常量改为 overselfx 域名，继续对 scheme、host、path、query 和 fragment 失败关闭。
- GitHub Staging 工作流的 `CRM_STAGING_BASE_URL` 精确守卫改为 `https://staging.overselfx.com`。
- `.env.example`、production/Rootless Staging 运行手册、当前部署事实和根说明同步两个新域名。
- 更新真实配置、平台适配器、Webhook 地址和生产门禁测试；测试先在旧实现上出现预期失败，再由最小实现修复。
- 为消除同一安全契约的竞争描述，同步 2026-09-09 staging 设计/计划中的 production 地址。

# 关键决定与偏差

- staging 与 production 继续使用不同精确主机，不放宽为任意 overselfx 子域。
- `integration` 延续现有契约，使用 production 固定 OAuth 回调。
- 没有修改 `AUTO_REPLY_ENABLED=false`、`REAL_TIKTOK_HIGH_RISK_WRITE_ENABLED=false` 或其他真实能力默认关闭项。
- 没有建立兼容旧域名回调的双域名窗口；部署前必须先完成外部配置切换。

# 数据、配置、接口、迁移或 Prompt 影响

- 公共配置契约变化：`PUBLIC_BASE_URL`、`PUBLIC_API_BASE_URL`、`CORS_ORIGINS`、`TIKTOK_OAUTH_REDIRECT_URI`、`CRM_STAGING_BASE_URL` 和 TLS 目录示例。
- TikTok Partner Center 的 production OAuth 回调和 Webhook 地址需要改为 `www.overselfx.com`；staging OAuth/Webhook 需要使用 `staging.overselfx.com`。
- 无数据库迁移、数据结构、Prompt、模型、权限或店铺隔离变化。
