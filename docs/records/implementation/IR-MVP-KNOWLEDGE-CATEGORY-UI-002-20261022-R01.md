# 实施目标与范围

对照用户指定的 v4 原型和四张截图，补齐知识库侧栏业务分类，使新增分类进入“自定义分类”并自动选中。Agent 管理页面源文件保持不变。

# 实际变更及原因

- 侧栏固定展示原型中的“核心业务线”四类与“合规与政策”一类；当前店铺尚未创建的预置分类显示 0 篇，不向服务端传虚构分类 ID。
- 与当前店铺真实分类同名的预置项绑定服务端 ID；其余实际分类列入“自定义分类”。新增分类使用现有分类接口保存到当前店铺，成功后自动选中，刷新后仍由服务端返回。
- 分类角标单独查询当前店铺的未筛选数量；页面演示文件计入本页角标。店铺切换重置选择；其他店铺遗留的 URL 分类 ID 自动清除。
- 对缺失预置项选择“新增知识”时，先打开已填名称的分类弹窗，用户明确保存后才能添加知识。重复名称与创建失败都有反馈。
- 产品事实文档同步说明展示模板与真实分类的界线。

# 关键决定与偏差

原型中的分类和数量是固定示例，本项目按当前授权店铺展示真实数据。缺失预置项只作为前端展示模板，不在页面加载时自动落库；用户新增的分类是真实店铺分类。保留原有折叠的知识层级入口，以维持现有查询能力。

# 数据、配置、接口、迁移或 Prompt 影响

沿用分类和知识列表接口，无新增公共接口、迁移、权限、模型或 Prompt 变更。分类创建继续由服务端校验店铺范围和权限。PDF/Word 上传及检索参数仍遵循前任务的本页演示边界。

# 验证交接

见同任务 TR R01。独立只读审查发现跨店铺 URL 分类选择的状态问题，已加浏览器回归并修复。最终 subject 已跑生产构建、前端契约、浏览器交互、类型和 lint。

# 限制、风险与回滚

每个真实分类需要一次独立计数请求，目前按四个并发分批；店铺若有大量自定义分类，角标可能延迟。计数失败显示“—”。本地浏览器为合成 API，尚未部署或核对真实登录态页面。回滚撤销本 subject 提交即可，无数据迁移。
