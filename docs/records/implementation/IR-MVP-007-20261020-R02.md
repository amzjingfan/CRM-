# 目标与变更

针对[本轮失败记录](IR-MVP-007-20261020-R01.md)中公网入口与固定出口 SSH 同时失联，缩短已有 SSH 客户端发现无响应连接的时间。反向隧道 unit 与 TikTok 出口 helper 的 `ServerAliveInterval/ServerAliveCountMax` 从 `30/3` 改为 `10/2`；保持原账号、固定网关、受限端口、主机密钥校验和原有 systemd/Docker 重启策略。同步精确进程参数校验器及确定性测试。

网关 staging `/healthz` 原本 `access_log off`，导致单次失败无法从入口日志定位。本次改为与同站其他路径相同的 `crm_staging_safe_json`；记录 `$uri`、状态和耗时，不记录查询串或正文。应用镜像、接口、数据库、G3 写入权限与生产运行状态均不变。

# 决定、限制和回滚

这是缩短失联检测的缓解措施，不证明 SSH 断开的根因，也不保证公网未来零故障。共享 TikTok 出口 overlay 的默认参数也改变了；production 当前未部署该变更，任何未来生产发布仍需独立放行。若 live 验证显示 SSH 频繁误断、helper 未按预期恢复或 Nginx 日志暴露超出低敏字段，则恢复已审查的旧 unit/Compose/vhost 并复核三公网健康、固定出口和 G3 边界。仅从合并后的源码部署 staging，现场结果另行留证。
