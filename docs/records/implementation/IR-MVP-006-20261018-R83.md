# R83 两次手动 G5 窗口与连接状态诊断

从已合并 main `4228e0b5f8a12e27f29132cbeb8afd002e8913e9` 手动发布一个私有后端镜像，核对 OCI index、linux/amd64 子清单、revision、压缩层与按摘要拉回。用同 SHA 的受审 Git bundle 在 staging 新建独立源码目录；六摘要预取、配置验证通过后，先后两次临时部署同一 G5 候选。每次都核对原隔离店铺的唯一 ready FAQ、50 个会话和 50/50 授权用户；单会话出现安全 `delta` 且满足严格门槛后，才运行 50 个不同账号各一次的合成 SSE。

本轮未改产品源码、Schema、DLP、评分或发布阈值。仓库外保留临时脚本、令牌、原始快照和隔离身份；仓库只保留 24 份低敏机器证据及哈希清单。没有向 TikTok 买家发消息、部署 production 或运行 GitHub Actions。结论与下一步见 R83 TR/RR。
