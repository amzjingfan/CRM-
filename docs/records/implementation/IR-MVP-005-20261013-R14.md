用户确认 `v1.2.7` 有界设计：针对获批 [R13 live](../../../release/evidence/ai/crm-staging-g4-v126-live-38336560477.json) 中条件政策与售后两条禁用内容失败，将合成评测政策答复收敛为有证据的正向申请和审核流程。仅修改评测系统 Prompt、版本、契约测试和 AI 当前文档；镜像、staging 与再次付费复测不在本次实施范围。

# 实际变更

`src/backend/app/agent/security.py` 将重复的条件政策反向禁令收敛为一组通用流程约束：售后只说明有证据的申请资格、时限和平台审核；英文条件政策以一般现在时陈述批准前置条件；正文止于规则，省略个案审批现状和保证。保留退款政策结构化声明、引用改述、否定状态、弃购和翻译约束。未按样本 ID 分支，也未把冻结禁用词原文写进 Prompt。

集中式测试先因新契约缺失出现预期失败，再随 Prompt 和版本更新转绿。`docs/architecture/AI.md` 同步说明源码候选与当前 staging 的区别。没有变更冻结 36 条数据、评分器、85% 门槛、DLP、TikTok 开关、公共接口、迁移或运行拓扑。

# 风险与交接

Prompt 是模型指令，本机契约测试只能证明外发请求内容，不能证明真实模型逐项通过；先前售后样本曾在不同轮次间波动。当前 staging 仍运行 `v1.2.6`，G4 `PARTIAL`、production No-Go。R14 TR 保存本次命令与结果，R14 RR 审查安全边界。后续镜像发布、staging 部署和一次付费 live 各须分别精确授权。
