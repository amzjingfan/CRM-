# 实施目标与范围

用户在两个店铺看到 FAQ 与 RAG 文件详情布局及操作不同。本轮统一知识详情外框，切店铺时立即清除旧店铺状态，并按用户选择让文件“编辑知识”提供替换文件和调整分类。对看板、营销、工作台的同类竞态及文件列表的逐行查询做证据驱动修复；Agent 页无店铺切换入口，未无依据改写其逻辑。没有部署 staging 或 production。

# 实际变更及原因

- 知识页在切换店铺时清空详情、弹窗、筛选、列表、计数和导入进度，请求代次拒绝旧响应；FAQ 与文件详情共用 500px 外框。上传检查和业务写入期间锁定店铺切换。文件图标显示真实扩展名。
- 文件编辑沿用同名显式替换导入，旧版不变；新增同店铺有效分类调整、归档、恢复和软删除接口。删除从列表和详情隐藏，归档仍可查看。接口要求管理权限、CSRF、幂等键，审计记录保留操作前后状态。处理中版本拒绝归档或删除，归档文件不能重试、复核或替换。
- 新增迁移 032 的可空 `knowledge_files.archived_at`。Worker 认领排除归档或删除文件，提交有效版本前再次检查文件状态；旧版本和向量记录不被物理删除。
- 文件列表按页批量取得最新版本和分块计数，消除逐文件查询。看板和营销使用请求代次防止旧店铺响应覆盖；营销切店关闭旧编辑器；工作台切换店铺或平台立即清除旧会话、菜单、确认框和详情，拒绝迟到详情。
- FAQ 和文件仍分别按每页最多 20 条读取，共用页码覆盖两类记录。类别计数和搜索继续使用服务端口径；类型与状态筛选仍是页内筛选，界面明确提示，后续统一服务端列表才适合改变这一契约。

# 关键决定与偏差

遵循用户明确选择：RAG 文件编辑为“替换文件/调整分类”；同名替换保留不可变版本，归档/删除为可审计软操作。没有批量删除所谓“无用代码”，因为未证明其无引用，且项目清理规则要求独立任务。没有改变现有 FAQ 审批、Agent 检索或外发权限。

# 数据、配置、接口、迁移或 Prompt 影响

迁移 032 增加可空归档时间，升级不改写已有数据；若已有归档记录，降级会拒绝丢失归档状态，需以部署备份恢复。新增文件元数据写 API 和响应中的 `archived_at`；默认列表与文件历史不变。Prompt、模型、检索和自动发送模式不变。

# 验证交接

验证命令、隔离数据库、先红后绿与残余限制见 [TR](../../reports/tests/TR-MVP-STORE-VIEW-CONSISTENCY-001-20261025-R01.md)。审查重点为租户隔离、幂等、审计、迁移和跨店铺状态，见 [RR](../../reports/reviews/RR-MVP-STORE-VIEW-CONSISTENCY-001-20261025-R01.md)。本分支仅含源码候选；合并与部署以各自门禁和现场证据为准。

# 限制、风险与回滚

类型、向量和审批状态筛选当前仅作用于已读取页；界面已明示，不应将当前页空态解读为全店无匹配。通用文件向量尚未进入 Agent 检索；未来接入必须同时排除归档和删除文件。回滚应先核对是否已有归档记录，保存新增数据并按迁移门禁决定是否保留 032 列；前端和后端可回到原候选前镜像，不能假定有状态迁移可无损回退。production 仍按独立 G8 门禁。
