# 实施目标与范围

修复第二次 G4 `prepare` 在容器内读取冻结清单时的文件权限错误，仅涉及一次性合成输入文件。

# 实际变更及原因

现场 [#38201088441](https://github.com/CP11-gh/CRM/actions/runs/38201088441) 证实精确六文件 GitHub API 读取通过，但 `docker cp` 后的 `manifest.json` 对 backend 非 root 用户不可读，预检在 `PermissionError` 处失败。工作流在复制两份冻结输入后，限定对这两份生成文件执行容器内 `chmod 0644`，失败即停止。没有修改容器用户、服务代码、密钥或其他路径。

# 关键决定与偏差

维持 backend 的非 root 运行；只用 Rootless Docker 内的容器 root 调整已知合成文件读取位。原运行未进入 Provider 步骤，也未生成 artifact。

# 数据、配置、接口、迁移或 Prompt 影响

没有业务数据、接口、迁移、Prompt 或服务配置变化。容器中的合成输入目录按唯一 run id 创建；两文件为冻结测试材料，不含客户数据或密钥。

# 验证交接

YAML 与 PowerShell 静态解析通过；实际 chmod 路径要由合并后的 staging `prepare` 验证。见 R03 TR。

# 限制、风险与回滚

容器内权限变更只适用于本轮两份生成文件；若 Docker 拒绝 `-u 0` 或读取仍失败，工作流继续失败关闭。回滚本提交会重新暴露已复现的权限阻断。G4 未通过，真实模型调用仍未授权。
