# 实施目标与范围

关闭人工消息发送中的一个失败关闭缺口：进程在创建并提交 `processing` 出站消息后中断时，新幂等键不得再次触发 TikTok 真实写入。本记录只覆盖 G3 安全补丁，不宣布 G3 现场通过。

# 实际变更及原因

- 隔离 PostgreSQL 红测确认，遗留 `processing` 消息及 `running` 工具调用存在时，原实现仍调用发送适配器，返回 `succeeded`。
- 真实 TikTok 发送在检查并提交新 `processing` 消息前锁定同店铺行；未结清的 `processing` 或 `unknown` 出站消息使新调用失败关闭。店铺范围由可信服务端上下文判定。
- 更新行为测试与 API、系统架构、任务、测试和门禁当前文档。没有修改数据库结构、公共请求/响应格式或部署配置。

# 关键决定与偏差

对 `processing` 保留“平台可能已经接收”的保守解释。现有管理员接口只对 `unknown` 对账；不在本补丁中自动把遗留 `processing` 判成失败，也不自动重发。真正出现遗留记录时，须先确认无在途调用、核对平台事实并实施受审恢复路径。

# 数据、配置、接口、迁移或 Prompt 影响

无迁移、密钥、Prompt 或运行开关变化。已有发送接口在未结清消息时返回冲突，保持零次新平台调用。staging `REAL_TIKTOK_MESSAGE_WRITE_ENABLED=false`，本补丁未发布镜像或部署。

# 限制、风险与回滚

隔离库回归证明代码边界，不证明真实 TikTok 已发送。尚无受控测试买家会话、真实平台对账和遗留 `processing` 的人工恢复流程。回滚代码使用共享提交的 `git revert`；staging 当前未部署此补丁。
