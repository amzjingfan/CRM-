# R86 把 G5 接入与 FAQ 检索墙钟拆分

R85 现场 50/50 安全输出通过，但首安全 `delta` P99 4696.9 ms 超过严格 3000 ms；接入 P99 2806.5 ms、混合检索墙钟 P99 1363 ms。[G3 空载只读认证基线](../../../release/evidence/staging/crm-staging-g5-r86-auth-baseline-20261018.json)对原 50 个隔离账号取得 50/50 HTTP 200、P99 352.45 ms、Provider 0、数据库写入 0；这与 G5 负载不是同一条件，尚不能归因负载延迟。现有记录尚不能区分认证、Redis 限流/租约、数据库连接获取和取得连接后的查询。

仅在 G5 SSE 压测模式，对 `/v1/chat/query` 成功认证、限流和会话租约输出固定事件与整数毫秒；其他路径和 G3 模式不产生这些事件。独立 FAQ 检索会话先获取已有数据库连接，再分别记录连接获取与混合查询/融合整数毫秒，并经 Agent 成功摘要的固定白名单保存；原 `retrieval_search` 墙钟保留。日志格式器只放行固定事件、校验后的 trace UUID 和数值，不保存 Token、用户标识、正文、Prompt、查询、模型响应或原始异常。无 API、迁移、模型、评分、DLP、店铺隔离、发送开关、调用次数或 3 秒/5 秒门槛变更。

本轮只交付本地源码候选。R85 恢复的旧后端/G3 模式保持运行；诊断数据须由匹配 main 的新镜像在可恢复 staging 窗口取得。未使用 GitHub Actions，未因本次代码变更调用 DeepSeek 或发送 TikTok 消息。
