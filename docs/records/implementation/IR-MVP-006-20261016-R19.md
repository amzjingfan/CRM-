# G5 手动恢复的源码边界

R17 手动脚本对 `CheckOnly`、`DeployG5`、`RestoreDefault` 和 `RollbackPrevious` 一律要求原 `SourceSha` 仍是 GitHub 当前 main。部署后若只合入 R18 这类证据文档，原部署源码就不再是 main，默认恢复和上一版回滚被阻断。subject `c231165` 抽出可确定性测试的源码策略：所有模式核对 GitHub 仓库中存在的精确提交；新检查和新部署仍要求该提交为当前 main；恢复/回滚允许原已审核历史提交，但必须核对本地不可变候选 backend 的 OCI revision 等于该源码 SHA。归档哈希、全部文件内容、Rootless UID、GHCR 仓库摘要和既有恢复门禁维持原要求。

部署说明同步区分新部署与恢复的源码约束，并更新已核对的 SSH 入口。未发布镜像、修改服务、调用 DeepSeek 或运行 GitHub Actions。现场恢复仍须以实际候选运行态和私有证据执行；代码修复不代表演练通过。
