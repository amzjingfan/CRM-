# 实施目标与范围

为 G4 建立可重复的 staging 一次性评测入口。用户已批准先实现入口；34 次真实 DeepSeek 调用、数据外发和可能费用仍需单独精确授权。本轮不声明 G4 通过。

# 实际变更及原因

新增 `evaluate-staging-deepseek.yml`。工作流仅从 main 手动派发，锁定所填 main SHA、当前运行 backend OCI 摘要、四个评测相关源码文件哈希及独立 36 条合成数据 SHA。`prepare` 在运行容器内验证数据、环境、凭据存在性与真实写关闭，只上传不含密钥或正文的准备证据，Provider 调用为零。`live` 额外需要确认短语，仅在一次性子进程内启用现有评测脚本；质量未过时先上传低敏报告再令作业失败。`docs/operations/DEPLOYMENT.md` 记录使用和费用边界，任务转 `DOING`。

# 关键决定与偏差

复用现有 staging Runner 和运行 backend，不发布新镜像，不改变运行服务、TikTok 开关或 production。数据集包含 34 条 Provider 样本与 2 条注入故障；历史 32/36 不能作为本轮结果。运行镜像的评测代码若与 main 不同，预检失败，不能任意替换摘要规避检查。

# 数据、配置、接口、迁移或 Prompt 影响

没有数据库、公开 API、Prompt 或服务配置变更。工作流仅在 `live` 子进程注入现有白名单 DeepSeek 估价配置；报告成本为保守估算，不是账单。冻结集和运行代码原样复用。

# 验证交接

本轮静态解析、聚焦测试与冻结集校验见对应 TR。staging 的 `prepare` 和真实 `live` 均尚未执行；后续现场运行需另记低敏证据。

# 限制、风险与回滚

工作流使用现有 staging 容器凭据，但准备模式只读取配置，不调用 Provider。运行容器、镜像或配置不符时失败关闭。撤回入口可回滚此单一工作流提交；G2/G3 阻塞与 G4 质量缺口不受本变更消除。
