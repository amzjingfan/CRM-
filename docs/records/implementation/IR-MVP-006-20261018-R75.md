# R75 审批 FAQ 原文与分类并行候选

[R74 现场](../../reports/tests/TR-MVP-006-20261018-R74.md)的首安全输出 5174.6 ms、总耗时 5476.1 ms，未满足严格 3 秒/5 秒。其分类与本地检索并行，但 FAQ 草稿和独立安全复核仍是两次串行模型请求。

运行工厂改为在无确定性工具问题时并行分类与本店 FAQ 检索。仅当唯一命中是当前店铺、当前审批版本、通用退货政策，且原文通过脱敏、语言和确定性安全预检时，才在分类等待期间启动一次独立结构化安全复核。分类仍须返回 `return_policy` 并达到原人工阈值。复核须确认相关性、引用、安全与业务声明；本地再次要求唯一通用 `refund_policy/explain_policy` 声明、无客户实例、无跨引用且为一般时态，再执行原业务声明、DLP、引用、语言和安全门禁。通过后仅形成员工审核草稿，自动发送资格固定为否。拒判、其他意图、越店、旧版、未审批、无知识、异常和取消保持失败关闭或旧路径，并回收并行任务。

新增 `faq-trusted-review-v1.0.0`（SHA-256 `703c863bea159b150a8f5c06de4499dfafa4b1b93609f2401f6331d39a3053af`）及严格结构 `TrustedFaqReviewOutput`，使用 DeepSeek Responses JSON Schema；工作流版本 `faq-agent-workflow-v1.8.3`。旧 FAQ 草稿与复核路径保留为不满足精确资格时的回退。没有数据库、公开 API、限流或 TikTok 写开关变更。

并行复核可能在分类最终不是政策时已发起模型调用，取消只能停止后续等待，不能撤销第三方已接受的请求。这是延迟与少量额外费用的显式取舍，staging 需核对真实用量与时延。本地验证不能证明 3 秒/5 秒或 50 并发达标；现场仍必须先通过严格单会话，才可启动并发。恢复目标是原 G3 单店人工发送模式，生产仍为 No-Go。
