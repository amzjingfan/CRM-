# 实施目标与范围

用户要求继续完成 G5。本次只扩展现有 staging Runner 的零模型调用入口，对 R05 已创建的仓库外私有凭证池做一次只读身份、会话和运行配置预检；真实 SSE、模型调用、知识写入与服务部署不在本源码变更内。

# 实际变更

- `prepare-staging-sse-fixture.yml` 增加 `preflight`：沿用精确 main SHA、Git Blob、运行后端摘要、数据库指纹和专用 Runner 核对；要求私有目录恰有 R05 的一份普通文件，属主为专用账号且无组/其他权限。原 `check_only` 与 `provision` 的空目录和精确写入确认仍保留。
- 一次性只读容器仅挂载经核对脚本和该凭证文件，不传部署环境文件；使用运行 backend 的网络空间，复用 `prepare_clients`，对恰好 50 个凭证最多发送 50 个 `/v1/auth/me` GET 和 50 个会话 GET，不启动 SSE 或模型调用。
- Runner 从运行中 backend 读取生效的 `CHAT_QUERY_LIMIT` 与 Access Token 有效期，输出人数、固定失败类别和两个数值；身份/会话失败或限流低于 50 均使门禁失败。异常隐藏原始内容并失败关闭。现场凭证只留在私有目录，不进入工作流 artifact。
- 增加确定性 HTTPX 与工作流契约测试，更新测试策略和运行说明。现有合成会话尚无已审批且向量化 FAQ，不能据此启动真实 50 并发。

# 关键决定、限制与恢复

只读脚本与工作流代码合入不证明现场 Token 仍有效。若 preflight 报认证失败，应先核对令牌有效期并对现有身份设计受控更新，禁止重跑 `provision`。若运行限流低于 50，后续真实负载须先取得单独范围的 staging 配置切换授权。G5 与 production 均未因此放行；回滚源码可 revert 本次 PR，私有夹具与运行服务不受源码合并影响。
