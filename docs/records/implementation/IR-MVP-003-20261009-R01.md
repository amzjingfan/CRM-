# 本轮实施

在 `feature/mvp003-g2-webhook-validation` 上加固 Webhook 接收：先验官方签名再访问数据库；通知 ID 与原始正文摘要绑定；并发唯一键冲突后重新读取核验；未绑定店铺在保存载荷前返回 404。乱序旧消息仍入库和增加未读数，但不会覆盖较新消息的会话排序字段。

增加仅限 staging 的显式 Compose 叠加层及部署门禁参数。它只为 backend/worker 开启真实只读和 Webhook，消息写入、高风险写入、自动回复及其余进程保持关闭；默认模式和回滚继续关闭。增加仅发布当前 main 精确提交的 backend 私有镜像工作流，以免为本次后端更新重建大体积检索镜像。发布工作流本身不构成镜像发布授权。

# 现场状态与恢复

公网 Webhook 路径和 ready 入口可达，但本轮未发布镜像、未部署、未切换能力开关、未查询当前 Partner Center 订阅、未注册订阅或接收官方真实事件。staging SSH 拒绝当前公钥，浏览器工具也没有已登录 Partner Center 会话。低敏预检见 [`crm-staging-g2-preflight-20261009.json`](../../../release/evidence/staging/crm-staging-g2-preflight-20261009.json)。

本记录为过程版 `DRAFT`；G2 保持 `DOING`。后续须在受控 staging 部署并验证官方订阅、签名、店铺绑定、重复投递、重试、乱序和审计，形成终态记录。若候选配置异常，以受审镜像摘要执行默认 staging validate/deploy 恢复真实开关全关；不触及 production。
