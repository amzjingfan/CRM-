# 基础接待、快捷回复与人工发送栏设计

## 目标和边界

用户提供九张界面参考：在“智能营销”加入“基础接待”下的快捷回复、超时自动回复、进店欢迎语；快捷回复支持个人/团队、分组、快捷键、标签、内容预览及工作台选用；两种策略可列表管理。用户在 2026-10-23 确认：超时和欢迎语本次只保存页面配置，**不自动向 TikTok 买家发送**。本设计以 TikTok 人工辅助 v0.1 为安全边界，保留现有营销流程页面和人工消息审阅。

本次不新增 Worker 触发器、不复用会被营销 Worker 扫描的 `marketing_campaigns`、不启用公开自动回复或高风险写入，也不增加图片/视频平台发送。工作台快捷回复只能预填普通文本草稿或打开现有二次审阅，不能直接调用发送接口。

## 界面与交互

1. 全局“智能营销”导航展开“基础接待”三个子入口，现有营销流程保留。三个页面采用参考图的白底、蓝色选中态、表格、抽屉或弹窗；窄屏时表格可在自身区域横向滚动。
2. 快捷回复按当前店铺和“个人／团队”切换。分组可添加、重命名、删除空分组；回复可搜索、按分组筛选、新增、编辑、删除。表格显示快捷键、最多三个标签、分组、内容摘要、站点及操作。创建页含归属、分组、`/1` 式快捷键（1–8 位字母数字）、标签、站点、1–5 个文本消息段和右侧预览。消息段合并为一个可编辑草稿，总长度不超过现有 2000 字符发送上限。图片和视频选项保留界面位置，但明确标注本期不可保存或发送，不能形成虚假可用状态。
3. 工作台发送栏增加表情、图片、视频、收藏和快捷回复入口，按参考图排布。表情可插入草稿；图片、视频显示不可用原因；收藏可筛选本机已收藏快捷回复。快捷回复弹层含个人/团队、分组、搜索和内容预览。选“编辑后发送”填入草稿；选“发送”只打开现有的准确内容审阅弹窗，坐席仍需再次确认。会话切换、物流卡片草稿、翻译预览和失败重试保持现有行为；输入 `/快捷键` 可选中当前可见回复。
4. 超时自动回复和进店欢迎语各有独立策略列表，可按店铺搜索、状态筛选，新增、编辑、复制、上移、置底、删除和切换“配置开关”；支持多店铺适用范围、有效期和文本内容。超时策略另有超时分钟数。界面显著显示“仅保存配置，自动发送未启用”。列表中的“已配置”不表示平台正在发送。

## 数据与接口

- 新建独立 `reception` 模块和迁移 028。快捷回复分组按 `store_id`、`scope=personal|team` 隔离；个人分组绑定 `owner_user_id`，团队分组属于店铺。回复绑定分组和店铺，保存快捷键、标签 JSON、站点代码、文本消息段 JSON、排序与创建者。删除非空分组返回冲突。快捷键在同一可见范围内不可重复；个人与团队重复时工作台明确优先个人项。
- 策略独立存储 `kind=timeout|welcome`、名称、文本、超时分钟、有效期、配置开关、顺序和创建者，并以关联表绑定一个或多个店铺。所有读取和写入先校验当前用户对所涉店铺的权限；跨店 ID 返回 404。编辑多店策略须能访问全部原有和目标店铺。
- `/v1/marketing/reception/groups`、`/replies`、`/policies` 提供 GET/POST 和 `/{id}` PATCH/DELETE。GET 按授权店铺和范围筛选；列表按顺序、搜索和分页返回。写入执行 Cookie CSRF、`Idempotency-Key`、服务端校验和不含正文的审计。个人回复读写要求 `workspace.reply`，团队读取要求 `workspace.view`，团队写入及策略管理要求 `marketing.manage`；策略读取要求 `marketing.view`。响应显式返回 `delivery_enabled=false`。
- 前端 API 封装使用现有 `requestApi`，不另建认证或请求栈。站点字段目前仅作为话术展示标签；编辑页提供“全部站点 / 美国（US）”及已保存站点选项，工作台尚无可靠的会话站点字段，因此不按站点过滤快捷回复。真实租户边界始终是服务端店铺权限。外部消息仍只经 `POST /workspace/sessions/{id}/messages` 的人工确认路径。

## 失败处理与验收

- 无店铺或无权限显示明确空态；表单校验分组、快捷键、标签、消息长度、策略店铺和有效期。加载和保存失败保留输入，可重试；删除先站内确认。被删除的回复从列表与弹层消失，不改变已经填入的会话草稿。
- 后端测试覆盖个人隔离、团队权限、跨店访问、非法媒体、长度限制、重复快捷键、策略配置不会产生营销事件或平台调用、迁移 upgrade/downgrade/upgrade。前端契约和浏览器测试覆盖三导航、表单/预览、筛选与弹层、草稿预填、人工审阅以及图片/视频禁用。运行 Ruff、mypy、前端 lint/typecheck/build 和受影响测试。
- 本次交付不声明真实自动回复或媒体发送可用。staging 若部署，使用已批准的直接手动路径和独立备份/迁移/健康门禁；production 继续 No-Go。
