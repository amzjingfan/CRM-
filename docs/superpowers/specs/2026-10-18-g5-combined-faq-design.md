# G5 FAQ 双调用路径设计

## 目标与范围

R68 在 staging 的唯一合成 SSE 首次安全 `delta` 为 4550.4 ms，超过 MVP G5 的严格 `<3000 ms` 门槛。分类、FAQ 草稿和独立安全复核是三次串行 DeepSeek 调用。本设计只减少有同店铺已审批 FAQ 命中的非工具问题的一次串行调用；严格门槛、店铺隔离、DLP、引用和人工复核语义不变。现场单会话通过后才能执行 50 个不同 CRM 账号的并发压测。

## 数据流与契约

应用先用现有确定性规则识别工具需求。工具问题继续走原分类与工具路径。非工具问题先用现有 RAG 服务按服务端授权的 `store_id` 检索；无可用知识时保守转人工，不请求 FAQ 草稿。命中已审批 FAQ 后，应用向现有 Provider 发起一次注册的严格 JSON Schema 请求，同时取得 `IntentModelOutput` 和 `FaqAnswerModelOutput`。组合输出必须满足两套现有 Pydantic 约束；分类拒判、置信度不足、模型拒绝、草稿缺失或 Schema 不合格都不得产生可展示草稿。

通过分类门槛的结果继续使用现有代码校验引用集合、知识范围、业务声明、DLP 与语言，再调用原独立 FAQ 安全复核模型。原 `grounding_confidence`、最终置信度阈值、自动发送门禁和人工复核动作不变。组合请求的 Prompt 进入现有注册表并记录独立版本和 SHA-256；DeepSeek Responses JSON Schema 路径仅扩展到该新场景。模型正文、Prompt 和原始异常不进入日志或运行证据。

## 失败与兼容性

本次只在 FAQ 命中路径使用组合调用。工具、拒判、低置信度、检索失败和请求取消保持失败关闭；取消时不留下持有数据库会话的后台任务。独立安全复核必须通过，模型输出不能自行批准发送。Provider 不支持组合 Schema 时只记录稳定错误类型并停止现场窗口，不回退到无复核回答。G4 冻结评测数据、评分和发送开关不变。

## 验证

先用确定性测试覆盖 FAQ 成功、无知识、工具、拒判、低置信度、无草稿、伪造/跨店铺引用、Provider 错误、取消、Prompt 注册及 Schema 路由。运行相关测试、完整后端门禁和安全审查。合入 main 后手动发布私有后端镜像，仅在 staging 受控窗口运行单条合成 SSE；首安全 `delta` 必须严格 `<3000 ms` 且总耗时 `<5000 ms`。只有单会话安全与性能同时通过，才用现有隔离 50 账号执行真实并发、资源/队列/断连采样，最后恢复 G3 原模式并核对健康、摘要与固定出口。任一门禁失败立即停止后续负载并恢复。
