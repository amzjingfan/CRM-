# Agent 业务工具与分类设计

用户已批准本阶段实现 12 个工具、6 个业务分类和 3 种操作标签；本地完成与先前动态 Agent 重写一起等待部署批准。欢迎语/超时回复工具未纳入本阶段。

订单与物流：search_customer_orders、query_order、query_logistics；商品与优惠：search_products、query_product、query_available_coupons；售后服务：query_aftersales；客户与会话：query_customer_profile、query_conversation_messages；知识检索：search_knowledge；人工协作：create_handoff_request、add_internal_note。前十项只读，后两项写 CRM 内部协作记录。保留修改地址、发券、实际转交和平台发送四项人工确认提议，绝不直接执行。

元数据、参数 Schema、分类、权限及平台 scope 在 agents/tools 下定义，管理 API 向前端返回分类目录和当前店铺可用性。原生 @tool/function calling 暴露配置的完整工具集，不因分类限制工具数量。知识工具受显式绑定文件约束，旧配置绑定文件仍可自动得到知识工具。

复用现有工作台的同店授权查询与 TikTok 只读签名客户端。订单搜索返回本轮不透明候选引用；订单、物流、售后从已验证买家的候选中选择，零候选明确无数据，多候选未选时要求澄清，不默认最新订单。商品同样通过本轮候选引用选择。所有查询含来源与获取时间，缺权限、缺上下文、失败与无数据明确区分。物流保留全部包裹与轨迹；超过模型上下文时明确分页而非冒充完整结果。

消息工具仅读取冻结快照内当前会话的历史；客户工具只返回必要画像，不发送地址/电话。所有自由文本使用现有 DLP/不可信数据边界。结构化事实在最终依据复核中保留，原始平台响应不进日志。内部协作记录标明 AI 建议、类型、来源运行、会话和创建时间，按同店同会话授权读取；同次运行相同内容幂等，审计不保存正文。接管请求不改变分配状态。内部写入权限沿用 workspace.reply，读取沿用 workspace.view。

前端按 6 类展示卡片，提供搜索和已配置筛选；显示名称、用途、操作标签、上下文和授权状态。知识卡显示文件数并切换知识配置。保持原有页面视觉与键盘操作，窄屏单列；店铺切换清空旧目录并忽略过期请求，加载失败不回落前端假目录。

本地验收覆盖目录/Schema、模型工具循环、跨店与跨客户负向、多订单选单、分页、平台 scope 与错误、内部写入幂等和审计、冻结消息边界、工具+RAG汇总、迁移往返、前端交互和生产构建浏览器回归。真实平台与模型联合验收留待部署批准；本地结果不冒充现场通过。
