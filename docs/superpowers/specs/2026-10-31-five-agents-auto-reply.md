# 五类 Agent 模板、在售商品与多 Agent 自动回复预演

## 目标与范围

为 TikTok 多店客服保留现有「订单物流 Agent」模板，新增售前商品、售后商品、物流状态更新、回复兜底四个可编辑、可发布、可逐店应用的模板。每个模板使用现有七段式系统提示词和已注册的原生 function-call 工具；知识需求仅声明槽位，文件必须在目标店铺逐一绑定、索引并审批。模板本身不携带店铺文件、客户信息或发送权限。

在 TikTok US 测试店铺对五类模板分别验证配置发布、预览和真实会话工作台建议；使用只读工具和绑定知识，记录实际路由、工具轨迹、引用和语言。物流更新模板另需验证真实已核实节点驱动的只读通知预演；它不能靠买家普通提问伪造更新。兜底只在业务 Agent 均无法处理后参与；前两轮可简短澄清或安抚，同店同会话连续第三次无业务解答时使用**内容固定、语言跟随买家**的安抚及人工接管话术。英文原文如下，中文使用下列固定同义版本；其他已支持的买家语言仅做忠实翻译，不让模型自由改写内容。业务 Agent 成功一次后计数归零。模型或工具故障不计为无匹配。

> We have received your question. At present, there are too many inquiries and the agent is occupied.
> Please wait patiently. We will contact you as soon as possible. Thank you!

中文固定版本：我们已收到您的问题。目前咨询较多，人工客服正在忙碌。请耐心等待，我们会尽快与您联系。谢谢！

商品搜索及详情仅向 Agent 返回当前上架、有正库存的商品和 SKU。库存缺失视为未知，不称为有货；每次详情重新读取平台状态，不复用旧搜索结果作库存保证。

店铺级开关控制多 Agent 自动回复的**本地预演**：买家入站消息幂等入队，现有动态模型路由、多个专家、工具和知识链路产生复核后的建议及审计，坐席可查看；默认关闭，关闭或权限变化立即阻止后续任务。当前部署仍禁真实自动发送。真实发送需后续独立验收与放行，不因勾选预演开关而发生。已有人工发送、物流通知独立策略及生产边界保持。

## 模板职责与工具

| 模板 | 参与条件 | 工具 | 知识槽位 |
|---|---|---|---|
| 售前商品 Agent | 选品、规格、适用、价格优惠 | `search_products`, `query_product`, `query_available_coupons`, `search_knowledge` | 选购指南、规格/使用说明、优惠规则 |
| 订单物流 Agent（现有） | 买家主动询问订单、发货和包裹 | `search_customer_orders`, `query_order`, `query_logistics`, `search_knowledge` | 配送/丢件政策；实时状态以工具为准 |
| 售后商品 Agent | 使用、安装、故障排查为主；退换货和退款进度 | `search_products`, `query_product`, `search_customer_orders`, `query_order`, `query_aftersales`, `search_knowledge` | 说明书、故障排查、保修、退换货/退款规则 |
| 物流状态更新 Agent | 已核实新节点事件，非普通咨询 | `query_logistics`, `query_order`, `notify_logistics_update`；按需 `search_knowledge` | 配送通知措辞/说明；节点以工具为准 |
| 回复兜底 Agent | 其他业务 Agent 无解时 | `query_conversation_messages`, `create_handoff_request`, `add_internal_note` | 不绑定业务知识 |

模板工具是最大候选范围；运行时仍按店铺授权、已发布 Agent 工具白名单和具体问题决定调用。内部写入工具只保存接管请求或备注，不能发送平台消息。

## 实现决定

1. 复用现有 `app.agents`、模板 API、模型路由、工作台建议和物流通知服务；不引入新框架或服务。
2. 模板提供明确的路由用途（普通咨询、物流事件、兜底）配置，而非根据模板名称或正则硬编码。普通咨询先路由业务 Agent，零匹配/均无依据时才交兜底；物流事件走现有通知专用链路。
3. 店铺预演策略采用独立授权、乐观锁和审计；任务持久化、同一入站消息唯一、结果为待审阅草稿。全局真实发送门禁继续关闭。预演草稿只在授权工作台展示，不进入买家消息流。
4. 用一条主题分支集中修复、完整本地测试、一次合并与一次手动 staging 发布。现场验收如发现问题先汇总再统一修复与复验；不为每个失败单独 PR/部署。

## 验收与清理

- 五个模板最终在 staging 保留且可查询发布版本；订单物流原模板与已应用 Agent 不被重建或覆盖。
- 五类分别有真实预览和工作台建议证据；读工具来自同店真实 API 或明确标注的合成数据，知识引用对应本店已审批文件。物流事件单独证明幂等和不外发。
- 有货筛选覆盖混合库存 SKU、零库存、未知库存、下架和分页；跨店、未授权、撤权、重复入站、开关关闭和失败关闭有负例。
- 店铺预演开关开启后本地可完成多 Agent 路由、工具、知识、复核和待审阅结果；真实发送次数为零。
- 本轮合成 Agent、文件、会话及策略在验收后按可恢复方式清理并核对；五个共享模板保留，原业务对象不改。

## 已知边界

真实 TikTok 自动发送留待单独放行；未获授权的店铺/API 能力不会靠模板绕过。真实店铺没有可用商品、售后或物流节点时，测试应记录“无现场样本”，并以授权的合成/隔离集成样本补充，不能冒充真实平台返回。
