# TikTok 店铺列表与直接授权设计

## 目标和已确认语义

依据用户提供的店铺列表截图，系统设置的店铺页展示店铺名称、别名、平台 ID、系统 ID、所属站点、状态、授权到期时间、最近添加时间，并支持搜索、状态筛选、别名编辑、重新添加和删除。当前真实平台只有 TikTok Shop；Shopee 和 Amazon Mock 保留在既有“授权”页。Custom 应用使用现有卖家授权链接，用户点“添加店铺”即进入 TikTok 授权，无需预先手工填写店铺信息。

用户确认“删除”撤销本系统保存的 TikTok 授权凭证并从列表移除，保留内部店铺、系统 ID、历史订单、会话及审计。该操作不调用 TikTok 平台的远端取消授权接口；再授权同一平台店铺时复用原系统 ID。

## 授权与数据

- 新增授权使用独立 POST 入口，要求系统级管理员和 CSRF；只保存一次性随机 state，不立即创建 Store。卖家回调仍先生成加密短期任务，worker 验证 Token、Scope 和唯一授权店铺后，在同一事务里创建 Store 与 TikTok ChannelAccount。取消、失败或平台身份冲突不创建占位店铺。旧的“指定内部店铺再授权”入口继续可用。
- “重新添加”对现有内部店铺调用原 OAuth 入口，并将回跳页设为店铺列表；回调必须与原平台 shop ID 一致，不得悄悄换绑。已撤销授权后从“添加店铺”重新进入同一 shop，复用原 Store 和 ChannelAccount。已连接的重复“添加”返回冲突。
- 新 Store 的平台名称、ID、站点来自已验证的 TikTok 响应；系统 ID 是内部 UUID。币种依据平台站点的已知映射初始化，无法识别的站点拒绝自动建店；时区初始化为 UTC。别名是内部展示字段，写入 Store metadata，不改变平台名称或隔离编码。
- 授权到期时间取当前授权的 refresh token 到期字段与平台授权到期通知的更早者；最近添加时间优先使用最后一次成功授权时间，旧数据回退到渠道创建时间。缺失字段显示“—”，不虚构到期时间。状态由渠道状态、平台重授权提醒及授权到期时间计算。手动删除只隐藏本地撤销的渠道，平台侧解除授权显示异常供重新添加。删除沿用原渠道撤销能力：破坏本地 Token 可用性并保留渠道身份与低敏审计。

## 安全与兼容

新店授权状态只绑定发起用户，worker 重新检查系统管理员身份。OAuth 回跳地址只能是固定的店铺或授权页。进度查询只允许原发起者并再次检查权限；state 和 code 不进入 URL 回跳、日志或列表 API。现有店铺授权、Mock 渠道和单店人工发送边界不变。短期任务 `store_id` 允许为空，新增固定回跳字段，提供可失败关闭的迁移回退。

## 验收

后端测试覆盖未授权前不建店、成功后原子建店、取消不留空店、重复已连接拒绝、撤销后复用系统 ID、非系统管理员拒绝、跨店铺失败关闭、凭证不出列表 API。前端核对截图字段、搜索筛选、别名、回跳进度与二次确认删除；运行相关静态、单元、契约、构建和部署门禁。staging 发布必须使用已合入源码与私有备份，production 另经 G8 放行。
