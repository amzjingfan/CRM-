# 系统架构

## 仓库与运行边界

`src/` 是唯一工程根，包含 Next.js 前端、FastAPI 后端、数据库迁移、部署资产、构建配置和测试。仓库根保留 Git/GitHub 元数据、`docs/` 当前契约与 `release/` 发布基线及低敏机器证据。仓库不再用人员角色划分代码或文档。

## 核心组件

- Next.js 管理端：登录、看板、客服工作台、知识库、营销、Agent 和团队配置。
- FastAPI API：认证、授权、协议校验、业务服务编排和 OpenAPI。
- Worker：Webhook、同步、检索、模型和可重试的异步任务。
- PostgreSQL + pgvector：业务事实、审计、幂等、知识版本和 1024 维向量。
- Redis：会话/限流、OAuth state、短期状态和任务协调。
- MinIO：受控对象存储。
- 模型服务：本地 BGE-M3 Embedding、bge-reranker-large 和受控 DeepSeek Provider。
- 通用文档解析 Worker：独立 MinerU 4.0.12 CPU 容器，读取私有 MinIO 源文件，调用内部 BGE-M3 后将完整版本的向量写入 pgvector；不对公网提供端口。

当前源码数据库迁移头为 `030_merge_rag_reception`：文档导入和基础接待分组两条已独立部署的 `029` 从 `028` 分支，合流迁移保留双方 revision 身份；任一已有 029 环境升级 `head` 时只补另一条 029 后进入 030。staging 是否已升级以实际部署证据为准。迁移顺序是部署契约的一部分，禁止跳过或手工修改生产结构。`026` 在保留旧邮箱账号的同时增加可选登录名、账号元数据与独立的部门/店铺/成员关系表；`027` 允许 OAuth 短期任务在确认平台身份前不绑定内部店铺，并记录白名单回跳页。存在未绑定店铺的任务时 `027` 降级失败关闭；恢复须依赖经验证的备份并保护部署后的业务增量。

## 请求与消息流

1. 浏览器进入 API，认证中间件恢复用户和店铺授权范围。
2. 路由验证协议，服务层执行状态机、权限、幂等和审计。
3. 平台适配器负责 TikTok 等外部契约；Agent 不直接调用平台 SDK。
4. Webhook 先验证原始签名并落入内部事件，再由 Worker 幂等消费。
   授权店铺的客服会话另由现有 Worker 定期调用 TikTok 只读列表与消息接口，全页回填并依据平台消息 ID 幂等增量同步；成功后工作台按店铺权限查询内部会话和历史。
   TikTok 新消息通知不携带昵称时保留已同步的买家名称；通知提供新昵称时才更新客户画像，避免工作台在两次同步之间短暂显示匿名。
   工作台在可见标签页内每 5 秒拉取会话列表和当前会话的最新消息，按消息 ID 合并，保留已加载的较早历史和选中会话；后台刷新失败时维持现有视图并在下一轮重试。
    会话搜索由后端在授权店铺集合内关联买家、同店同平台订单/物流/商品及最新消息，先过滤后稳定分页；多个关键词取并集，搜索正文以 POST body 传输。TikTok 真实读取启用时，客户侧栏先核对会话店铺权限、本地客户 IM ID 与官方 202601 单会话 BUYER 参与者，再以其订单域 `user_id` 调用官方 202309 订单搜索；逐条验证返回买家身份，分页异常或超过 2000 笔上限时失败关闭，不把部分结果当成全集。其他运行模式仍从已同步的同店同平台同买家投影读取。缺失的商品、金额和物流字段不补造。订单详情保留官方通用物流全部节点；跨境店铺打开物流弹层时才尝试增强多包裹读取，Redis 按店铺与订单占位并缓存八小时，失败则只展示通用轨迹。商品和优惠券由当前会话店铺的有效 TikTok 渠道调用固定官方只读接口；Product Basic 不在既有授权时拒绝读取，名称/编码的逐页过滤明确标注不完整。侧栏快捷动作仅填入草稿。草稿多语言翻译沿现有 DeepSeek Provider 与注册 Prompt/DLP 边界只生成预览，不写入平台；草稿变化使预览失效，最终发送仍走原人工确认及工具执行层。
   会话表由可回滚迁移 `025_workspace_actions` 增加 `is_starred` 与 UTC `closed_at`：星标仅供 CRM 内部识别差评风险；关闭仅影响本地工作流。新买家消息晚于关闭时间时由 Webhook 或只读同步恢复活跃，历史消息回填不重开；关闭期间禁止人工发送和转交。
   Webhook 与只读同步按平台消息 ID 去重；只读同步补入晚于上次成功同步时间的买家消息时增加未读，首次历史回填不制造旧消息未读。
5. AI 请求先做字段允许列表和 DLP，检索已审批知识，必要时调用只读/受控工具。
6. 生成结果经过结构和安全校验后成为坐席建议；人工确认后才允许普通文本平台发送。
   staging 手动窗口额外要求单个数字平台会话 ID 与当前会话精确匹配；其他会话的工作台发送能力关闭，服务端和 TikTok 写客户端也拒绝发往其他会话。物流卡片先作为本地结构化草稿审阅，确认后服务端重新核对同店买家订单与包裹，复用消息工具的权限、幂等、店铺熔断和 `unknown` 对账，再由写适配器发送官方 `LOGISTICS_CARD`；CRM 保存卡片展示快照，详情轨迹仍按需重新读取。
   图片/视频由当前会话已授权坐席在前端审阅文件后发起。后端先核对店铺、有效 TikTok 授权和真实发送白名单，再验证 MIME、文件头与上限；图片直接上传客服图片接口，10–100 MiB 视频在固定出口完成官方初始化和顺序分片。只返回以服务端密钥签名、绑定坐席/店铺/会话/发送幂等键且限时 20 分钟的资源凭据。二次确认发送时服务和工具层重新验签、核对目标，由现有出站消息状态机执行一次 `IMAGE`/`VIDEO` 写入；未知结果维持店铺熔断并人工对账。媒体文件不存入 CRM 数据库，上传成功只记录类型与字节数审计；视频 `vid` 不推造播放 URL。

## 店铺隔离与权限

用户的店铺范围由服务端会话和授权关系计算。所有业务表查询、缓存键、审计和外部渠道映射必须包含内部店铺边界；客户端提供的标识只能用于定位，不能扩大授权。跨店铺访问、未知权限、失效 OAuth 和缺少幂等键均失败关闭。

## Agent 与工具边界

Agent 只能调用注册的白名单工具。工具层承担参数模型、店铺范围、角色权限、风险分级、幂等、超时、审计和输出字段过滤。订单、物流、优惠和政策事实以工具或已审批知识为准，模型不能生成或改写为事实。高风险工具与真实写入由独立配置关闭。

Agent 管理页调试走独立内部入口，复用现有分类、文件 RAG、独立安全复核和只读工具编排。调试运行记录允许没有客户会话外键（迁移 034），以 `mode=debug` 的不可逆输入摘要和 Agent 配置 ID 标识；可选的当前店铺授权会话只用于取得可信客户/订单上下文，不生成伪造客户消息。本地订单缺失时，TikTok 订单/物流调试通过现有会话买家身份校验读取平台最新订单，只生成本次只读工具投影，不同步订单表。运行结果只返回管理页，调试动作按人工复核处理。

## 数据与知识

- 核心实体包括用户、店铺、渠道、会话、消息、订单投影、知识分类/条目/版本、Agent 配置、营销任务、工具调用、审计和幂等记录。
- 知识使用 `statement_type`、`customer_scope`、`document_version` 和逐版本审批；正文或语义范围变化会撤销审批。
- 通用文件独立于 FAQ 建立 `knowledge_files`、版本、解析单元和 `vector(1024)` 分块表；配置按店铺保存且上传时快照。同名替换必须显式指定旧文件。解析或清洗中任一关键单元不可靠时，整个新版本停在 `review_required`、不写新向量，也不切换旧有效版本；全部修订或可信解析完成后才原子切换。Agent 仅在显式绑定当前店铺文件、当前有效版本索引就绪并获人工内部审批时读取文件向量块；检索查询同时过滤归档、软删除及模型不匹配。版本新增审批状态、语义类型、客户范围、审批人和时间，迁移 033 添加文件向量/词法索引。
- `knowledge_files.archived_at` 表示可恢复归档，`deleted_at` 表示从管理列表和详情隐藏的软删除；两者均保留版本与审计。文件管理 API 先按授权店铺定位资源，再校验分类、处理状态和幂等键。Worker 不认领归档或已删除文件，提交新有效版本前再次检查文件状态。文件列表批量取得最新版本及分块计数，避免逐文件查询。前端在店铺或会话范围改变时清除旧详情，并以请求代次拒绝迟到响应；FAQ 与文件详情共用外框。
- 知识库管理页以当前店铺启用分类为可见集合；FAQ 与文件的列表查询在数据库层先限制分类，再计数和分页，使“全部知识”与侧栏分类之和一致。未分类历史内容仍保留，原有 API 默认查询和按 ID 详情不改变；本次无数据迁移。
- RAG 使用 BGE-M3 的 1024 维向量，Dense Top-20 后由 bge-reranker-large 取 Top-5，Dense 门槛为 `0.52`。
- DeepSeek 不是业务事实来源，模型输入仅包含固定允许字段和已过滤工具结果。

## 真实平台与失败关闭

TikTok OAuth Token 加密保存，state 哈希绑定并由现有 jobs worker 原子消费。公开 callback 将 state/code 认证加密到短期任务并快速站内回跳；任务按 state 摘要去重，终态清除密文，过期和崩溃不重用一次性 code。状态查询同时核对原发起用户与店铺权限。Webhook 在真实模式只按官方签名验证。消息写入只允许人工确认的普通文本或原生物流卡片；部署范围可选单个平台会话或审核过的店铺 UUID 列表，二者互斥且空范围失败关闭。工作台、工具执行层和 TikTok 写适配器均按范围拦截，工作台还核对店铺有效、渠道已连接、Scope 与凭证有效期。真实发送在持久化 `processing` 前锁定店铺行，同店铺已有 `processing` 或 `unknown` 出站消息时阻断新发送。平台超时或结果不确定时记录 `unknown`，随后按消息标识对账，禁止自动重复发送；进程中断留下的 `processing` 同样保持阻断，待人工核对事实后走受审恢复流程。

基础接待配置独立于会被营销 Worker 扫描的活动表：个人/团队快捷回复按店铺和用户隔离，分组 `enabled` 只决定工作台能否选用该组话术，管理页保留停用分组及内容。超时回复与进店欢迎语只保存策略、店铺关联和按店铺时区解释的日期/每日时段；策略列表只返回对全部关联店铺都有查看权限的记录，多店策略去重分页。旧版 UTC `valid_from/valid_to` 记录保留原语义，新建配置写入独立 `schedule` JSONB。配置开关不接入 Webhook、Worker 或 TikTok 写适配器；工作台仅把文本快捷回复放入当前会话草稿或现有审阅框，实际外发仍须坐席二次确认并走原消息幂等、审计与对账路径。

买家阶段的人工覆盖值保存在同店 `customers.metadata`，只允许 `pre|during|after`；清除该值恢复前端依据最近已同步订单状态的自动判断。写入通过会话店铺鉴权、CSRF、权限检查、客户行锁与低敏审计，不触发 TikTok 写接口。

`AUTO_REPLY_ENABLED=false` 与 `REAL_TIKTOK_HIGH_RISK_WRITE_ENABLED=false` 是当前安全基线。Shopee/Amazon 真实适配、公开自动回复、自动营销和高风险写入不属于 v0.1。

## 可观测与恢复

请求、任务、模型、检索、工具和平台调用使用可关联的 request/trace 标识，但日志不含密钥、Token、客户正文或完整 Prompt。备份、恢复、迁移和回滚必须使用发布基线中的版本与哈希，并通过真实演练后才可用于生产签署。

## Staging 运行拓扑

当前 staging 是入口与业务运行分离的双服务器部署：

```text
staging.overselfx.com:443
  → 38.55.145.52 宝塔 Nginx / TLS
  → 127.0.0.1:18080
  → 受限 SSH 反向隧道
  → 192.168.1.173:127.0.0.1:18081
  → crmdeploy Rootless proxy:80
  → frontend / backend / worker / jobs / agent-worker / data / retrieval model
```

公网服务器只保存站点 Nginx 与宝塔管理的证书，不运行 CRM、数据库或模型。业务服务器只通过 UID 1004 的 Rootless Docker 运行 `crm-staging`，其宿主机入口固定为 `127.0.0.1:18081:80`；系统 Docker 和 GitLab 的 `10080/10443` 不属于 CRM 操作范围。隧道账号无交互 shell，只能创建新服务器回环 `127.0.0.1:18080`，目标固定为旧服务器回环 `18081`。

TLS 只在公网宝塔 Nginx 终止，内层代理使用明文 HTTP 并覆盖 `X-Forwarded-Proto=https`。隧道、应用或证书未就绪时入口必须返回明确 `502/503`，不得回退到 GitLab、默认站点或其他 vhost。历史同机 systemd `80/443 → 10080/10443` 资产已从活动树移除，只能通过 Git 历史查看。

production 仅复用 `www.overselfx.com`、固定 HTTPS、不可变镜像和安全开关等公共契约；是否采用相同双服务器拓扑仍需独立架构与发布批准。

## TikTok 固定出站拓扑

TikTok 出站与上述公网入口是两条独立、最小权限的 SSH 链路，不复用账号、密钥、转发方向或允许目标：

```text
backend / worker / jobs
  → socks5h://tiktok-egress:1080
  → Rootless Compose tiktok-egress helper
  → crm-egress@38.55.145.52:22（独立 SSH 动态转发）
  → auth.tiktok-shops.com:443 / open-api.tiktokglobalshop.com:443
```

helper 只加入独立 `tiktok-egress` 网络，不发布宿主机端口；backend、worker、jobs 同时加入默认网络与该网络。TikTok HTTP 客户端统一显式设置代理并使用 `trust_env=False`，隧道不可用时连接失败，禁止回退到业务服务器的随机直连出口。`checkip.amazonaws.com:443` 只允许发布门禁验证实际出口，不用于业务请求。

staging 的 helper 使用与候选 backend 相同的不可变镜像，并在 Rootless Docker 内显式以容器 `0:0` 运行；该 root 只映射到宿主机 `crmdeploy`，用于读取其所有的 `0600` 私钥，不获得宿主机 root。密钥目录只读挂载给 helper，应用容器继续使用镜像默认非 root 用户且不得取得私钥。production 只继承相同的配置与失败关闭契约，实际拓扑、出口、账号和密钥尚未部署或放行。
