# AI、RAG 与工具契约

## 回复审阅与交付（2026-10-30）

工作台显式请求 `reply_mode=review_plan` 时使用 `agent-reply-plan-v1.1.0`：原始买家消息独立绑定，模型以 `submit_reply_parts` function call 决定单条或多段完整答复，不按正则拆问题。已配置工具、Agent候选和绑定文件RAG保持原授权范围。每段独立经过当前隐私/依据复核和语言、长度重组；单段依据失败时废弃整组候选，改为从原题和原始专家证据重建并复核一条完整短答复；其他失败继续关闭。平台文字每段最多2000 UTF-16单元，计划预算16000；不截断原文制造通过。运行记录追加reply_plan版本，复用绝对deadline和数值用量。

Provider原生SDK流只向当前坐席发送 `draft` 快照；解析器只选择首个 `submit_reply_parts.texts`，不暴露reasoning、自由说明或工具JSON。草稿标记未复核/不可发送，不进入输入框、记忆或可信事实。最终 `result` 替换草稿，失败、取消、空结果、跨会话或旧请求清空并阻止使用。原安全 `delta` 指标与未复核首token不同，不以草稿流宣称G5安全首输出达标。

物流工具默认 `detail=latest`，仅最新节点进入正文；`history`保留内部核查分页，原生卡片按需展示完整轨迹。卡片重新核验当前买家、订单及包裹，先成功发送完整文字，再提交卡片。`reply-batches`冻结人工确认的准确有序计划，按段持久化；先提交unknown再外发，同parent key/body重试跳过已成功段，仅已知失败段使用新attempt key。锁内CAS拒绝迟到旧attempt；可信发送前零写入错误记failed，未知结果沿原消息人工对账，未确认前不重发。前端临时预演按钮、物流通知预演区及假的自动发送演示开关已移除；保留真实流式审阅、人工确认和卡片。买家交付已在零外发现场与本地替身测试验收，未验证TikTok同气泡逐token追加能力。

`notify_logistics_update`属于订单与物流的notification能力，模型仅提供候选正文，可信事件、店铺、买家、订单、包裹及幂等键均由服务端核验绑定。后台在现有jobs低频扫描每单到期台账，至少8小时一次且失败退避；无可靠新节点、买家语言、官方身份或发送窗口则阻断。首次默认仅建立基线；只有官方下单和节点时间都晚于策略开启时间才允许首次通知，旧/重复/乱序节点不发送。通知用已发布Agent提示词与同一独立模型复核；显式人工预演不消费基线、不启动后台、不建出站消息。实际通知要求全局与真实投递双开关、店铺策略、有效配置工具和现时授权全部成立，以独立通知台账授权调用统一执行器，保持 `human_confirmed=false`，只支持TEXT，不扩大普通自动回复权限。

通知pending从本地台账恢复，reviewing带十分钟持久租约及owner token，过期可重领；prepare及回写须匹配未过期owner，旧owner不能覆盖新owner。恢复重新核对当前策略及最新节点，不提前重新读取订单/物流，不改变八小时next_poll。unknown只用原稳定key对账，不重新生成或交付。

本轮详细回答契约：最终输出使用 `agent-evidence-review-v2.4.0` 独立模型同时核验事实与隐私，读取实际参与 Agent 的已发布 `compliance` 段。回答以原文片段编号提交；复核必须明确 `privacy_reviewed=true`，从服务端分配的证据别名选择依据，并返回待删除片段及逐字敏感值。程序只删除已定位原文并合并重叠范围；再将已清理正文交给模型自然整合，改写阶段不接收原始工具证据或未过滤草稿；结果重新独立复核后才能展示。非法片段、隐私反复恢复、缺少复核或无依据回答不展示，不以“敏感信息已隐藏”占位符替代最终正文。各轮共用绝对截止时间，取消/失败保留每轮已知数值用量。复核还须明确返回 `output_rewrite_required`，结合原始买家语言和已发布表达要求识别混语/表达偏离；仅对已清理且有依据的正文重组，再独立复核，不用正则检测语言。

`agent-answer-output-v2.3.0` 的调试与工作台汇总共同使用平台 2000 UTF-16 单元预算（与前端一致，emoji 计两个单元）。模型先按预算组织；仍超长则在完成隐私/依据复核后，仅使用已清理正文按原问题精简重复、长标题和无关细节，保留关键结论与必要编号，再独立复核。程序不切片截断回答，不增加工具/Agent 数量限制；重写仍共享原 deadline 与用量统计。重复超长候选记 answer_too_long，不显示未完成改写的答案。手工编辑器保留完整长稿和超限发送保护。

无成功工具事实和有效知识引用时，汇总丢弃全部未核验专家稿，仅以服务端缺证状态生成跟随买家语言的澄清，经同一独立模型核验后显示。该状态只能支持“无法确认”的说明，不能证明具体政策或业务结果；仍返回 no_verified_evidence、人工复核和零知识引用，不回退 FAQ 或整店检索。

知识工具审计将 search_knowledge 的 retrieved（命中）和 no_hits（查询完成但无命中）记作 succeeded，并在低敏 result_status 中保留原语义状态；失败、超时等仍按失败记录。知识投影与工具循环共用完整JSON的16000字符预算，超限时只移除尾部完整块，不截断原文；最终引用、grounding和返回前审批复核仅使用模型实际收到的块。单块仍无法容纳则返回 tool_result_too_large，零引用、零知识依据。知识库页说明实际审批/绑定入口；检索参数面板仍只是预览，不会改变服务端运行参数。

路由子问题只是模型生成的任务改写，不能替代买家原文。专家先校验原始问题；不同的路由改写再次校验时若仅发生VALIDATION_ERROR，则丢弃改写并使用已经通过校验的原文，不传递被拒内容。原文被拒仍零调用；没有原文时路由自身必须通过；其他异常不吞掉。原始输入DLP、权限和绝对时限保持。

正常订单号、运单号、SKU和商品编号只在当前授权工具的固定类型投影路径中保留；自由文本或任意同名字段不因此放行。业务编号不进入派生事实记忆，运行资源引用不能跨轮复用。个人电话、邮箱、私人精确地址与凭证继续过滤；正常字段名、日期、金额和公共物流节点由上下文语义判断，动态回答不使用旧地址字符或业务关键词裁决。

`agent-answer-output-v2.3.0` 将买家原始问题与路由子问题分开：专家和汇总遵从原始问题语言，并读取实际参与 Agent 的已发布 `language_format` 段。回答按问题决定详略，纯文本自然换行，不加入工具、模型参数或内部审阅状态。Markdown通过关闭HTML的解析器转换成纯文本，保护经核实业务编号中的字面字符。运营配置发布由 `agent-prompt-configuration-review-v1.0.0` 原生工具模型语义复核，不再按正则、字段词或地址类别数量裁决。编译器仅做七段结构、长度和哈希；授权发布事务在模型返回明确safe后冻结版本，并审计复核版本和数值用量。private_values、uncertain、无效结构、提供方错误及超时均不发布；正常运行只校验已发布哈希。此管理动作将操作者准备给所选模型的系统提示词交给同一模型复核，不授予跨店、额外工具或平台发送权限；不可信客户输入的既有外发门禁保持。模型草稿始终是不可信数据，不能直接展示或保存为可信事实。

当依据复核拒绝一份候选时，可以在同一绝对截止时间内仅根据本次核实证据重新生成；被拒正文不进入新生成上下文，新稿必须再次通过独立事实/隐私复核。隐私重组和证据重生成共享已复核正文集合，相同候选不能反复提交等待模型改判；无效Schema/引用/片段不视为事实unsupported，立即失败关闭。逐轮用量同步保留；无进展、超时或其他失败仍不展示回答。字段缺失、null或未知时不能由金额、相关状态或常识补齐。

动态 Agent 的专家和汇总回答已移除旧 `ReplySafetyPolicy` 的词法否决；独立证据复核继续拒绝无依据退款、送达保证和动作承诺。其他服务的既有安全策略保持。店铺、会话、当前操作者权限、工具白名单、输入 DLP/字段投影、知识审批及人工发送限制仍由服务端执行，配置提示词不能授权越权。

动态运行的原生模型客户端使用本次绝对截止时间的剩余预算，不再被通用15秒模型时限提前截断；路由、专家、汇总和独立复核的外层总截止时间保持，SDK零重试。创建时已过期则零SDK创建。未传运行deadline的配置发布等调用保留原通用模型超时。DeepSeek/OpenAI的SDK APITimeoutError映射为LLM_TIMEOUT，不伪造未知失败用量。

工具循环遇到生成截断、提供方失败、超时或取消时保留已完成工具事件和已知 Token；未完成调用记录 timeout/cancelled，迟到答案和事实不能进入展示或记忆。主请求取消仍向外传播。回答预算使用项目 `LLM_MAX_OUTPUT_TOKENS` 的实际配置，路由预算独立；staging 调试及人工建议 overlay 默认 2048，可由环境配置覆盖。预算与统一绝对截止时间同时生效，不承诺所有复杂问题必在时限内成功。

新执行器的工具目录使用 `langchain_core.tools.tool` 定义模型可见能力，按已发布 Agent 的全部工具配置构建，不设置固定工具数。模型可见的订单与客户工具参数不含资源 ID；服务端从已授权会话注入，且在调用前执行严格 Pydantic 参数校验。平台写工具仅产生人工确认提议；明确绑定的内部备注和接管请求可写入当前 CRM，不执行平台写入或发送。只读工具结果按固定字段投影并脱敏后才回送模型。DeepSeek、OpenAI Chat Completions 和 Anthropic Messages 的原生工具协议由 Provider 适配，`tool_call_id` 与结果逐次对应；工具循环、子 Agent 和汇总共用绝对截止时间。仅实际送入模型且展示前复核仍有效的知识块可作为引用。

编排采用本项目的 asyncio 协调器与显式状态机；langchain-core 只提供 @tool 和 Schema，不使用 LangGraph 图执行或 checkpoint。配置/运行/记忆保存在 PostgreSQL；快照用于版本追踪，不承诺服务重启后自动续跑。

动态 Agent 的自由文本入口按来源标注为不可信数据；普通问题经本地标识脱敏后进入模型，完整地址和未经过字段校验的结构化文本拒绝送出。知识、工具、记忆与其他 Agent 的自由文本不能升级为系统角色。路由读取名称、职责、七段服务范围与冻结消息 ID 内的近期历史和摘要；子 Agent 同样读取这些历史。工具事实记忆须仍属于该 Agent 已配置工具且当前操作者有对应权限。会话记忆保存最近三个脱敏问题及带调用来源、观察时间的核验工具字段；同会话重开恢复，跨会话、跨客户或跨店不可读，15 分钟以上的工具事实不进入模型上下文。无成功工具事实且无有效知识引用时，汇总器给出无法核实的人工澄清，不展示模型臆测结论。

最终汇总使用独立上下文的 `agent-evidence-review-v2.0.0` 原生复核函数，逐项对照低敏工具字段与知识原文，拒绝篡改政策时限、条件、状态和无依据高风险结果。复核不会授予自动发送；撤权在汇总结束后再次验证，候选失效则隐藏回答和引用。草稿编辑在行锁刷新后比较 expected_revision，两个旧 revision 不能同时提交。

每个所选模型从 `LLM_PRIMARY_CONTEXT_WINDOW_TOKENS` 或 `LLM_FALLBACK_CONTEXT_WINDOW_TOKENS` 读取保守窗口（默认 8192，部署时按实际模型配置）。初始上下文组装和每次原生调用都预留输出与安全余量；完整消息、工具 Schema 和多轮结果超预算时在 SDK 前停止并提示缩小范围/人工复核。不会截断逐字工具事实，不以固定工具轮数替代容量控制。

本地动态边界评测使用 `agent-dynamic-contract-v1.0.0.jsonl`，覆盖全候选/越权/重复路由、工具读写与伪造参数、脱敏和不可信来源。它是协议评测，不测真实模型语义准确率；既有 237 条安全样本继续运行。真实模型、实时 TikTok 和性能门禁待部署获批后实测。


### 六类工具目录本地候选

agents/tools/metadata.py 是名称、描述、分类、参数 Schema、权限和平台 scope 的单一事实源；前端不维护工具清单。@tool 按发布版本完整构建工具，不按数量或固定正则裁剪。工具通过现有工作台业务服务和 TikTok 签名只读客户端访问平台，候选映射仅在同一父运行、同店同买家内有效；跨子 Agent 的同一对象使用稳定不透明引用，模型不能传入资源 ID 或任意 URL。写平台能力仍是提议，两个内部写入通过唯一键和同事务审计持久化。

业务查询返回强类型白名单字段后再逐字段 DLP；商品 HTML 只转为纯文本，不执行脚本或拉取资源。模型实际收到的结构化事实按查询范围和分页保留，进入最终独立依据复核；过大结果明确要求缩小范围，未送入模型的正文不能成为回答依据。工具、知识、记忆和汇总共用绝对截止时间，取消慢工具不恢复已删除 FAQ 路径。冻结消息读取只允许本次快照内当前会话；缺失消息使分页正常结束。知识查询前与最终展示前重新检查操作者授权，撤销店铺/业务/知识权限则隐藏回答、引用和将写入记忆的事实。运行记录保存每个能力的终态与父子运行关联，不保存模型参数或平台正文。

客户画像的订单数和消费额来自 CRM 同步汇总，不能据此宣称平台完整历史；优惠结果不授予买家领取资格。接管请求表示已保存的 AI 建议，不能声称已转交、退款或发送。工具目录、测试与本地构建不证明真实模型语义正确率或 TikTok 现场链路，本候选仍等待部署批准。

## RAG

- Embedding：本地 BGE-M3，固定 Revision 与 SHA-256，向量维度 1024。
- 召回：Dense Top-20；重排：bge-reranker-large Top-5。
- 接受门槛：最高 Dense 相似度至少 `0.52`；低于门槛返回无可靠知识并转人工/保守回答。
- 引用：只允许本次已接受候选中的知识标识，不允许模型伪造引用。
- 评测：冻结数据集同时覆盖有答案和无答案样本，坏样本或模型资产不匹配直接失败。

通用文件导入独立于上述 FAQ 检索路径：MinerU 4.0.12 在本地 CPU 解析，清洗后按上传时冻结的九种策略之一分块，再用同一 BGE-M3 模型生成 1024 维向量并录入独立 pgvector 表。分块大小、重叠、策略和模型 revision 随版本保存；语义分块边界调用内部模型。OCR 内容、缺失关键页和无法可靠恢复的表格结构进入整版本待复核，修订完成前该版本 0 向量，旧有效版本不切换。Agent 显式绑定的文件只在当前有效版本已索引、未归档/软删、人工确认语义类型并获内部建议审批后进入 Dense/词法双路召回、RRF 融合及重排；未绑定时继续使用旧 FAQ 路径。导入或绑定本身不构成审批，也不开放自动发送。

归档或软删除通用文件时保留不可变版本与向量记录，但 Worker 停止认领该文件，提交有效版本前再次拒绝停用文件。Agent 文件检索在两路 SQL 均以可信店铺、绑定文件 ID、未归档/软删、当前有效 ready 版本、人工审批人/时间和当前 Embedding 模型作硬门禁；替换、归档或软删除后旧版本不能再被检索。

G5 R84 的运行工厂为每次 FAQ 混合检索创建独立短时数据库会话；检索端口完成本店、当前审批版本和 ready 状态过滤后立即关闭该会话，之后的重排、DeepSeek 分类与独立安全复核不占用这条检索连接。查询失败或请求取消也关闭会话。请求会话仍负责权限检查与 Agent 运行记录，店铺隔离、DLP、阈值和人工发送门禁不变。此修复须经 staging 相同 50 客户端负载确认事务数与严格 P99，不能由本地测试推断性能通过。

## 知识语义与审批

知识条目明确区分事实/政策/操作建议等语义类型和客户范围。内容、语义类型或范围变化生成新 `document_version`，撤销上一版本审批。发布动作目前只产生 `approved_for_internal_review`；`approved_for_public_reply` 未开放，FAQ 审批不授予自动发送权限。

## 可信业务声明

订单状态、物流、退款、优惠、库存、政策和客户身份等声明必须来自当前工具结果或已审批知识，并携带内部可验证来源。DeepSeek 不是业务事实来源。缺少来源、来源冲突、数据过期或结构未知时，不生成确定性承诺，改为说明无法确认并转人工。

## 工具白名单

Agent 不直接访问业务数据库或平台 SDK。每个工具都必须有：

- 强类型输入/输出和字段允许列表；
- 店铺范围、角色权限和风险级别；
- 超时、幂等、审计和可观测字段；
- 明确的失败关闭与人工接管结果。

只读查询与建议生成可以进入 v0.1；外部写入只有人工确认的普通 TikTok 文本消息例外。高风险写入、自动营销和公开自动回复保持关闭。

## 回复、翻译与营销

回复先形成安全结构化草稿，再按坐席/客户语言渲染。翻译不得改变金额、订单号、政策、行动主体或风险级别。营销文案只能作为内部预览，不能绕过审批、幂等、频控和平台权限自动发送。

工作台单条中文辅助译文由坐席点击后触发，复用现有 `TranslationService` 和 DeepSeek 结构化输出；模型输入在现有 Prompt 安全/DLP 边界脱敏，结果只在当前会话页面展示，不写回 TikTok、不自动发送，也不批量回填历史。`WORKSPACE_MESSAGE_TRANSLATION_ENABLED` 独立于通用 `LLM_ENABLED`，默认关闭，当前仅供受审 staging 覆盖层启用。翻译失败保留原文并允许重试；生产翻译质量与数据边界仍由 `MVP-011` 独立验收。

物流弹层的“一键翻译”只处理当前已核对订单返回的物流轨迹，不批量翻译聊天历史。服务端先对全部节点执行长度和 DLP 检查，再复用上述翻译 Prompt，以最多三个并发处理最多 40 条节点；任何节点失败则整批保留原文。审计仅记录节点数和模型用量，不记录物流原文或译文。“发送物流卡片”只在本地放入卡片草稿；人工审阅并确认后，平台卡片只引用经服务端重新核对的订单与包裹 ID，不把译文或模型生成内容作为物流事实发送。

`customer-translation-v1.0.1` 明确要求 DeepSeek JSON Output 恰好返回 `source_language`、`target_language`、`message_translation`、`draft_translation`；源/目标语言复制可信输入，没有草稿时最后一项为 `null`。模型输出继续按 Pydantic 必需字段及目标语言校验，缺字段不做猜测性兼容，失败关闭并允许人工重试。
