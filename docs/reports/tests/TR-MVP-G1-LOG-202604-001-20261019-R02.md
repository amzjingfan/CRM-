# 范围和现场方法

用户更正此前“有 CBT 包裹”的判断，提供当前授权店铺 Seller Center 截图：订单页选择“全部”，筛选“物流承运商：CBT”后显示 0 个订单。Codex 的 computer-use 会话无法访问紫鸟浏览器窗口（`UI_UNAVAILABLE`），因此此项为用户提供的页面证据，不声称由 Codex 独立操作 Seller Center。截图不纳入仓库，低敏结论见[机器证据](../../../release/evidence/staging/crm-staging-g1l-cbt-absence-20261019.json)。

在用户更正前，为协助定位候选包裹，手动从同一 staging 已授权 TikTok 渠道分页读取 325 笔订单，并对 2026-09-30 创建、已送达且有单号的一笔 TikTok 配送订单调用**一次** `/logistics/202604/orders/{order_id}/tracking`；临时限制该次客户端不重试。HTTP 为 200，平台业务码为 `11007009`（订单不支持）。该候选并未被确认是 CBT，不据此推断合格 CBT 包裹的 API 行为。全过程不输出订单、包裹、店铺、买家标识或原始平台响应，不修改数据库和服务，也不执行 GitHub Actions。

# 结果与阻塞

当前 Seller Center CBT 筛选为 0，缺少可与 `202604` 首程节点对账的真实包裹；该次普通 TikTok 配送候选的 `11007009` 也不是成功证据。后续不继续盲查其他订单。G1-L 本轮为 `BLOCKED` 的测试结论；任务因外部合格样本前提未满足而保持 `BACKLOG`，G8/production 不放行。

解除条件：同一授权店铺出现可在 Seller Center 核对 `pickup_start`、`pickup_success` 或 `pickup_station_in` 的 CBT 订单，或取得 TikTok 对该店铺/应用的明确适用性说明。确认订单后，遵守每单 8 小时查询频率，只查该订单并低敏核对包裹、首程动作和时间。当前无该样本，不能将普通订单、旧版物流或合成数据计作 G1-L 通过。[官方增强物流说明](https://partner.tiktokshop.com/docv2/page/8syhoy40)
