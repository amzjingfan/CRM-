# R81 空载检索分段与 R80 同批客户端耗时关联

本次只读诊断建立在 [R80 真实 50 并发](TR-MVP-006-20261018-R80.md)的低敏原件上。G3 已恢复；临时探针进程使用 R80 已发布后端镜像，但显式关闭 LLM，只读取原隔离测试店、调用本地 BGE 和 FAQ 数据库。Agent 查询只读匹配 R80 时间窗内原 50 个隔离会话，按测试客户端序号关联，不输出任何身份值。没有 DeepSeek 调用、staging 服务切换、业务写入或 GitHub Actions。

空载探针的单次本地向量化为 **99.7 ms**，四路独立 BGE 请求全部完成、中位 **223.0 ms**、插值 P99 **350.7 ms**；单次 FAQ SQL **23.4 ms**，50 路只读 SQL 全部返回唯一候选，中位 **12.0 ms**、插值 P99 **93.5 ms**。这些是恢复 G3 后的临时进程测量，不能替代带 DeepSeek 的真实并发环境；与 R80 检索节点 P99 **3336.6 ms** 相比，只能说明尾延迟需要在负载时拆分，尚不能认定 BGE 或 SQL 单独导致。

同批 50 个客户端、Agent 行均匹配。按现有压测脚本的最近秩 P99 口径：客户端 `accepted` 中位/P99 **1273.7/2266.0 ms**，首安全 `delta` **5252.6/7287.4 ms**；`accepted` 到 `delta` 中位 **4066.3 ms**。服务端现有 `first_output_latency_ms`（从 Agent 开始前到可公开结果、尚未写首输出审计）中位/P99 **3759/5621 ms**；Agent 运行本身 **2676/5000 ms**，两者差值中位 **568.5 ms**。`first_delta - accepted - server_first_output` 的近似剩余中位 **68.6 ms**、最大 **1638.2 ms**，含网络观察与审计写入，不能直接归为某一次数据库提交。

客户端首 `delta` 与同客户端 `accepted`、Agent 耗时、检索耗时的 Pearson 相关分别为 **0.854、0.687、0.728**；与分类和独立复核分别为 **-0.133、0.018**。最慢客户端的 `accepted=1605 ms`、服务端首输出 `5621 ms`、Agent `5000 ms`、检索 `3341 ms`，客户端首 `delta=7287 ms`。这些数值表明接入与检索/Agent 长尾同时出现，不能仅优化最后的审计写入或把安全复核删去。相关性不等于根因；同机不同时间的空载与付费负载也不能作受控 A/B 结论。

结论 `PARTIAL`：诊断把下一轮测量范围缩小到**负载时的本地 BGE 与数据库检索分段**、请求接入和 Agent 前后包装；尚未证明哪项资源排队。下一次可恢复 G5 窗口需要对这些阶段和本地 BGE 资源作低敏同步采样，再针对实测瓶颈作单一修复。严格 50 并发 P99、断连验收和 G5/production No-Go 不变。
