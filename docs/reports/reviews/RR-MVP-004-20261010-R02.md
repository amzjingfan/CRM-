# 审查范围、依据与重点风险

审查本轮单后端私有镜像发布、staging 预取/预检/部署和真实消息写入边界。代码缺陷修复的审查见 R01；本记录只批准已执行的 staging 部署事实，不批准真实消息发送或 G3 关闭。

# 发现、级别、位置和证据

- 镜像来自同一远端 main SHA，发布工作流只产出一个 backend 镜像，OCI 清单及压缩层大小通过；前端和检索摘要保持不变。
- staging G2 overlay 与门禁脚本要求 backend/worker 只读及 Webhook 为 true，普通消息、高风险写入和自动回复为 false；候选部署沿用已预检的精确摘要和 overlay。
- 六角色预取含上一版 backend，部署后固定出口、迁移头与三个健康端点通过；独立只读作业核对当前 backend 摘要。
- 未发现本轮需要返修的部署门禁问题。低敏证据见[部署记录](../../../release/evidence/staging/crm-staging-g3-backend-rollout-20261010.json)。

# 已验证与未验证内容

已验证镜像来源、不可变摘要、预取、配置契约、staging 运行健康与运行后端摘要。未验证真实 TikTok 发送、受控买家接收、`unknown` 现场对账、遗留 `processing` 恢复和本轮实际回滚。

# 结论和返修条件

批准本轮**真实写关闭的 staging 安全部署**。G3 保持未通过；在受控会话、精确外部消息授权和恢复方案齐备前不得开启真实写。若镜像摘要或运行开关漂移，停止后续现场发送并重新预检。
