# 独立只读审查

首次审查指出 Important 阻断：R02 的路径校验依赖 Git checkout，而工作流只挂载四个 Git Blob，后端镜像未显式安装 Git，因此未来 `provision` 会在写入前失败。修复后复审确认，固定容器路径在无 Git 时使用 `/proc/self/mountinfo` 验证只读源码挂载与独立私有可写挂载；原 Git checkout 路径、输出独占新文件、POSIX、owner/mode、数据库指纹和未知提交保留 manifest 的门禁未放宽。没有剩余 Critical 或 Important 源码阻断项。

此次为静态审查，模拟 mountinfo 测试不能替代现场 Rootless Docker 运行证据；首次真实 `check_only` 会验证只读路径及 Runner 配置，而实际 `provision` 仍需单独精确授权。合并 R03 代码不等于现场创建账号或通过 G5。

末次复审确认 staging Secret 路径不再经 `GITHUB_OUTPUT`，两个执行步骤直接读取同一环境 Secret；挂载校验仅有格式调整，无新的 Important 阻断。

再审确认私有目录已有任何文件、目录或隐藏项时工作流在数据库操作前失败关闭，禁止用新 run ID 绕过旧 manifest。该保守规则也会阻断已对账但仍留存的材料，清理须按项目独立批次执行。

最终复审确认失败诊断只输出四类白名单阶段，并始终以非零退出；原始 stdout 不再写入工作流日志，无新的 Important 阻断。
