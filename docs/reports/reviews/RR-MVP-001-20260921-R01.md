# 审查范围与结论

独立静态审查一次性脚本的秘密传递、SCRAM 生成、Compose 范围、MinIO 初始化依赖、失败回滚、旧值负例、有效容器环境、日志/响应扫描和 production 边界，并复核实际失败路径与最终低敏证据。最终脚本结论为 READY，Critical 0、Important 0；本 RR 批准已完成的内部凭据轮换和证据入库，不把尚未提供的外部平台凭据误判为完成。

# 已关闭发现

- 初版健康请求缺 Host、应用重建可能重跑 `minio-init`、数据库/env 窗口与回滚验证不足、ALTER 可能记录明文、旧 DB 密码负例不可靠、有效容器 env/安全开关未验证、xtrace/日志窗口/候选文件清理不足；全部在执行前关闭。
- PostgreSQL 密码改为本地生成 SCRAM-SHA-256 verifier 后通过 stdin 提交，SQL 会话关闭 statement logging；旧/新值不进入 argv、Git 或证据。
- 应用重建固定 `--no-deps`，避免 MinIO 初始化命令把口令展开进子进程 argv；成功后移除已退出 initializer。
- rollback 固定为恢复 env、启动基础服务、恢复 DB verifier、恢复应用、刷新 proxy、验证网络认证和 HTTP 健康；错误文件均为 `/run` 下 0600 临时文件并清理。
- 首次实际执行暴露 `TLS_CERT_DIR` 预插值缺口；补入隔离子进程的固定非秘密占位目录，独立复审确认最终 rootless overlay 不挂载 production TLS。
- 第二次实际执行暴露 localhost HBA trust 与 proxy 旧上游 IP；恢复后把数据库正反例移到 backend 网络，并在成功/回滚路径重启 proxy。最终增量再次独立复审为 READY。
