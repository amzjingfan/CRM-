# 审查范围与发现

逐项检查源码差异：SSH 仅缩短客户端无响应检测，`BatchMode`、固定身份、主机密钥校验、回环反向监听及固定目的地限制未放宽；既有 systemd/Docker 重启策略继续负责重连。`/healthz` 改用站点已有安全 JSON 日志格式，其 `$uri` 不含查询串；不新增凭据或正文日志。对应测试检查了配置和精确进程参数校验器。

# 决定与剩余风险

批准源码候选进入 staging 安装验证；本审查**不批准 G6 门禁**。较短的 SSH keepalive 可能在网关高延迟时触发更多重连，需现场观察重启计数与三公网健康。共享出口 overlay 的变更也可能影响未来生产部署，但本次不得部署 production。失联的上游原因未证实，修复效果要靠现场检查和新的完整独立窗口判断。

独立诊断另捕获两次公网探针 TLS 阶段约 8 秒超时；一次网关记 `499`，内层代理已快速返回 `200`。网关本机 TLS 90/90 成功，公网路径及网关上游第一跳的 ICMP 样本出现丢包。SSH keepalive 只能缓解隧道恢复时间，**不能解决这类公网 TLS 抖动**；网络路径稳定性是重新开始 24 小时门禁前的独立阻塞项。
